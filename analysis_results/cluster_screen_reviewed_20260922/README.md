## x坐标均值的提议

当前理解为**同一份作答内、同一竖直角点的上下端点**，不是跨人员把作答拉向人群均值。用户确认按百分比坐标讨论，具体探索数值交Pro；尚未确定是超过多少必须纠偏，还是只对小偏差允许自动规整。0.2个百分点在1024px宽图上对应2.048px；它与当前整份作答25.6px最大端点距离不是同一参数。

在上下配对可信、图像重力方向已校正且目标确为竖直边界时，统一方位角是有几何依据的分析规整候选。均值是上下端点等权的选择，不保证比更清楚的那个端点更准确。左右接缝必须用周期中点，例如0.1%与99.9%不能普通平均成50%。大差异或配对可疑者不能直接拉直；原始坐标及其违背对齐要求的程度继续保留。

当前2444份作答、12781个已绑定点对中，4537个点对（约35.5%）的周期x差大于0.2个百分点；1771份作答至少有一对超过该数值。中位数0.128、90分位0.531个百分点。该统计说明候选规则会影响较多作答，不是质量判决；未依据它改点。详见[上下点x偏差](上下点x偏差.json)。

**代码核查的重要发现：**仓库正式标注脚本 `tools/label_studio/official/ls_userscript_annotator.js` 在构建预览点对时已执行 `(points[i].x + points[bestJ].x) / 2`（约2452行），之后 `vis_3d.html` 的 `projectCornersForViewer` 用一个共享x生成上下端点。此处5%宽度参数是寻找配对的上限，不是本轮0.2个百分点的修正阈值。这条预览路径可能隐藏原始x错位；不能凭原始x未对齐就认定人员未看3D。尚未核对每位人员当时部署版本及实际操作日志。研究Studio则保留上下原始射线，其原始重建与上述共享x预览不能混称完全一致。
