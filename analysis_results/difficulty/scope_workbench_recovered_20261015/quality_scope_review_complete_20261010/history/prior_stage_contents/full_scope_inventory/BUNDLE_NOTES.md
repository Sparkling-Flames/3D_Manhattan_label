# 保存快照说明与复核边界

本目录保存先前完成的全量库存、经独立核验的本地增量，以及映射中选定的工作台代码。原报告保留当时的取证范围；当前状态以 `CURRENT_STATUS.md` 及后续追加的对账材料为准。

## 怎样检查

在有 Python 3.9 或更新版本的环境中运行：

```sh
python /path/to/quality_scope_full_review_20261010/verify_saved_results.py
```

脚本不依赖当前工作目录、不联网，也不执行旧构建脚本。另可传 `--root` 指向完整目录，或用 `--output` 保存 JSON。`SAVED_RESULTS_VERIFICATION.json` 是本次保存结果的检查回执，`FILE_MANIFEST.json` 记录新增快照文件的字节数和 SHA256。清单自身与生成的检查回执不自哈希；后续追加报告后应刷新清单再运行检查。

检查覆盖保存文件完整性、CSV/JSON对应、图片/标注/评论/来源连接、分母、数值有限或空值状态与分量和、本地内嵌原记录的原文、SHA256和时间层级。它不重新打开原始电脑文件，不从原GT重算几何或质量，也不重新裁定文本语义。

## 计数容易误读的地方

- 冻结库存有259张基集图片、3152份几何记录，1648条身份与文字去重的评论、6340个来源位置。1648条包含基集外41条，分别涉及21张历史图片；不能全部称为259图内评论。
- 203张是宽检索候选，56张未命中。两者只描述检索结果，不等于真实范围不同或相同的数量。
- 本地69条是69个不同来源/身份记录，涉及36图、66个不同的图片+原文组合。三组同图同文各绑定两份不同标注，保持分别可追溯，不作独立范围投票。
- 69条中36条近期记录分为22条精确标注绑定和14条图片/墙组绑定；另33条包含21条原评语（其中7条成对比较）及12条跨图上下文。成对比较不拆成两条范围票，跨图文字不摊为逐图裁决。另19条本地基集外记录单列。
- 11705行是候选覆盖清点；未把全部候选升级为用户原评语或人工语义判断。123行记录的是当时的读取失败。后来用户确认文件存在且长路径可读，不应将123称为丢失文件。

## 工作台代码快照不是完整站点包

`workbench_source/` 保留选定构建脚本、核心网页代码、两份检查脚本及历史QA回执。上传映射未包括 `dist/data.json`、各图记录、照片、导出清单或 fixtures。因此：

- 可审阅源码，核心JavaScript可做语法检查，独立几何检查可运行。
- 仅此目录不能启动有完整数据的工作台，不能运行完整 `qa-state.cjs` 状态/数据回归。
- `QA.json` 的3386项状态/数据断言与49项几何断言是已保存的历史回归回执；除另附明确结果外，不把它们称为本次再次执行。
- 浏览器视觉与真实交互尚未验收。站点发布回执见 `deployment_receipt.json`，发布成功不等于浏览器验收。
- 旧构建脚本保留原工作区路径与外部输入约定，不视为可独立重建的输入全集。可移植入口是顶层 `verify_saved_results.py`。

## 追加式发布边界

原仓库的 `README.md`、`received_scope_review_batch2.json`、`batch2_validation.json` 不包含在此次新增文件清单中；保持既有内容，不覆盖、不删除。冻结子目录中的同名README为新的独立路径，不是仓库已有入口。Git发布应只添加核验列出的新增路径，不包含已物化的研究源输入或其他工作区文件。
