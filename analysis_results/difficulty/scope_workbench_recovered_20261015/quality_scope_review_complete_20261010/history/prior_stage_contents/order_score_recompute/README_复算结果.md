## 为什么确认了正确顺序，固定 GT 分数反而下降

“确认环连接”与“更接近固定 GT”是不同问题。三份作答都从点对序 1→2→3→4→5→6→7→8，变为用户确认的 1→2→4→3→6→5→7→8。坐标和点对没变，但连接边、底面和连续顶边已经改变。引擎实际使用新环，不会把它按 x 重新排回旧序。

主要变化是边界与固定 GT 的距离增大：按原引擎固定扣分顺序，W006/W017 的边界扣分从 6.014286 升为 17.097910（+11.083624）；W018 从 6.035187 升为 17.747148（+11.711961）。范围扣分只分别增加 1.318354、1.329593。方向残差反而下降，所以不是“新环更不规整”导致的大降分。

扣分分解是原公式的顺序分解，不能把各项当作相互独立的因果贡献。高度和内在约束的绝对扣分略减，部分因为它们作用前的分数已被边界项降低；这不表示高度误差一定变好。完整因子、残差和扣分保存在 complete_components.csv。

以上是可复算的数值观察。至于局部结构与固定 GT 的细节表达是否一致，属于语义与目标裁定，不能由本次分数推出。本次按用户要求维持现有 GT，不重新讨论壁炉取舍，不更改难度／范围判断。

## 可运行入口

环境：Python 3、numpy、scipy、shapely；测试另需 pytest。实际版本见结果文件与日志。

1. 离线重放（只需本包）：`python recompute.py --out results_replay`
2. 便携回归测试：`python -m pytest -q tests`
3. 从完整仓库只读重新提取：`python extract_formal_input.py --repo <旧或新仓库> --out <快照路径>`。每个仓库需正式 LFS 数据已物化。
4. 原始提交／LFS／冻结引擎验证：`python verify_provenance.py --old-repo <旧仓库> --new-repo <新仓库>`
5. 独立投影、保存旧面积与采样验证：`python validate_recomputation.py --repo <新仓库>`
