## 直接可用的数据与字段合同

`image_tags.jsonl`是当前工作包的衍生目标表，每张原图一行，共648行。原始用户记录不改动；来源为`metadata/spatial_history.jsonl.gz`内`latest_selection_record`，并已逐图核对原始导出`analysis_results/candidate_selection_review_20260913_v2/用户审查原始记录.json#/decisions`。当前确认使用全部106张已填写标签，不按采集采用与否再次筛掉图片。

|字段|含义/边界|
|---|---|
|image_id|唯一连接键；一张原全景对应一行|
|building、source_split|图片身份及原始数据划分；不是难度预测输入|
|scene_category、scene_source|人工采用分类的原值及来源；采用spatial_classification.coarse_type，空值时读已保存的spatial_prior_user.user_type，与Pro v2来源层一致。32张需读取原字段，均保留“复合／待定”或带附注的原值，不用AI替代或自行清洗|
|selection_display_group|选用审查展示组；仅用于追溯，不是自动有效的同房/独立样本标识|
|difficulty_tag|用户原标签：简单/中等/困难/未定；无记录时为null|
|difficulty_status|labelled、undetermined、not_recorded；仅labelled参与标签评价|
|difficulty_ordinal|简单0、中等1、困难2；其余null。只声明顺序，不假定难度等距|

标签作为目标时，不把该标签、同义难度描述、计划人数、选用决定、组编号、原图序号或任何真人结果当预测特征。基于原图提出的可见证据与带历史结果/难易判断的文字须区分。预测输出不得覆盖用户标签；当前学习的是用户的判断，实际困难及收敛需要后续真人数据验证。

`coverage.json`提供类别、building和展示组的全池/标签覆盖计数。`image_tags.jsonl`不含原图、作答、姓名或本地绝对路径；模型和特质输入仍读父工作包的`models/`、`visual/`、`metadata/`。如云端尚未收到这个新目录，原工作包的`latest_selection_record.difficulty`已包含同一批标签，可以直接读取并核对106/112/648覆盖，不需要原图。
