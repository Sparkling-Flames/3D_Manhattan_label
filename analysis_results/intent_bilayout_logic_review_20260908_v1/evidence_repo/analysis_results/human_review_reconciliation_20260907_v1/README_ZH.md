## 二、需要先纠正我的点序解释

**此前把读取／显示失败归因于工人顺序错误，证据不足，应撤回这种归因。** 几何文件的数组排列、上下端点配对、墙角邻接、查看器显示顺序不是同一件事。

当前HD适配器把导出数组每两个相邻点视作一组，再按组序构造墙环。仓库保存的历史Label Studio脚本则先按横坐标排序，再在图宽5%的阈值内寻找最近点进行配对，还可能应用浏览器保存的预览覆盖。原始关键点导出没有显式relation边，不能证明数组邻接就是工人的墙角顺序。

旧渲染器在读取失败时，仍将偶数／奇数编号分别串成红线。这些是程序的诊断连线，**不是工人画出的墙边**。在V06、V10等案例中尤其容易误导判断。本轮没有继续重排坐标；旧资产保留用于追溯，阅读时必须应用本勘误。更规整的3D外观也不证明布局、配对或范围正确。

- 12份已保存建议均保持原点值，改变的是点的读取排列；在现有读取假设下，其地面环均无自交。没有证据说这12份保存的建议本身都新引入了地面自交。这里没有检验全部3D墙面相交，不能推广成“3D正确”。
- 其中10份建议与仓库历史脚本默认配对映射完全相同。这更像恢复另一条显示路径，不能称为发现并修正工人的顺序错误。历史代码并不证明每位工人当时使用了哪个部署版本或是否有本地覆盖。
