## V01／W31：此前解释哪里不严谨

来源为C1 Manual，project 67、task 3206、annotation 5963，canonical版本ID `385caf3701dee7042d51`。导出有8个独立关键点，未发现显式墙边关系。原图点位正确与否、导出列表的排列、作者实际墙边意图是三件事；目前没有证据把它们等同。

旧脚本将相邻点当上下点对，再把四组按导出顺序连成环，此时地面代理自交，于是按方位角生成另一种连接。原点编号从0开始，旧候选是 `(6,7) → (4,5) → (0,1) → (2,3)`，即原组编号从1开始的 `4 → 3 → 1 → 2`。它没有移动W31的点，但改变了墙边连接。旧失败面板的红线是脚本直连诊断，不是W31在标注界面画出的墙边；旧3D中的pair编号还是显示槽位，不能当作原始点号。

高清原图中，玻璃门框、近侧餐厨外圈与左侧厨房凹位均需区分。四组重排可形成近侧四边形，具备作为连接候选的视觉依据，但省略厨房细节；这不能证明作者原顺序错，也不能证明候选符合作者本意。此前“顺序修复后即可读取范围”的表达过强，已撤回。原序、纯点图、旧候选都保留供比较，不预选正确版本。

## 字段、复现和交付范围

`visual_order_recheck_notes.json` 是人工编写的AI视觉观察工件：键为唯一case_id，值为非空中文意见；覆盖当前selection中的全部50图，不含人工最终判断。它不是重新生成原始标注的真源。`preview_adjustment_review_notes.json` 保留此前意见，增加当前视觉意见并由finalize汇总；`decision`仅为预览建议，不能用作工人质量字段。

`ORDER_AUDIT.json` 的 `summary` 为覆盖与一致性计数，`layouts` 一行对应一份展示布局；`role_swapped_pairs`只计组内角色读取，`proposal_point_map`为新位置对应的原点编号（从0开始），`proposal_ring_edge_set_changed`区分真实邻接变化与同一环的旋转／反转。`author_intended_order_verified=0`表示未验证作者意图，不能推断所有导出顺序都无意义。

复现：`python -m tools.thesis_main.analysis.audit_uncertainty_review_order`；展示汇总：`python tools/thesis_main/analysis/prepare_uncertainty_visual_review.py finalize`。均不会生成视觉意见。验证结果在交付后附于本文。地图及文档索引登记此探索性入口；不改变protocol、分簇、人员资格、统计度量或最终裁决。不重跑推理、疲劳分析及无关运营测试。
