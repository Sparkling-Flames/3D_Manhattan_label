## GT为什么不总从左到右

本仓库称为“原始Matterport GT”的文件对应MatterportLayout布局标注。原数据格式不仅有角点列表，还有每面墙的`pointsIdx`连接关系，见[数据发布仓库](https://github.com/ericsujw/Matterport3DLayoutAnnotation)。[HoHoNet官方转换流程](https://github.com/sunset1995/HoHoNet/blob/master/README_prepare_data_mp3d_layout.md)按原角点列表顺序生成上下交替的`label_cor`，没有按横坐标排序。

全景横坐标表示围绕相机的方位角，具有左右接缝；环从哪个角开始编号不决定墙体邻接。此外，存在凹入结构、遮挡时，沿实际墙体行走的相邻角点在方位上可以局部回退。只有所有相关边界从相机可见等适用条件满足时，按方位排序才可能与实际环序一致。将全体角点强制按x排序可能改变真实邻接，不能用它“修复”原始GT。

例如原7y3sRwLe3Va-21的GT点对x序列为518.92、587.92、736.54、828.40、199.27、286.59、295.13、316.79、279.82、387.82。既有接缝跳转，也有316.79→279.82的局部回退；它们本身不证明源顺序错误。当前工作台显示的原始GT排列与`label_cor`一致。两份导出中的21份原始GT全部保留默认排列，其中20份确认、1份草稿。

官方流程另外提供`*_no_occ`，专门处理遮挡并转成可见边界表示；不能把训练读取器的x单调要求套到保留遮挡结构的原GT上。原始GT也可能有实质标注错误，但必须另有图像或来源证据；本次没有因为稠密点或锐角修改GT。人工修订GT的点击/配对次序不自动具有同样的源环序保证。
