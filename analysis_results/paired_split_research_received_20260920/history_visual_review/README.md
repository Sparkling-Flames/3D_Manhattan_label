## 全量队列如何选

`all_history_queue.json`覆盖全部239个单元，保存资格分母、是否在旧资料出现、优先级、触发数和本轮目视状态。`candidate_pairs.json`保存每单元每类型的优先作答对；`selected_evidence.json`保存8项距离、完整成员身份和分区、用户裁决空值。

在9度研究设定下，触发接缝变化的单元1个、绑定变化3个、自由匹配变化11个、近对被拆25个、同簇局部差异集中50个；Manual数值相近候选38个。类型重叠，**不是错误率**。筛查规则：近对被拆使用≤4.5度；同簇局部集中使用最大值≥6度且大于均值3倍；对照为≥8人单元内0.5–3度Manual作答对，避免把Semi完全同坐标直接当独立一致证据。这些是队列规则，未拟合或冻结正式方法。

队列优先尚未在既有资料出现的图，再按对应分歧、近对过拆、同簇局部差异、对照排序；首批每类1–2张并去重。无新接缝候选时不强行重复旧图。无触发不等于正常，后续还需覆盖未触发图、不同点数/角色不可比及OOS等情况。不同点数门本身的效果不在本轮同点数候选筛查内；未自动修点。
