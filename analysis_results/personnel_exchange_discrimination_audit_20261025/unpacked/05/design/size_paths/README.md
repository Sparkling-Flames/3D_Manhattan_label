# 固定 X7/Y7/Z7 的人数—共同背景增长路径（仅注册）

本设计复用 `../target_omissions/ANCHORS.csv.gz` 中 **286个已按无结果哈希选定的锚点**，回到它们对应的原 n10/m7 严格 ABC 登记。方法为 **DSTRUCT_K3、MSDGEOM_SCOPE_K4**。不重新挑选有利锚点，不读取融合效果，不在本步骤运行融合。

## 1. 真正固定与改变的内容

每个锚点固定原 **X7、Y7、Z7和D3**。把实际人员池中不在这24人中的其余人员，按固定种子 `2026102521` 的 SHA256 排名形成一条无放回顺序，逐人加入共同 D：

- A＝D＋X7；B＝D＋Y7；C＝D＋Z7。
- 三队的实际换人数始终 m＝7；AB类别人数向量始终相同，AC/BC源类−7、目标类＋7。
- 每一步三队同时加入同一名新背景成员，n增加1，m不变。
- 保留每个锚点所有可行整数 n＝10…N−14，本批实际最高 **n21**，没有在n20截断。
- 原有 phase、类别方向及历史角色字段从原注册事件原样继承；建类标签直接复制锚点包的 `FROZEN_LABELS.csv.gz`。

这条路径把 XYZ固定下来，使前后比较不再混入不同替换块的变化。人数增长与新增共同背景成员同时发生，解释的是该联合过程；实际投票、对应或连接机制要在补算结果中检查。

## 3. 文件与接口

- **`EVENTS_EXACT.csv.gz`**：沿用主实验事件接口；包含A/B/C及D/X/Y/Z精确人员、完整类别向量、池与历史角色、`parent_anchor_id`、`path_id`、`previous_event_id`、`entrant_worker`、`entrant_class`、n/m及背景来源。
- **`REQUESTS.json.gz`**：所有9792个去重必需集合，使用主运行器一致的 `{pool_id, team_key, worker_ids}` 接口。
- **`NEW_SIZE_REQUESTS.json.gz`**：只含8934个n>10集合，便于补算。是否缓存命中由主运行器判断。
- **`EXISTING_N10_REQUESTS.json.gz`**：858个原n10引用集合。
- **`ANCHOR_PATHS.csv.gz`**：每个锚点的固定XYZ、D3、精确背景进入顺序及全可行n。
- **`PAIR_LINKS.csv.gz`**：2978个相邻前后事件，`delta_n=1`、`delta_m=0`，逐臂新旧端点关联，三队均添加同一人、未移除人员。
- **`BASELINE_N10_LINKS.csv.gz`**：每个n对原n10的关联。
- **`ENDPOINT_REQUEST_USAGE.csv.gz`**：团队端点到事件/臂的关联，避免把几何复制到每个事件。
- **`CAPACITY_AND_ATTEMPTS.csv.gz`、`COVERAGE_BY_METHOD_PHASE_N.csv`**：真实路径覆盖、逐方法/阶段/n的分母。
- **`FROZEN_LABELS.csv.gz`、`FOLD_ROLE_CENTERS.csv.gz`、`IMAGE_PHASE_ASSIGNMENT.csv`**：直接复制原登记来源，未重新建类。
- **`DESIGN.json`**：固定种子、输入SHA256、精确注册规模及集合断言。
- **`code/register_fixed_block_size_paths.py`**：实际注册代码。

事件记录名义门槛 `ceil(n/2)`、奇偶与相邻门槛变化；`additional_D_votes_needed_if_Z7_unanimous` 表示**假设7名目标成员对同一节点一致支持时**还需多少背景票，不是实测节点票数。

## 4. 覆盖含义

本设计完成的是 **286条固定块、固定初始D3、单一无放回背景顺序上的全部可行人数**。它没有宣称覆盖所有背景顺序、所有D集合或全池成员组合。

每个事件另记录：固定D3/XYZ后该n可行的D成员集合数、可行的D类别人数向量数以及本路径实际登记1组；锚点表记录所有剩余人员顺序的阶乘规模。这样能够明确区分“人数全部覆盖”与“成员组合全部覆盖”。既有286锚点本身已覆盖不同成员块与背景，本阶段在这些锚点上做有明确比较对象的规模过程。

## 5. 复现与后续计算

在研究根目录的父目录运行：

```bash
python exchange_research_20261025/design/size_paths/code/register_fixed_block_size_paths.py
```

脚本只读锚点、原登记事件、冻结标签和v2人员池，不读取结果文件。所有n10成员与team_key都已与原登记逐一核对；所有事件均断言严格ABC不重叠、m恒7、原D3保持、XYZ固定、路径无人数缺口、每步三队恰好加入相同1人。

**状态：已注册，未运行融合。** 主运行器可在当前批次完成后补算这些请求，并用精确关联表重聚合B−A、C−A、C−B及各分项随n/背景的变化。
