# Scope 回答特征：本轮人员分类的辅助输入（2026-10-25）

本目录是分类输入的新增整理，不是新的 scope 裁定，也不改动真实 v2 的 GT、人员资格、原标注、质量评分或融合规则。最新仓库提交为 `972857b2b3f548316be215400e42d6ef6e639250`。

## 实际来源和恢复

主来源是已归档 `RECORD_EVIDENCE_LEDGER.csv.gz`：10,439 条记录，其中 9,845 条有统一字段 `scope_response`。按精确人员与图片关联早期 `scope_response_evidence.csv` 后，额外恢复 286 条历史原值 `oos`：这些记录在主来源的统一字段为缺失，原问卷与当前记录一一对应，没有与已记录回答相矛盾的覆盖。796 条原有 `in_scope` 和 1 条 `out_of_scope` 与当前 ledger 一致。恢复仅进入本目录的 `scope_feature_response`。

因此本轮输入包含 10,131 条有来源的回答；同人、同图、同条件的重复对象归为一个行为机会，共合并 28 条重复库存对象，未发现同一机会内矛盾回答。所有原始对象仍在逐记录表保留。没有回答的仍为未知，不填为“接受”。

## 建议交给分类的域

主域 `scope_centered_rejection` 是**回答倾向**：先在训练侧同图片、同条件、同来源内计算回答相对均值，再对有充分支持的普通 Manual 与普通 Semi 历史均值等权。这避免“新批看过哪些图”或“不同条件记录量”直接充当 scope 风格。

- 同一个比较情境至少 3 名实际有回答者。
- 每个条件至少 8 张图、3 栋楼；支持不足保留未知。
- ALL 共 62 人，61 人有该域支持，W022 不足。
- 每个楼外折先删除目标建筑下全部条件记录，再做情境居中和人员汇总。
- 本轮返回 ALL 与 22 个建筑外折，`worker_id, heldout_building` 可与新分类输入连接。
- `scope_manual_residual`、`scope_semi_residual` 分别保留条件；`scope_hard_minus_easy` 表示困难相对简单图的回答变化；门洞、OOS、特殊范围单列并保留各自分母。

不要同时把所有这些近义指标重复加权。主 scope 域建议先用中心残差；困难差或跨条件差可用于增量候选。与不加 scope 的同一几何／难度基线在共同人员域比较，再判断是否带来融合区分度；输入可用不等于作用已经成立。

## 来源影响及解释边界

新批 Manual 原始拒绝率约 21.06%，旧批 Manual 约 6.82%，但两批机会和采集协议并不相同，不能直接据此划分“宽松/谨慎”。图×条件×来源居中后的 ALL 主特征，新批均值约 0.0002、旧批约 0.0022；特征仍保留不同人员的变化。旧批 Semi 的已记录回答均为 `in_scope`，该条件内不能提供人员区分，表中如实保留其零变化，不能解释为每人已被充分证明正确。

附带的 scope 讨论提供一个有用解释区分：表示范围、可见信息／遮挡、目标边界政策应分别说明；多人在可见扩展上分歧不自动等于有一类“能力差”。本轮沿用冻结 v2 资格，不因这份讨论重新放行任何参考或恢复被筛除的作答。

## 文件

- `SCOPE_FEATURES_ALL_LOBO.csv.gz`：全部楼外特征、分母、未知原因；分类主入口。
- `SCOPE_FEATURES_ALL.csv`：全数据描述名单。
- `SCOPE_RECORDS_WITH_OPPORTUNITIES.csv.gz`：10,439 条原记录关联、原值及派生值。
- `SCOPE_RESTORED_HISTORICAL_286.csv`：286 条精确旧问卷恢复桥接。
- `SCOPE_SOURCE_SUPPORT.csv`、`SCOPE_FOLD_COVERAGE.csv`：来源及逐折覆盖。
- `PROVENANCE.json`：输入路径、SHA-256、定义与所读提交。
- `build_scope_features.py`：实际运行代码；`python build_scope_features.py --root /path/to/workspace`。

这里的 ALL 标签支持仅用于整体描述；换人实验应使用对应 `heldout_building` 的历史特征。
