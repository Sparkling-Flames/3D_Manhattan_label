# 本轮分簇疑问：三个代表例的只读核查

本轮评论按当时默认 **shared-x＋直径约束二次亲近度（affinity）** 解释。读取已保存距离和成员，未重算或修改分簇，也未据此改判作答。

## 实际比较的是什么

现有分簇不是曲线墙带IoU，也不是质心距离。每份作答先使用已绑定的上下点对共享x；同点数、固定端点对应下，取周期ERP平面上**最远一组对应端点的欧氏距离**。任意一对成员距离超过25.6像素，就不允许同簇。点数不同也不能直接同簇。距离定义对局部最差端点敏感，即使整体区域视觉相近，也可能越阈值。

在上述直径约束下，算法最大化同簇近邻的二次亲近度总和 `(1-d/25.6)^2`。它要求整个簇两两兼容；“A接近B、B接近C”不能保证A和C同簇。单人簇不是异常/无效判定。

## 是否错绑

逐一核对以上三个案例的35份成员：页面canonical作答ID、worker及affinity标签与历史memberships一致；有效点逐项一致，共享x点集合一致。部分共享x数组因页面按上下点对展开而改变存储顺序，未改变点集合。这三个案例未发现人员、标签或点位错绑；此结论不替代全库视觉复核或真实墙角连接顺序确认。

因此，这些疑问目前揭示的是**硬直径与全局亲近度划分和人眼空间相似判断并不等价**，不能因为算法有最优证书就把分开解释成合理的空间类别。后续可在清洗后研究距离/阈值的敏感性，但本轮不按用户意见强行并簇，不为改善共识曲线调整现分区。
