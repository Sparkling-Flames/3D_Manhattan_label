## 4. 明确难度缺口：已在总入口保存，旧分析没有消费

真实数据流为：

1. `analysis_results/review_final_20260928/evidence/latest.json#/traits/image:<image_id>` 保存后续 `difficulty`、`status`、`updated_at`。
2. `analysis_results/review_final_20260928/全量复核.csv` 同时保存独立 `difficulty` 列及完整 JSON `image_traits` 列。
3. `materialize_current_research_input.py` 第 127—128 行把完整 `image_traits` 写进当前总入口 `objects[].review_evidence.image_traits`。**这条路径没有丢失难度。**本次核查 259 图同图所有标注携带的该结构均一致。
4. `final_review_summary_20260929.py` 的逐图汇总没有提升独立 `difficulty` 字段；`逐图分类及覆盖.csv`、当前总入口 `images[]` 和 `research_tables.json.images[]` 因此没有这个独立列。
5. 问题发生时，`research_panel_inventory_20261003.py` 的 `HUMAN` 和 `bind_difficulty` 只消费 `candidate_selection_review_20260913_v2/用户审查原始记录.json`。历史 inventory 和 Lee 扩图快照因此没有叠加当前对象中已经存在的后续等级。

259 图中，后续填写等级共 **34 图：20 easy、10 medium、4 hard**；其中33图resolved，Uw-17仍pending，不能把34图全部称作已确认。其中 29 图在旧 9/13 源没有等级。uNb-47 则是实际旧值更新：9/13 为“中等”，后审为 `hard`。此外，自由原话另有uNb-07明确“中等难度”的后续纠正，不能仅据traits判断旧45图完全不受影响；最终合并见本目录REPORT.md。

## 5. 历史原话检索不完整，不是后来裁决被遗漏或失效

原件：`analysis_results/human_review_reconciliation_20260918/用户_39图文字审核_原始.json`，39 条 `#/image_notes/<index>/note` 都非空且对应当前 259 图。相应 `reviews` 的 36 个图×condition 表单选项为“未审核”，但用户已明确指出这些文字是实质审核意见。**不能用未勾选等级推断用户未审。**

这些原话已在历史归档中保存；`build_review_reconciliation_20260925.py` 的 `historical_evidence` 第 92—100 行也明确将 image_notes 作为历史图片证据加载。问题是当前统一 `research_input_20260929/comments.json` 的 sources 没有直接纳入该历史图级原件；`build_review_comment_table_20260929.py` 主要收集新 evidence、逐份 commentary 和最终台账，未完整带入这组历史原话。

逐 image_id 核对当前 `comments[].text`，无论全文相等或原话作为子串，39 条仅有 **3 条可原文检索到**（原件索引 10、11、12），其余 **36 条不能从该统一表按原文检索到**。这只是原话检索覆盖检查，不声称后来的审核没有读过、吸收过或更新过这些意见。

两个明确例子：

- `#/image_notes/0/note`，jtcx 图 ID `jtcxE69GiFV_27535f650b78489abcf2397c1eaa3037`，原话从“边界明显，大体范围个人感觉是无歧义的”展开讨论小结构与人员表现。
- `#/image_notes/1/note`，uNb 图 ID `uNb9QFRL6hY_748279b5d6e740c4b2cba9fc78d6fc62`，原话讨论楼梯开口、阶梯型墙角与遗漏。

这是**历史资料可检索性缺口**。可以将原件、作者、image_id、时间和原指针加入历史检索层，但不应让早期旧簇编号、当时场景猜测或一正的条件评级覆盖后续图片/个人裁决。用户 9/18 文字文件也没有新增明确难度等级，不能为了补字段自动将文字转成三档标签。
