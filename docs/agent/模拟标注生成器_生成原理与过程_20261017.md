# 模拟标注生成器：生成原理与过程（教学版）

> 给学长与后续维护者。本文回答一个问题：**这些合成标注到底是怎么被"造"出来的？**
> 覆盖：第一轮（v6 难度 259 图 → 6678 份）+ 第二轮（画廊 144 图 → 2740 份）+ anchor-space 变体。
> 原则一句话：**模型提议当"底稿"，真人偏差当"笔迹"，图片难度当"出错率"，全程打标隔离、可溯源、可复现。**

---

## 0. 一句话本质

合成标注 = `模型预测 + 真人实测偏差（楼外 donor） + 按难度的"离谱"改造`。
**没有一条合成数据是凭空随机画出来的**：每个坐标偏移都来自真实工人的历史改动样本，每类"离谱"都对应真人真实会犯的错误类型。合成数据的唯一"新"东西是组合——所以它"有特征"，而不是"太假"。

## 1. 输入真源（全部只读，冻结校验）

| 真源 | 用途 |
|---|---|
| 模型三族 bank（HoHoNet / Bi-enclosed / Bi-extended） | 每条合成标注的"底稿" |
| 难度表（第一轮=v6 学长裁定；第二轮=真人分歧经验值） | 决定每图几个"离谱" |
| 真人作答（残差/时间/范围投票） | "笔迹"与"出错频率"的校准来源 |
| 全景图 + GT/参考 | 显示与（有 GT 时）诊断评分 |
| 冻结输入包 + 哈希清单 | 开工前锁定，跑完核对"源文件没被改过" |

## 2. 生成一条合成标注的八步（核心管线）

以第一轮为例（第二轮差异见 §5）：

1. **定目标**：每图 `need = 35 − 真实人数`（真实人数来自准入台账/画廊 annCount）。
2. **难度 → 离谱预算 k**：简单 0–2（偏 0–1）、中等 5–7、困难 8–20；`k = min(k, need)`。其余 `need − k` 份为"正常组"。
3. **挑"人"**：每条合成绑定一个**真实工人模板画像**（质量 较高/较低 × 速度 快/慢，来自 B8L2 楼外效应拟合），分配 `S_MANUAL_xxx` 独立编号——**合成身份与真人隔离**。
4. **挑模型族**：按该画像的历史模型倾向（三族概率）选一个模型提议做底稿。
5. **转移"笔迹"（正常组）**：从**楼外建筑**的真实 donor 池分层抽残差——先个人、不足再同类画像、再总体（shrinkage 加权），把该 donor 的坐标改动量加到模型点上（按该工人 95% 分位 cap 裁剪）。
6. **"离谱"改造（仅 wild 人）**：随机组合三类真实错误型，且**必须仍然"角点落在墙角附近"**（几何校验通过）：
   - `partial_corner` 没完全标出来 → 较大抖动（低质量工人实测残差的高分位）；
   - `missing_corner` 漏角点 → 删 1–2 对（删除频率照真人删点占比）；
   - `scope_restricted` 只标了一个空间范围 → 环序上取**连续子集**（参照真人多数派范围）。
   - 几何失败就**减档重试**；绝不"退回去照抄模型"来粉饰成功率。
7. **时间 / 范围作答**：时间按任务效应平移 donor 的 active_time（log 尺度）；scope 从真实回应/投票分布采样——**只记录、不改几何**（scope 是"作答回应"，不是几何裁决）。
8. **落盘 + 审计**：`synthetic=True`、`S_MANUAL`、`difficulty`/`difficulty_basis`、`wild_error_types`、donor/模型/seed 溯源、时间/范围状态；导出 Label Studio 兼容 JSON；逐图审计（预算、几何、重复、复现、源完整性）。

## 3. 校准数据从哪来（"像真人"的来源）

- **残差分布**：真实工人"模型 → 最终作答"的坐标改动（逐人 95% 分位 cap）。
- **"离谱"幅度**：第一轮取低质量工人实测残差高分位；第二轮取**本图真人相对模型残差的 Q75–Q95**。
- **删点频率**：真人中点数较少作答的占比。
- **范围"正确性"**：真人多数派范围投票（第二轮 in_scope 1748 / oos 552）。
- **难度（第二轮）**：本图 15–16 份真人作答的**成对平均角点距离**，144 图三分位切分（阈值 188.32 / 225.00 px，写入 `difficulty_thresholds.json`）。
- **建筑隔离**：donor 一律排除目标建筑（第一轮 19 栋、第二轮 24 栋画廊中 15 栋为目标），防"自己抄自己"。

## 4. 两条质量底线（诚实边界，写进交付）

1. **合成 ≠ 真人**：`synthetic=True` + `S_MANUAL` 命名空间，与真人数据严格隔离；不进入真实资格/GT/评分/融合。
2. **可算 ≠ 已验证**：
   - 第一轮有 GT → B8L2/D10 只作**诊断**（wild≈25 < normal≈58 < 真实低质量≈63，方向对但组间图集不同，**不宣称与真人分布匹配**）；
   - 第二轮无 GT → `evaluation=null`（`no_gt_reference`），**完全不评分**，只审计几何合法 + 合成/真人分歧比值（中位数 1.036，仅诊断）。

## 7. FAQ

- **为什么合成数据"像真人"？** 每个偏移、每次删点、每次"只标一个空间"都抽自真人真实改动的实测分布，不是随机噪声。
- **怎么保证不出现假到离谱的数据？** 三关：几何校验（角点必须落在墙角附近、点对闭合合法）、同图去重（不同合成人不得产生完全相同的坐标）、审计面板（预算/复现/源完整性）。
- **能不能把合成标注当真人用？** **不能**。它是模拟实验与补足人数面板的工具；质量是否与真人分布一致尚未认证，无 GT 的图更是不评分。任何下游使用都必须带着 `synthetic=True` 与来源字段。
- **难度从哪来？** 第一轮是学长人工裁定（v6 交接）；第二轮没有标签，用真人分歧的经验三分位，`difficulty_basis` 逐图写实，**不冒充学长裁定**。

## 9. 转成 project-98 项目快照格式（下游导入用）

**用途**：合成导出是 Label Studio「标准 JSON 导出」（task 只有 `id/data/annotations/meta`、字符串 ID、`scope` 控件），而真实项目 project-98 的备份是「项目快照」结构（整数 ID + DB 字段 + `worker_scope_response` 控件名等，19/21 字段）。两份结构不同，下游工具没法同流程处理。转换脚本把合成导出**逐字段重写成与 project-98 完全一致的快照**（连键名键序都一致），这样合成批次可以走和真实项目相同的导入/分析流程。

**工具**：`convert_to_project98.py`（在 `/Users/ethan/Documents/ME/`，不放进 manha 仓库，避免污染研究代码；说明文档 `conversion_README.md` 同目录）。

```bash
python3 convert_to_project98.py <源.json> <输出.json> <映射.json> \
  [task_id起点] [ann_id起点] [user_id起点] [slot35] [slot_offset]
```

**转换规则（要点）**：

| 项 | 合成导出 → project-98 快照 |
|---|---|
| task | 4 字段 → 19 字段（补 `file_upload/drafts/predictions/created_at/inner_id/project/updated_by` 等 DB 字段，`meta` 置空） |
| annotation | 补 `unique_id`(UUID)、`prediction:{}`、`result_count`、`import_id/last_action/parent_*:null` 等，共 21 字段 |
| 控件/取值 | `scope` → `worker_scope_response`；`normal→in_scope`、`oos→out_of_scope`；result 补 `origin:"manual"` |
| 标注人 → 用户 | 默认一人一个新整数 ID；`slot35` 模式按仓库公式 `S_MANUAL_{offset+image_index*35+slot}` 取 `slot=(编号−offset)%35` **坍缩为 35 个槽位身份（同 slot=同人）**——第一轮 offset=100000、第二轮 offset=200000 |
| ID | 新整数 task/ann ID 按起点区间分配（批次间错开防冲突）+ 10 位短随机 result id |
| 时间/lead_time | 落在 2026-09-22~28 窗口（对齐真实项目时间线）；`draft_created_at = created_at − lead_time`；lead_time 收敛到 [1, 600]s 对齐真人量级 |
| 确定性 | 随机种子与源文件路径绑定：同一源文件重跑逐字节一致，不同源文件时间戳/随机 ID 不同 |

**两个硬性注意（与 §4 底线一致）**：
1. project-98 快照结构里**没有 synthetic 字段**，转换产物不含 `synthetic=True` 标记。隔离与溯源保留在两处：① 源合成文件（`synthetic=True` + donor/seed 全溯源）② 映射文件（原 ID → 新 ID、slot → 用户）。下游若把转换产物与真人数据混用，必须回头对映射文件核身份，**不能把转换产物当作"已认证真人"**。
2. 合并多批次：图片不重叠时直接拼接 + 重编号 `inner_id`/`package_task_code`（1..总任务数）；同 slot 映射保证跨批次同人同 ID。
