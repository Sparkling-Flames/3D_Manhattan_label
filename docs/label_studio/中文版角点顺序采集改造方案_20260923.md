# 中文版角点顺序采集改造方案

状态：设计方案，未部署、未改正式脚本或正在采集的10图。当前研究合同仍为 `consensus_research_20260923_v1`。待这一批结束并导出备份后，在新版本中文采集批次启用；不将新字段自动补成旧作答的已确认真值。

## 1. 当前链路的缺口

本地源码核对（不等于已核实线上运行版本）：

- `tools/label_studio/official/ls_userscript_annotator.js` 已有上下点配对、顺序交换、3D预览、`normalizePreviewOrder` 和 `handlePreviewOrderSaveMessage`。
- `savePreviewOrderOverride` 仅将顺序写入浏览器 `localStorage`；缓存按 project/task/user 区分，未按 annotation 版本区分。预览中的“保存”不等于随标注提交到服务器。
- 提取关键点时只保留坐标，未保留 LS region/result ID；`clonePreviewCornerPoint` 也会丢失身份。当前顺序是相对于当时默认配对数组的下标；再次排序或重配对后，仅有下标不能可靠恢复。
- `renderPreviewOverlayPairs` 按当前顺序重新编号。若标注者填写这些会随换序变化的编号，就可能发生编号含义漂移。
- 当前按 x 近邻贪心配对，未配上的点可能不进入预览；保存正式顺序前必须保证所有目标角点都有明确上下对应，不能以“预览出现了”代表点集完整。

结论：复用现有顺序编辑器，补齐稳定点对身份、明确确认、同一份标注的持久化和导出校验。不新建独立上传服务，不修改 active_time 的用途。

## 2. 标注员实际操作

1. 正常标点，打开现有预览。每个上下点对显示固定编号 A、B、C……；编号绑定点身份，不随顺序交换重新编号。同时显示一条环序，如 `A → C → B → D → A`。
2. 先检查上下配对。配对不正确时先核对配对，不能靠换环序掩盖。首版不必新增完整配对编辑器；现有操作无法明确配对时记录“无法确定”，不要求移动原点去迎合近邻配对算法。共享 x 仅是预览派生坐标，不自动挪动原标注点。
3. 沿房间边界依次核对。选择“确认当前顺序”，或复用现有交换功能调整后选择“确认调整后的顺序”。提供直接输入 `A C B D` 的快捷方式；末点自动接回首点，不要求重复填写起点。起点任意，正向/反向均可，不强制从图片最左端开始。
4. 若遮挡导致不能判断，选择“连接顺序无法确定”，可备注疑问点对；允许提交这种明确的未知，不要求编造一条看起来好看的环。没有可用角点时单列“无可记录的角点布局”；不能把全部 OOS 自动视为无顺序。
5. 提交前显示“顺序已随本次标注准备保存”。只有服务器提交成功并能重新读取后才显示“已提交”；浏览器缓存或 iframe 的保存 ACK 不能冒充服务器成功。

标注提示建议：**请按房间围护墙体实际相邻关系连接角点。墙段被其他墙体遮挡时，连接顺序可能不同于图片从左到右的顺序；家具遮住角点不一定需要换序。不要为让3D预览规整而改变你认为正确的墙体关系。无法判断时请选择无法确定。**

尖角、自交和怪异3D只给检查提示，不用几何指标强迫标注者“修成合格”；正常转角、遮挡重叠和非Manhattan结构可能触发这些信号。不显示GT、其他标注者的点或自动推荐GT环序。

## 3. 数据记录与保存

建议新中文表单版本 `manual_scope_order_v1`，只对新版本任务启用。正式字段合同需在实现验收后纳入当前机器合同；以下是草案，不是已经上线的schema。

采用一个 LS 原生图级结果字段 `layout_order_record` 承载结构化文本，由脚本写入，标注员操作中文控件而不编辑JSON。优先使用原生 TextArea result，顺序与点位一起通过同一 annotation 的原生提交保存；禁止只写 `task.data`、localStorage 或 active_time 日志。原生 TextArea 支持图级文本采集，但当前 LS 版本中脚本写入、重新加载及导出链路必须在测试项目实证，不能只看到输入框有字就宣布保存成功。参考：[官方 TextArea](https://labelstud.io/tags/textarea)、[官方结果格式](https://labelstud.io/guide/task_format)。

| 字段 | 含义 |
|---|---|
| `schema_version` | `layout_order_record_v1` |
| `status` | `confirmed_current` / `confirmed_adjusted` / `uncertain` / `no_layout`；编辑中另有未确认状态，不伪装成确认 |
| `pairs` | 每对的稳定 pair_id、top_region_id、bottom_region_id、固定显示编号。ID来自真实LS点对象，不从可变化的数组位置猜测 |
| `ring_order` | 完整且无重复的 pair_id 环序；`uncertain/no_layout` 为 null |
| `draft_ring_order` | 可选，未知时保留标注者当前草稿，但不得作为已确认顺序分析 |
| `point_snapshot` | 确认时各 region_id 的原坐标、坐标制和图像尺寸；用于导出时核对是否仍对应同一版点集，不是新增GT |
| `confirmed_at`, `script_version` | 确认时间与脚本版本 |
| `note` | 标注者的可选说明；不推断遮挡事实 |

project/task/annotation/completed_by 以父级LS导出为主。浏览器未提交草稿用当前annotation草稿身份隔离；不能沿用仅 project/task/user 的旧缓存键。复制、重开或修改版本均需核对身份及点集。

展示编号与稳定ID分开：重排不改ID；点移动保留ID但撤销“已确认”，删点使相关配对失效，新点创建新ID。任何坐标、上下对应、点数或环序变化都需要重新确认；不能拿旧确认状态覆盖新坐标。缺少/重复LS点ID时显式报错，不退回“第几个点”静默关联。

保留旧 localStorage 作为编辑恢复缓存，显示“仅本机草稿”；它不能自动升级为标注者已确认的正式结果。

## 4. 修改位置与最小范围

| 位置 | 改造内容 |
|---|---|
| 中文正式/调试 userscript | 关键点与克隆链路保留region ID；稳定点对编号；原生顺序结果写入/读取；编辑失效；提交核对 |
| 中文 Manual XML | 新增原生顺序记录字段与中文状态控件；继续保留原Scope问题，不引入其他人员/GT信息 |
| `vis_3d.html`及顺序消息协议 | 传递稳定pair ID、当前环序、源点集版本；确认消息只能作用于当前iframe、当前任务和当前annotation；复用交换/预览，不改几何让其自动变规整 |
| 导出分析入口 | 读取新字段，核对点身份、全部配对覆盖、环序排列和点集版本；未知/旧版缺失分别报告，不能默认按x等于已确认 |

共享 viewer 对旧版/英文消息保持兼容，但新采集字段仅在新的中文表单版本启用。现有英文脚本不被动更换表单要求。不能只更新 userscript 而不更新XML及结果解析，也不能把原生 points 的数组顺序重排当作保存环序。

提交校验优先验证身份和结构合法性：每个点至多属于一个点对、每对上下身份明确、已确认环包含全部点对且无重复/缺漏。自交、锐角、不正交等几何疑点只提示，不能直接阻止一个注明不确定的作答。原生表单必填与导出校验配合；现有点击/快捷键 best-effort 拦截不足以保证所有提交路径，必须检查实际提交结果。

## 5. 上线验收与批次边界

最小验收覆盖：默认确认与交换确认；刷新/重新登录后从服务器恢复；同任务不同annotation不串记录；移动/增删点后确认失效；未知可提交；部分未配对不被静默丢弃；原生提交与更新/快捷键路径；从标准JSON导出重新构建同一环；旧中文/英文任务不受影响。只用测试任务，不动正在收集的10图。

这批10图结束后先保存原始导出和版本清单，再在下一批启用。若想给这10图补顺序，单独安排“针对已导出版本补充顺序”的任务，固定原点坐标及annotation身份，不覆盖原始作答，不把事后补充冒充原采集时已有顺序。标注员旧浏览器若还留有缓存，可作为待确认线索，不能当服务器已保存的事实。

新增顺序核对会增加时间，并可能促使标注者反思点位；新旧批次用明确form/script版本分开，不能直接把总active_time差异解释为人员效率变化。保留现有计时和分发真源，不另造一套日志；若后续需要区分顺序检查耗时，再单独设计阶段计时。

本轮交付仅此方案。当前采集、官方脚本、XML、路由、原始数据和字段合同均未应用变更。部署前须确认实际中文在用脚本/表单版本并完成上述小范围验收。
