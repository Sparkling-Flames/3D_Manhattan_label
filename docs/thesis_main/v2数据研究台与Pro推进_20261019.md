## 3. 导师汇报的默认阅读路径

建议现有首页提供“汇报导览”和“数据浏览”两种阅读入口，共用数据。默认导览按六步：

1. **任务与真实数据**：一张全景图解释上下点、目标空间和不同人的表达；库存与可评分分母分开。
2. **怎样判断结果**：先看一对图，再解释总分、底面/方向/高度和局部结构，公式默认折叠。
3. **图片为什么难、人怎样响应**：固定6转折的条件图与同人标注，展示多数支持。
4. **人有什么不同**：连续画像与可靠性实例，不要求理解类别代号。
5. **多人怎样形成共识**：对应→投票→定位→连接的可切换保存状态，再看人数过程中的Q/V/完整率。
6. **能用来做什么**：已有同房相似、选队质量—时间取舍、人数选择与历史成本，最后列分类成果报告与展示待办。

每个结论卡固定四层：**一句发现 → 一张图/一组实例 → 支持范围与例外 → 数据/方法来源**。首屏不铺几十张表。允许进入原表、按图和人员筛选、对比正反例、返回讲解当前位置；图表坐标尽量写中文含义和单位，缩写作为辅助。静态报告图不随筛选变化时明确注明，避免表格筛选后图仍旧却看似同分母。

## 4. tooltip / hint具体要求

- 使用[CONTEXT汇报名词表](CONTEXT.md)作为解释起点，落实成一个可复用词典；若已有组件则扩充，不到处复制长文案。
- 表头、指标名和图例加可识别的“?”提示入口。悬浮和键盘聚焦能看短释义；点击/触屏可固定打开详细解释，Escape关闭。不能只靠HTML title或鼠标悬浮，内容不超出视口。
- 解释分为：它回答什么、数值方向/单位、当前比较对象、一个直观例子、详细来源。公式和精确算法放详细层。
- 单位、分母、Manual/Semi、v1/v2、正式/诊断及自动/辅助状态常驻；这些不能藏在tooltip里。
- `H`分别显示“几何自遮挡”和“高度损失”；`D`分别显示“方向残差”与“共同背景”时用完整名；`k`在源人数和融合人数中按表释义，避免一个全局字母提示错误套用。
- 人员ID、案例ID都配一句内容标题，例如“全票仍会位置不同”，避免让导师靠代码记研究。

## 两条研究方向都继续

**正向方向：Q×T×难度产生可解释细类。** Q的绝对交付与相对表现并列；难图绝对质量好、相对同图他人好、相对本人平常更好，分别定义。“难度纳入细类”不是只做难图汇总表。连续画像作为信息底座，粗类用于解释，细类用于组队，不预先限定最多四类。当前相对Q与时间阈值为探索设置，不是已验证能力等级。Semi、scope、排除及结构错误可继续细分，但不揉成Q或通用综合分。

**反向方向：从当图标法簇出发。** 沿用既有距离，优先研究全局亲近度9°/12°，完整链接作对照；不同点对数分开。先比较固定背景成员时簇内/跨簇换人及簇构成，再回看成员Q/T/难度等特征，最后用未参与发现的建筑检验是否能预测。簇号是图内编号，不能直接跨图当人员类型。分簇、融合与质量评价分别承担不同职责。

两条方向最终比较同图同k下随机、Q、Q+T、Q+T+难度及进一步细分策略。直接用当图实际标法选择的方案另列解释性/oracle结果，不能混为人员历史画像的预测成功。接受高Q组合共享遗漏、簇内换人也会变、跨簇不一定变坏等反例。
