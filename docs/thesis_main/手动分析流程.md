# 手动分析流程（Pilot / PreScreen）

这份文档只给我自己用。目标很简单：每次拿到一批数据后，按同一套顺序把分析、审计、可视化和基础测试跑完。

当前正式入口只有一个：

- `tools/thesis_main/analysis/analyze_quality.py`

旧的 `visualize_output*`、旧 notebook、旧临时脚本都不作为主入口。

## 1. 先区分阶段

### Pilot

Pilot 的作用是先把流程跑通，不是做最终结论。

你在 Pilot 里主要看三件事：

1. 导入/导出有没有明显 schema 问题。
2. `quality_report` 能不能正常生成。
3. 图表和审计包能不能正常落地。

### PreScreen

PreScreen 是正式 Stage 1 的第一轮。

你在 PreScreen 里主要看四件事：

1. `PreScreen_manual / PreScreen_semi / PreScreen_oos` 的数据量和冻结口径对不对。
2. `scope`、`difficulty`、`model_issue`、`type4` 这些合规字段有没有按正式口径落到 `quality_report`。
3. active log 有没有缺失、unknown、multi-session、script_version 问题。
4. 生成的审计包是否能直接用于后续人工检查。

当前 Stage 1 冻结对照值是：

- `PreScreen_manual = 30`
- `PreScreen_semi = 18`
- `PreScreen_oos = 9`

这几个数是对照值，不是让你重新定义规则。

## 2. 你需要准备哪些文件

### 2.1 Pilot

Pilot 通常只需要一批小样本导出：

- `export_label/<pilot_run>.json`

如果你已经开了日志，就再准备：

- `active_logs/`

如果这批 Pilot 里有多份导出，就把它们先放到同一个 run 目录下。

### 2.2 PreScreen

PreScreen 这一阶段，除了本轮导出，还要对照当前正式 Stage 1 冻结文件：

- `analysis_results/phase1_progress_20260324/stage1_final_binding_audit_v6.json`
- `analysis_results/final_gold_layer_20260325/final_gold_records_v1.jsonl`
- `analysis_results/final_gold_layer_20260325/final_gold_summary_v1.json`
- `import_json/stage1_prescreen_final_20260325/stage1_prescreen_manual_import_v2.json`
- `import_json/stage1_prescreen_final_20260325/stage1_prescreen_semi_import_v5.json`
- `import_json/stage1_prescreen_final_20260325/stage1_prescreen_oos_import_v2.json`
- `import_json/stage1_prescreen_final_20260325/stage1_prescreen_import_summary_v4.json`

如果是新一批 Prescreen 导出，就把它们替换成你这次 run 的实际导出文件。

## 3. 标准手动跑法

### 3.1 先跑分析

#### Pilot

单文件示例：

```bash
python tools/thesis_main/analysis/analyze_quality.py export_label/pilot_YYYYMMDD.json \
  --dataset_group Pilot_Manual \
  --project_version pilot_YYYYMMDD \
  --output_dir analysis_results/pilot_YYYYMMDD \
  --output analysis_results/pilot_YYYYMMDD/quality_report_YYYYMMDD.csv \
  --metric corner \
  --quality_mode v2
```

如果有日志目录，就显式带上：

```bash
python tools/thesis_main/analysis/analyze_quality.py export_label/pilot_YYYYMMDD.json \
  --dataset_group Pilot_Manual \
  --project_version pilot_YYYYMMDD \
  --output_dir analysis_results/pilot_YYYYMMDD \
  --output analysis_results/pilot_YYYYMMDD/quality_report_YYYYMMDD.csv \
  --metric corner \
  --quality_mode v2 \
  --active-logs active_logs
```

#### PreScreen

如果是单个导出文件，直接跑：

```bash
python tools/thesis_main/analysis/analyze_quality.py export_label/stage1_prescreen_manual_YYYYMMDD.json \
  --dataset_group PreScreen_manual \
  --project_version stage1_YYYYMMDD \
  --output_dir analysis_results/prescreen_YYYYMMDD \
  --output analysis_results/prescreen_YYYYMMDD/quality_report_YYYYMMDD.csv \
  --metric corner \
  --quality_mode v2
```

如果这一轮有 manual / semi / oos 三份导出，就按同一个 CSV 追加：

```bash
python tools/thesis_main/analysis/analyze_quality.py export_label/stage1_prescreen_manual_YYYYMMDD.json \
  --dataset_group PreScreen_manual \
  --project_version stage1_YYYYMMDD \
  --output_dir analysis_results/prescreen_YYYYMMDD \
  --output analysis_results/prescreen_YYYYMMDD/quality_report_YYYYMMDD.csv \
  --metric corner \
  --quality_mode v2

python tools/thesis_main/analysis/analyze_quality.py export_label/stage1_prescreen_semi_YYYYMMDD.json \
  --dataset_group PreScreen_semi \
  --project_version stage1_YYYYMMDD \
  --output_dir analysis_results/prescreen_YYYYMMDD \
  --output analysis_results/prescreen_YYYYMMDD/quality_report_YYYYMMDD.csv \
  --append \
  --metric corner \
  --quality_mode v2

python tools/thesis_main/analysis/analyze_quality.py export_label/stage1_prescreen_oos_YYYYMMDD.json \
  --dataset_group PreScreen_oos \
  --project_version stage1_YYYYMMDD \
  --output_dir analysis_results/prescreen_YYYYMMDD \
  --output analysis_results/prescreen_YYYYMMDD/quality_report_YYYYMMDD.csv \
  --append \
  --metric corner \
  --quality_mode v2
```

如果有日志目录，就在这一步加上 `--active-logs active_logs` 或你这轮实际的日志路径。

### 3.2 再跑 active log 审计

如果这批数据有 active logs，就单独跑一次：

```bash
python tools/thesis_main/analysis/audit_active_log_quality.py active_logs \
  --summary-json analysis_results/prescreen_YYYYMMDD/active_log_audit_summary.json \
  --per-file-csv analysis_results/prescreen_YYYYMMDD/active_log_audit_per_file.csv
```

这一步主要看：

- `parse_error_count`
- `unknown_task_count`
- `unknown_annotator_count`
- `unknown_project_count`
- `unknown_session_count`
- `missing_script_version_count`
- `multi_session_pair_count`

### 3.3 再跑可视化审计包

这一步的正式入口是：

```bash
python tools/thesis_main/analysis/build_experiment_visual_audit.py \
  --quality-csv analysis_results/prescreen_YYYYMMDD/quality_report_YYYYMMDD.csv \
  --out-dir analysis_results/experiment_visual_audit \
  --tag prescreen_YYYYMMDD \
  --active-log-summary-json analysis_results/prescreen_YYYYMMDD/active_log_audit_summary.json \
  --active-log-per-file-csv analysis_results/prescreen_YYYYMMDD/active_log_audit_per_file.csv
```

如果这批没有 active logs，就把后两个参数去掉。

## 4. 每次要看哪些输出

### 4.1 Pilot 先看这些

- `analysis_results/pilot_YYYYMMDD/quality_report_YYYYMMDD.csv`
- `analysis_results/pilot_YYYYMMDD/reliability_report_YYYYMMDD.csv`，如果这批任务满足多标注且脚本真的生成了它
- `analysis_results/experiment_visual_audit/pilot_YYYYMMDD/summary.json`
- `analysis_results/experiment_visual_audit/pilot_YYYYMMDD/SUMMARY.md`
- `analysis_results/experiment_visual_audit/pilot_YYYYMMDD/table_field_audit.csv`
- `analysis_results/experiment_visual_audit/pilot_YYYYMMDD/table_schema_alignment.csv`
- `analysis_results/experiment_visual_audit/pilot_YYYYMMDD/table_active_time_row_audit.csv`

Pilot 里我重点看：

- `n_rows` 是否和实际导入一致
- `scope_missing_rows` 是否为 0
- `type4_source` 是否还是 `derived_fallback`
- `session_count_column`、`project_id_column` 是否只是在做兼容桥接
- 生成图表有没有缺图

### 4.2 PreScreen 再看这些

- `analysis_results/prescreen_YYYYMMDD/quality_report_YYYYMMDD.csv`
- `analysis_results/prescreen_YYYYMMDD/reliability_report_YYYYMMDD.csv`，如果有
- `analysis_results/prescreen_YYYYMMDD/active_log_audit_summary.json`
- `analysis_results/prescreen_YYYYMMDD/active_log_audit_per_file.csv`
- `analysis_results/experiment_visual_audit/prescreen_YYYYMMDD/summary.json`
- `analysis_results/experiment_visual_audit/prescreen_YYYYMMDD/SUMMARY.md`
- `analysis_results/experiment_visual_audit/prescreen_YYYYMMDD/table_field_audit.csv`
- `analysis_results/experiment_visual_audit/prescreen_YYYYMMDD/table_schema_alignment.csv`
- `analysis_results/experiment_visual_audit/prescreen_YYYYMMDD/table_b2_scope_conflict.csv`
- `analysis_results/experiment_visual_audit/prescreen_YYYYMMDD/table_active_time_row_audit.csv`

PreScreen 里我重点看：

- `PreScreen_manual / PreScreen_semi / PreScreen_oos` 的行数是否和这轮导出一致
- `scope_filled`、`difficulty_filled`、`model_issue_missing_required`、`model_issue_conflict` 是否按正式字段在跑
- `type4_flag` 是否是正式字段直出，还是还在 fallback
- `active_time` 行级审计里 `missing_script_version`、`unknown_*`、`multi_session` 是否过高
- `scope` 混合任务有没有被单独披露

## 5. 数据怎么存、怎么看

这部分按 `analysis_results/README.md` 的口径来：新结果放在带 round/tag 的子目录里，旧结果进 `legacy/`，不要把一堆输出散到根目录。

### 5.1 怎么存

每次拿到一批新数据，尽量按同一个 tag 归档，方便后面回溯：

- 原始导出：`export_label/<round_tag>.json`
- 日志目录：`active_logs/`
- 分析输出：`analysis_results/<round_tag>/`
- 可视化审计包：`analysis_results/experiment_visual_audit/<round_tag>/`

如果这一轮有多个导出文件，就放在同一个 round 目录下，不要拆散。

如果某批结果只是试跑、示例或被后续结果覆盖，就挪到：

- `analysis_results/legacy/<date_or_tag>/`

不要直接删，后面经常还要回看。

### 5.2 怎么看

先看主分析结果，再看审计包：

1. `analysis_results/<round_tag>/quality_report_*.csv`
2. `analysis_results/<round_tag>/reliability_report_*.csv`，如果这批真的生成了
3. `analysis_results/<round_tag>/active_log_audit_summary.json`
4. `analysis_results/<round_tag>/active_log_audit_per_file.csv`
5. `analysis_results/experiment_visual_audit/<round_tag>/SUMMARY.md`
6. `analysis_results/experiment_visual_audit/<round_tag>/summary.json`
7. `analysis_results/experiment_visual_audit/<round_tag>/table_schema_alignment.csv`
8. `analysis_results/experiment_visual_audit/<round_tag>/table_field_audit.csv`
9. `analysis_results/experiment_visual_audit/<round_tag>/table_active_time_row_audit.csv`

Pilot 里优先看：

- 导入量是不是对得上
- `quality_report` 有没有正常落地
- 审计包有没有缺文件

PreScreen 里优先看：

- `PreScreen_manual / PreScreen_semi / PreScreen_oos` 的行数是不是对得上
- 合规字段是不是按正式口径落到了 `quality_report`
- active log 的异常信号是不是过高

## 6. 出问题时先看什么

### 导入不对

先看：

- 导出 JSON 里的 `task_id` 数量
- `dataset_group`
- `scope`
- `prediction` 是否和任务类型匹配

然后对照：

- `import_json/stage1_prescreen_final_20260325/stage1_prescreen_import_summary_v4.json`

### 分析结果不对

先看：

- `quality_report_*.csv` 里 `dataset_group` 是否对齐
- `scope_missing_rows`
- `layout_gate_fail_rows`
- `model_issue_missing_required_rows`
- `n_type4_rows`

### active log 不对

先看：

- `parse_error_count`
- `unknown_task_count`
- `unknown_annotator_count`
- `missing_script_version_count`
- `multi_session_pair_count`

只要这些信号明显不正常，就先停，不要继续往后堆图。

## 7. 什么时候跑测试

只要你改了分析脚本，就跑下面这组：

```bash
pytest tests/test_audit_active_log_quality.py tests/test_build_experiment_visual_audit.py -q
```

如果你改了更靠后的分析逻辑，再补：

```bash
pytest tests/test_analyze_stage_aware.py -q
```

如果你只是跑数据、没改代码，这组测试不是每次都必须跑。

## 8. 一句话原则

Pilot 先验证流程能跑通，PreScreen 再验证正式口径和冻结文件能对上。  
任何时候都先看 `analyze_quality.py` 的输出，再看审计包，不要反过来。
