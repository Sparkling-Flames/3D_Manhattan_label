# 点投票与区域投票：方法溯源

2026-10-07当前实现与路线见[共识投票机制与三路线推进](共识投票机制与三路线推进_20261007.md)。本页保留原讨论与历史原型，不把当时未完成状态当作当前进度；当前融合以人员支持为目标，GT为外部评价。

2026-10-03。用户已确认想法是跨人员的邻近角点聚类，并补充可能需要以一对上下点，或分别对top、bottom进行匹配。因此这里的“簇”明确是角点／点对簇，不是先给整份标注分簇。目标是按人员支持投票，以簇中心形成融合角点；本页不更新融合基线或正式合同。

**以前确实做过接近的实验，最直接的是9月26日八图原型：全体角点对先聚簇，再融合对应坐标；既试过整份标法分支内融合，也试过跨分支共享角点融合。尚未完整验证的是“全部点簇投票后直接生成一个新闭合环”的一般算法。这个方向可以作为当前Lee区域融合的并行候选，旧反例不构成全盘否定。**

## 2. 八图原型究竟怎样投点、怎样保留连接

核心位置为[角点身份构造](../../tools/thesis_main/analysis/union_branch_consensus_20260926.py)、函数`_feature_union`（第66行起）及`fit_union_branches`（第112行起）：

1. 一个人的一处角点保留**上下端点对**。把全部人员的角点对汇入同一池，比较两对的top球面角距与bottom球面角距，取两者最大值作匹配距离；不是直接将所有top和bottom混为一个点池。
2. 对这个角点对池做complete-linkage；探索2.5°、5°、10°门限。5°为演示／探索参数，历史三值扫描不是最优阈值校准，未经实测证明5°最佳。门限限制的是簇内最大距离，不是已校准的点击误差半径。
3. 同人不同角点之间距离设为181°，禁止合入同一身份簇；输入同一worker出现两份作答直接报错。因此自动模式下每个点身份至多获得每人一票，不因某人点多就增加该点票数。它尚不能自动解决同一细节有人画2对、有人画3对的完整对应。
4. 每份标注的角点身份按原环排列，循环起点和反向等价；身份集合或邻接不同的作答保留不同分支。它没有把所有点统一按一个新x序重连，也没有恢复未知物理邻接。
5. 主输出在每个分支内，对同身份的BEV底点坐标逐维取中位数，高度另取中位数。
6. 另保存`shared_feature_candidate`：同一身份的点可以来自**其他完整分支**，汇总其全部当前人员观测取中位数，但输出仍沿用本分支的连接；各点支持人数单列，完整分支支持人数不随之增加。

所以，旧原型已经包含“全体点先聚簇”和“簇中心融合”两个重要环节；但“投票”主要体现为点身份支持及整分支支持，没有先设点支持率门槛，再把过门槛点自动连接成一个新环。不能将“每个角点各有很多人支持”改称“完整融合形状有同样多的人支持”。

旧代码的“中心”是BEV底点坐标中位数及高度中位数，不是ERP画布质心，也不是角点的算术平均或二维几何中位点。另有角点距离medoid和区域IoU medoid，均选取一份实际原标注，不产生新的逐角点坐标。

## 3. 已保存的实测信号及限制

[八图结果](../../analysis_results/union_branch_consensus_20260926/results.json)对应160份输入、153份当时可用于独立几何计算的作答，八图均为用户指定的困难／门洞／OOS开发例。保留当时分母，不将历史资格直接迁移到当前研究；原始导出与当前独立票规则不变。

本次仅读取八个保存的`cases/*.json.gz`、核算其中已保存分数差，没有重新运行匹配或几何算法。在默认5°、至少2人支持的19个分支上：

| 对照 | 原GT BEV IoU差均值 | 提高／降低／不变 |
|---|---:|---:|
| 分支内逐点中位数 − 分支内原标注medoid | +0.001905 | 6／6／7 |
| 跨分支共享身份中位数 − 分支内逐点中位数 | +0.017880 | 15／4／0 |

这说明**利用其他标法中可对应的共享角点，曾出现值得继续检查的收益**，不是“点融合已经试过并证明无效”。同时，19个分支共享图片及人员，不是19个独立实验；GT在这些场景下有范围适用性限制，不能将IoU改善直接称真实质量提高，更不能把这张表与当前136图Lee结果直接横向排名。

默认5°产生130个精确身份／邻接分支，最大分支通常仅1—4人，2.5°／10°下数量明显变化。这暴露了身份匹配和“完全相同环签名”的碎片化，不能证明困难图没有共识。更不应据此否定用较可靠局部对应来聚合点的可能性。

[9月27日讨论](PANORAMA_CONSENSUS_RESEARCH_DISCUSSION_20260927.md)比较了绑定上下对、独立端点、混合三路的概念及反例，当时明确没有完成三路端点融合实测。7/8图存在bottom很近、top较远的候选，4/8图存在同人两个角点对很近；它们是阈值选择的诊断，不是三路算法胜负的结果。

**10月1日随后确实做过拆分端点的匹配实测，不能笼统说“只讨论过”。** [Pro报告第4.2与第5节](../../research/layout_methods_review_20261001/pro/REPORT_zh.md)分别运行绑定、仅top、仅bottom的周期保序部分匹配；3个真实作答—参考比较、各15个参数设置，共45组，其中6组的top／bottom映射冲突。另在两份真实几何上生成300组共线加点＋噪声对照，某个4px条件的30次中11次冲突。[dot独立复核](../../research/layout_methods_review_20261001/dot/audit-oct1-matching/MATCHING_LOCAL_AUDIT_zh.md)核对了映射和冲突计数。这些是实际运行的**两份布局间对应／冲突诊断**，不是多人角点簇投票、中心融合和完整layout恢复的实测；参数网格与扰动次数也不是独立真人数。

因此，与用户记忆的对应关系明确为：八图的“上下点对身份簇＋中心”已经实现；分开top／bottom的匹配已有数值实验；以点对和邻接为骨架、分开估计两端的混合多人融合仍待落实。**两端分别匹配成功，不等于它们可以自动重新配成同一面墙角**；应保留原始点对身份及冲突状态，不能从两个独立中心直接推定配对正确。这个边界不否定分别利用两端定位信息的价值。

严格绑定上下点对的基线不能代表绑定／拆分／混合三路完整方案，也不能据此决定三路优劣。

## 4. 对新想法的判断

**合理，尤其适合大体相同的结构、对应墙角较明确、主要差异是定位波动的情况。** 汇集同一角点观测后估计中心，有机会抑制个别偏点，并给出直接可显示的融合角点；若保留可靠上下对应，还可以形成完整layout候选。它也可能补充区域面积投票对小细节不敏感的问题，但这一点仍需实测。

算法必须分开三个决定，才能知道收益或失败来自哪里：

- **什么点属于同一角：** 相近是候选证据，不自动等于相同结构；预处理共享x和既定环序继续保留。
- **这一角是否保留：** 按不同人员支持数计票，明确未匹配是缺失、遗漏还是另种结构；“取最高票”和“超过半数”不能混叫同一种规则。
- **保留角点放在哪、怎样连接：** 均值、中位数、点medoid分别是候选。位置中心不能自动决定正确邻接、上下配对或完整空间范围。

算术均值并非原则上不合理；它对离群位置较敏感。逐坐标中位数更耐单轴离群，但依赖坐标表示；medoid保留真实观测却不一定最贴近中心。跨ERP接缝应使用周期一致的坐标处理，地平线附近相同像素波动可能对应很大BEV变化。不能在多峰结构间无条件取一个中心，随后将其解释为多数都表达过的墙角。

这些是需要展示和比较的具体环节，不是要求把所有难点一次解决之后才能做demo。一个正例证明当前例子可行，一个反例说明某个边界；两者都不能单独决定全路线有效或无效。

## 7. 用户对完整标注输出与demo的进一步纠正

用户要求demo先展示同一图的不同**整份标法簇**、每簇支持人数及代表，再看融合结果；这与前述跨人的**角点身份簇**不同。当前BEV融合只有底边，缺失top_y，不能作为已经完成的完整layout共识。后续完整点候选必须明确保存top/bottom、配对及连接，不以从底面猜出的统一墙高补顶边。

[Lee原文](https://ceur-ws.org/Vol-2173/paper10.pdf)第4、5、6节分别描述区域tile投票、以Jaccard相似度作谱聚类，以及MSCOCO普通对象分割实验。它既非全景layout论文，也非逐角点投票；BEV不是论文要求。当前将其区域投票迁移到BEV是本项目的方法选择。也可以直接以ERP上下曲线形成墙带进行区域投票，此时上下轮廓都参与，而非只投底边。

在每份墙带每列都是跨共同地平线的单区间、人员数为n且票数门槛为t时，区域多数的上边是top_y的第t小值，下边是bottom_y的第n−t+1小值。因此该适用域内能直接得到稠密上下轮廓；MV50的t=ceil(n/2)，严格多数t=floor(n/2)+1。这是对区间集合投票的等价计算，不是对角点身份投票。它尚未决定稀疏墙角在哪里、上下转折如何配对，也不证明融合后是Manhattan布局。

保留确认环时，不能沿用会重新按x排序的墙带入口去掩盖回退或多层范围。本轮最小直接ERP候选仅研究既定环沿经度单向绕一周、上下曲线单值且跨地平线的输入；不适用状态按人员及整组保留，不改环、不静默取最近墙包络。直接ERP表达与完整声明空间适用范围不同，不能用其可见轮廓代替所有隐藏结构。

## 8. 融合候选也需要单独检查连接顺序

用户再次提醒：融合形成的新角点可能仍需调整顺序。当前点中心demo只沿用簇代表的环邻接作为初始候选，保存`source_order_status`与`source_ring_confirmed`，新候选自身始终为`ring_confirmed=false`；合法底面或可投影状态不等于邻接正确。原作答仍遵守已确认环保留、未确认采用既有共享x默认序，不回写原始或预处理数据。

已核对的历史流程如下；这些是当时的候选筛查，不是自动错误分类器：

- 早期[9/23宽筛](../../analysis_results/order_screening_20260923/README.md)曾用曲线接头、极区、边交叉、退化等异常广泛召回；[9/28候选整理](../../analysis_results/order_candidates_20260928/README.md)再区分明确人工线索、自交、连续锐角与密集点。这些早期规则不应冒称后来最终主筛。
- [原GT主筛](../../analysis_results/order_gt_screened_20260928/README.md)：原始GT的完整点对环忽略循环起点及反向，正常全景接缝不触发；局部x回退、不同点对同x及明确人员问题线索用于圈定复核范围。原始GT只读，不自动改它的环。
- [几何补查](../../analysis_results/order_pattern_recall_20260929/README.md)：改前地面锐角小于45°、1024宽图周期24px内至少三对点、近方位且深度比至少1.5组成补查并集；两对密集不单独召回。当时4对及以下默认跳过，明确人工顺序证据除外，另有排除、已确认和用户不召回名单。
- [同图改序史补查](../../analysis_results/order_model_same_image_20260929/README.md)：同图其他作答曾真实改变邻接，是对尚未确认对象的补查线索；本对象不给自己提供证据，循环起点或整体反向不算改序。这一步确实执行过，不只是建议。
- [完成性审计](../../analysis_results/order_completion_audit_20260929/README.md)：77份几何补查中6份改序、71份不变，后续35份同图补查中1份改序、34份不变。说明候选只是值得看，不是已经判错；“既定队列无剩余”也不等于全量零漏检。该审计是配对补齐前的历史快照，最终输入仍以当前manifest为准。

已再次向[原线程](codex://threads/01a0db6b-526e-79c3-b8ba-b50f1a1fffd6)取得只读交接。其补充确认：3D预览参与人工判断，但未查到方向残差作为后期主排序队列的独立自动召回门限；`crossing_count`虽被计算，也不是77份补查`candidate_reason()`的单独触发项。不能把所有诊断字段都称为实际筛选规则。

迁移到融合研究时，可以复用固定点对身份上的排列检查、循环／反向等价判断，以及作为预警的自交、锐角、密集、深度突变与原图／3D对照。**不能直接照搬旧人工任务的召回资格、4对跳过规则或GT主筛来决定融合环。** 旧`diagnose_points`还含历史地平线角色限制和共享x计算；如复用，应只提取诊断逻辑并按当前坐标合同适配，不重新预处理输入。

后续应并列保存融合原候选与改序候选，记录角点／点对身份、连接来源、改序依据及是否人工确认；多种顺序均可成立时保留歧义。目标GT只评价，不能拿最高IoU选择连接；若有人工改序，单列为含人工介入的方法。ERP不适用不能自动推出顺序错误：合法的凹入、遮挡或相机外声明范围也可能不是单值墙带。当前demo尚未实现自动改序或新环搜索。

## 9. 历史阈值确实有工作版本，仍需重新验证适用性

用户明确记得以前定过阈值内容，同时要求继续探索。核对原线程交接及仓库后，不能再将历史概括为“只有一个未经研究的5°”，也不能把已有工作设置说成已正式确定的语义门限。

| 历史工作设置 | 当时的对象与距离 | 对当前demo的意义 |
|---|---|---|
| 9°主分析，6°／12°敏感性 | [9/20 RC1配置](../../analysis_results/clustering_release_received_20260920/config.json)：整份标注`split_cyclic + complete`，上下可分别循环对应 | 有明确工作版本；当前统一点对绑定的整环对应不同，数值不可无条件迁移 |
| 25.6px，统一1024×512画布 | [9/22方法说明](导师汇报讲解与问答_20260922.md#51-预处理与距离)：周期横向差与纵向差构成端点二维距离，再取最大值 | 是像素距离容差，不是球面角距；可重用历史审核案例，不能直接换成当前5° |
| 2.5°／5°／10°，默认5° | [9/26八图点对身份](../../analysis_results/union_branch_consensus_20260926/README.md)：跨人员角点对簇，取上下端点球面角距的最大值，complete-link | 文档明确未校准；对象是角点身份，不是整份作答簇 |
| q＝0.95及更宽／窄网格，OSPA≤6°对照 | [早期多建筑研究](../../analysis_results/multibuilding_threshold_stability_20260909_v1/分析结果.md)：不同几何亲近度与无序点集距离，仍有同点数门槛 | q不是可信概率；OSPA的30°是截断与多点惩罚，6°才是当时分簇阈值，均不等同当前最大端点距离 |

25.6px并非完全没有人工依据：[9/22 Pro开发报告](../../analysis_results/cluster_validation_received_20260922/Pro原报告.md)记录24图、21项明确判断；直接成对判断符合20项，完整链接整簇符合15项，代表半径也符合15项。它提示**成对相近怎样组成互斥簇**本身也需研究，不应只调距离阈值。该数据是目的性选择的开发审核，不能称独立准确率；共享x与最终环序也已在后来更新。

[用户原话与决定](../../analysis_results/clustering_numeric_received_20260920/evidence/latest_decisions.json)明确：容差起辅助作用，仍需人工核验；用户确认了uNb-21的一组对应及相近判断，但反对把该例最大4.59°直接定为筛选条件，`threshold_confirmed=false`。6°／9°／12°也未被确认成普遍语义阈值。旧报告提出的重复定位和独立留出审核只是建议，本次未找到完成独立校准验收的证据。

下一步先复用这些已核准对应及同／异表达案例，在当前预处理输入上分别检查“对应是否成立”“成对距离是否可接受”“整簇是否合理”。同一距离定义下再比较一组容差，同时保存簇人数、近对被拆／远对被并、融合点及连接变化；不以簇更少、人数曲线更早稳定或目标GT更高来挑门限。若开发后需要给正式值，再用未参与定参的图片检验。当前demo的整份作答5°继续只是展示缺省，本轮仅追溯并记录这条验证路线，没有运行阈值网格或冻结新阈值。
