## 2. 坐标、原始视图与环序

数据链为：**原导出及已确认删补 → 完整配对 → 每对上下共享x → 最终环序视图 → 实验人员池 → 融合输出。**

- `original_export_points`保留源导出；`before_preprocessing_points`是共享x处理前视图，可能已含确认修订，两者不保证相同。
- 已确定的上下点对在1024周期内取最短横向差的中点，y不变。这是单份作答预处理，不是跨人员融合。用户认可其作为当前分析的“原始”基准。
- 源点顺序与最终环序都保留；近共线节点不自动删除。无法完整配对的对象保留状态，不静默回退原点冒充可计算输入。
- 修补／借用见`repair_evidence`与借用来源；借用别人点的结果不能再当一份独立完整原答。
- 坐标为1024×512 ERP。原GT连续坐标与模型像素中心适配须区分；BEV／三维的h为共同相机高度单位，h²不是实测平方米。

| 字段 | 对应数组／含义 |
|---|---|
| `preprocessed_points`、`point_labels` | 共享x后的源身份顺序坐标与标签 |
| `links_zero_based` | 上述源顺序数组中的上下点索引 |
| `points_1024x512`、`matterport_links_zero_based` | 最终环序、top/bottom成对排列的坐标及配对索引 |
| `ordered_source_point_indices`、`ordered_source_pair_indices` | 最终视图回到源点／源点对的映射 |
| `ring_confirmed`、`order_status`、`order_record`、`order_origins` | 原作答环序状态与依据，不等于角点身份或新融合环确认 |

报告点号须说明源／最终视图、端点／点对、零基／一基。人工确认环不一定改过顺序；查实际改序应读记录及前后映射，忽略等价的环起点平移／整体反向，不能只比较数组字面是否不同。相关历史在统一包`final_review/received_orders.json`、`历史本人改序补充.csv`、`改前特征与最终改序.csv`与`同图历史改序_补查统计.json`。

**新融合环单独审核。** 原作答改序历史或非x单调确认环可触发新候选顺序复核，位置／节点变化另列。具体政策见[方法第5节](共识投票机制与三路线推进_20261007.md#5-当前进度与下一步路线)。当前交付已保存来源环、直接／投影边和独立人审记录；旧包字段未改，已复用[融合排序工作台](../../analysis_results/consensus_delivery_20261008/order_workbench/index.html)，固定节点与票数，仅审查顺序。

晚共享x对照用`before_preprocessing_points[ordered_source_point_indices]`恢复各端x，保留y、原配对和环序，融合后再协调x。[九图实验](../../analysis_results/adaptive_point_20261007/REPORT.md)中150份有149份处理前坐标等于原导出，另1份不同；原导出、处理前、研究基准在`inputs.json`／`input_comparison.csv`区分。该对照不改统一包。

## 3. 对象、人员、参考与资格

统一包保存3152份人员记录、259份原GT、30份手工GT，共3441对象；涉及27名人员、259张作答研究图及2张仅手工GT参考图。这是库存，**不是任何一次实验的有效样本数**。1295份确认环包括1265份人员环和30份手工GT环，不表示全部标注正确。

- 用`object_id`连接对象，保留与`canonical_annotation_id`的映射；`worker_id`、`image_id`、`image_code`分别承担人员、图片身份与展示名。W／P人员编号、R／object_id作答编号不得直接互换。
- 投票读取`independent_vote_eligible`及原因，并按`canonical_unit`／`person_image_unit`去重；同人多版本不是多票。清洗保留不等于所有实验均纳入。
- `main_quality_gate`、`main_consensus_gate`与方法可计算性分别消费。Manual／Semi／OOS条件、失败池及其原因保留，不删个别失败成员来凑完整池。
- `object_kind`区分人员作答、原GT、手工修订GT，图片`references`给出引用。两版GT分开评价，不按较高分挑参考；GT不参与人员计票。
- 同房／建筑从`room_registry`及同房分类读取，不凭文件名前缀猜；同房不同视点也不必选择同一范围。
