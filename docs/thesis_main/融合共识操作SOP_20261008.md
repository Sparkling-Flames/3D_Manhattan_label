# 融合共识操作 SOP

更新：2026-10-08。适用于当前离线研究流程，执行入口是 `consensus_delivery_20261008.py`。本页说明怎样从人员作答得到一份可追溯的上下点对共识、怎样接入少量人工帮助，以及怎样回收排序。它不改变正式采集协议、人员资格或 GT。

当前定位是**可运行、允许人工辅助的研究流程**。有输出、几何可用、人工确认顺序、实体对应正确是不同状态；本 SOP 不表示所有图片已经完成语义认证，也不宣称自动正确率超过 90%。当前数量和本轮待办统一读[交付报告](../../analysis_results/consensus_delivery_20261008/REPORT.md)，不在每份方法文档重复维护统计。

## 1. 目标与当前选择

给定一张图片和声明的 N 名人员，输出他们按既定规则支持标注的墙角线及其代表位置。自动计算不读取GT，也不以GT分数挑选对应、节点、位置或连接。人工辅助记录实际参考材料，不宣称全部盲于GT；rPc三目标判断曾参考GT，无需因此撤销或重审。GT用于后续质量分析，自动与辅助结果分开解释。

当前流程：

> 已预处理点对与各人原环 → 逐两份作答寻找对应 → 多人相容身份组 → 全池 MV50 → 全部同身份成员的坐标中位数 → 来源候选顺序／人工顺序 → 独立记录几何状态。

“墙角线”是由上下端点组成的竖向观察，不是两个墙角之间的墙面。相同实体的坐标偏差可以融合；前后不同停止处、不同转折处不应仅因距离近就合并。同一墙线上的玻璃顶／天花板等端点目标差异也不能自动解释为定位噪声。遇到难以判定的观察，保留不确定并允许人工辅助。

当前路线已收束为共同墙线身份后的直接融合。绑定、上下独立、自适应是历史设想及原型，保留为可选对照，不再是三条必须完成的任务。当前联合上下与原环找对应，使用同一批成员分别估计上下位置；没有采用上下独立身份、不同来源集合或自动局部切换。固定成员和估计器后，两种“分别算上下中位数”可能相同。

## 3. 自动融合步骤

### 3.1 逐双人作答匹配

对两个原环中的点对，计算上端、下端的球面角距离，代价为两者平均值。遍历环起点和正反方向，动态规划可以匹配两节点，也可以跳过其中一份作答的节点，以容纳漏标和点数不同。

当前交付显式使用 `gap=7.5`：它是**跳过一个节点的代价**，与角距离同量纲，不是“墙角内部最大间距 7.5°”。匹配一对和分别跳过两点是不同代价，不能把该值解释成简单聚类半径。

底层历史函数 `build()` 默认值仍为 13.5，用于旧实验。新研究调用交付入口 `fuse()`，或明确传入 `gap=7.5`，避免误用旧默认值。代码见[对应与连接](../../tools/thesis_main/analysis/ring_correspondence_20261007.py)。

### 3.2 多人身份成组

把逐双人匹配转成相容关系，以完全连接方式成组：组内任意两份观察都要有对应匹配支持；同一人不同点不能进入同一组。不能用简单连通分量把 A≈B、B≈C 自动推成 A、B、C 同一身份。

这是可计算的身份候选，不是已知实体墙角。相邻角可能误合，分散同角可能拆散；完全连接也可能因局部不一致过于保守。这正是后续少量身份审核的对象。

### 3.3 存在票

候选组支持数为不同人员数量 s，按 `2*s >= N` 保留，即 `s >= ceil(N/2)`。偶数人数平票保留；严格多数是不同政策，本流程不暗中切换。

未达票组保存在完整身份账本，但不进入主输出。两处不同目标若分别达票，可以分别保留，不因接近或 GT 只有一个就强制合并。反之，真实同角被拆成几个未达票组时，应先改正对应，再按原完整 N 重计票，不能为了凑票直接合组。

### 3.4 位置融合

当前使用同身份的全部来源，每人等权：

1. 用联合上下距离选取 medoid 作为周期展开锚点。
2. 将各成员 x 在该锚点附近展开，取中位数，再映射回 1024 周期。
3. 分别取 top_y、bottom_y 的中位数，两个输出端点共享上述 x。
4. 周期展开含歧义时保留未决位置，不强造中心。

当前不先选最大位置簇，不作第二次位置多数票，也不以 GT 挑中心。上、下来源集合相同，组内人数不会因位置诊断再次缩水。输出中按 9°划分的上下位置子组仅供诊断，**不决定存在票或最终中心**。

中位数表达观察折中，可能没有任何人员恰好画在该坐标；不等于选中了某个语义目标模式。若组内确有不同端点目标，应查看来源后明确保留折中，或另外定义模式选择实验，不把尚未实现的模式选择写成已有功能。

### 3.5 节点与连接分开输出

`node_consensus` 保存所有达票节点及支持、坐标和来源，独立于排序。对 N≥3，自动顺序从各人原环投影到保留节点后，选取**覆盖全部保留节点的来源环中支持最多的一种**。来源环起点平移与整体反向按等价处理；并列留标记。

这只是来源建议，不要求整环获得全池多数，也不能把每个节点分别达票说成某个完整环达票。原始直接邻接与删去未选节点后的投影邻接分开保存。没有完整来源环时保留无序节点，交给人工排序，不自动补节点或偷偷以 x 排序替代。

人工可指定完整节点排列；明确授权的个案也可用 x 递增。某一图片的授权不推广到全库。原作答 `ring_confirmed` 不传给新融合环。

## 4. 人工身份审核：何时看、怎样接入

先看有实际疑点的局部：疑似同角拆散、不同停止处误合、近邻多人共现矛盾，或审核者指出的具体异常。不要求逐图逐点先认证，也不把异常提示自动认定为错误。

展示原图、足够局部上下文、目标高亮及作答 ID／人员／点对号；来源拥挤时逐份查看，并可展开该人的完整原环。用户只需判断“是否想标同一墙线／停止转折处”与“当前归类是否可用”，不要求选择参数或认可精确坐标。

将反馈转成可执行分区时：

1. 原上传 JSON 原样保留；后续口头澄清另存，写清覆盖哪条判断。
2. 以 `(作答 id, pair_index)` 绑定实际来源，必要时对照源坐标；A/B/C 是该局部的人工目标分类，不泛化为全库标签。
3. 对触及的旧算法组，明确所有成员最终归属。只确认其中几份同角，不能顺带搬移未经判断的整组成员。
4. `apply_partition` 要求新分区完整覆盖所触及成员且不重叠；同人多个节点不能合成多票。部分覆盖或同人多节点问题保留待定。
5. 重建组后重新计票、融合中心、映射各人原环和候选连接；保留 `automatic`，另写 `assisted` 与采用依据。

“包含不同墙线”只有“不全属同一组”的含义；若没有具体分区，不将其展开为所有人两两不同。模棱两可的反馈允许保持不确定，不因收尾要求强行定类。

已采用的事例包括 rPc 的 A梳妆台／B玻璃外侧／C玻璃与墙相交处区分，以及 yq-25 遮挡角的同角合并。rPc 某一已审子集没有 C，不代表整张图没有该目标。最新完整人员清单以 `user_followup.json` 为准，不从报告文字反向猜来源。

## 5. 人工顺序审核与回收

### 5.1 发放工作台

复用[融合排序工作台](../../analysis_results/consensus_delivery_20261008/order_workbench/index.html)。可直接在浏览器打开本地 HTML；不依赖 8768 端口。相对资源路径依赖当前仓库目录，不要仅复制单个 HTML 后期待原图自动跟随。

该工作台冻结当前节点坐标、配对、支持数和 `feature_id`，人只能调整完整点对顺序。队列优先包含历史实际改序图、来源环分歧等；队列是复核范围，不是错误清单。N=2 不入队，已有明确融合顺序不重复询问。

人工操作：选图 → 看全景／几何预览 → 拖动点对卡片或输入完整排列 → 确认 → 导出 `融合共识排序审核_20261008.json`。若发现缺节点或身份归属问题，记录问题，不能靠删点或改坐标把排序凑成合法结果。完成勾选、文字意见和节点问题分别读取，不能把未勾选但有具体内容的反馈丢弃。

**发出后不重建覆盖正在审核的工作台。** `sources.json` 是本次冻结源绑定；若融合组或中心随后改变，回收旧顺序时要单独检查，不直接宣称新结果已确认。

### 5.2 导入原则

排序回收入口为 `tools/thesis_main/analysis/consensus_order_import_20261008.py`，以 `prepare_orders(document, sources, outputs)` 比较上传记录、冻结来源和当前交付，分别返回可采用与待处理项。

- 核对图片、源绑定、点对及其坐标，以及排序是否把全部冻结节点恰好列一次。
- 没有确认或明确报告节点问题的条目不强制采用；保留备注并进入待办。
- 冻结节点与当前结果未变时，把界面点对号转为当前 `feature_id`，只改变排列。
- 身份或中心改变时，旧顺序不直接移植；展示更新结果后复核。
- 采用记录写入 `user_followup.json` 的明确顺序及来源信息，导入结果写入 `order_import.json`，再运行交付批处理。
- 若用户后续已解释并接受不完整共识，以`identity_review_resolution`记录处理结论，归入`resolved_by_followup`；不得因此添加人工顺序确认或补点。

本轮35条反馈中，33条排序采用，rPc后续指定x递增，Uw两处同角合并后仍3点，按用户讨论保留该不完整结果。当前没有等待回复的条目；这不等于35图全部身份及几何被认证。最新计数读`order_import.json`及交付报告。

## 8. 例外、验收与下一步

当前已知例外分别保留：

- rPc-22：单份坐标不满足入口要求，整池失败。须沿源证据处理输入，不能直接删人。
- uNb-36：节点和人工顺序可保留，但上端位置不满足常规地面／顶面反投影条件；不得为让 3D 检查通过而移动融合坐标。
- 两人池：暂停排序，不把 MV50 留下的单人节点解释为多数人达成一致。
- pa4-10、q9-23、uNb-86 等模糊目标，以及 wc2-53 同人多节点／不确定目标：保留具体未决意见，不把局部关系检查通过解释为整图已解决。
- 排序回收中新报告的缺节点或中心版本变化：回到相应来源／身份／位置步骤处理，不当成一般排序错误。

本轮两项定向材料在[本地收尾页](../../analysis_results/consensus_delivery_20261008/closeout/review.html)。Uw-09有多个未达票组，P023同时画出其中几处；不能为达到四对而把不同节点的支持相加。逐点多数即使能形成几何，也不保证保留足够的节点来表达完整合理布局。该情况应显式留为输出限制或进一步方法研究，不能靠高IoU或人为补点掩盖。

一份融合交付达到当前流程验收，要求：输入池与源索引明确；自动与人工辅助分开；票数和坐标符合声明规则；连接与几何状态不隐瞒；人工采用有具体来源；未决项仍能查到；报告和当前输出一致。它不要求所有困难图自动完美，也不以高 IoU 或四对角点作为验收条件。

如果当前待办只剩少数不确定例外，可以交付“可用结果＋例外账本”，不能写成全库完美结束。之后是否扩大自动有效性评估，由研究问题决定：需要“绝大部分自动成功”的数字时，应抽查普通整图，分别报告身份误合／拆散、完整输出、人工介入量和适用分母；已反复开发的局部案例、几何可算比例与人审修复后比例都不能代替自动正确率。

本阶段全员流程已收尾。后续人员×图片×人数研究基于当前墙线融合继续；三条历史原型不是遗留必做任务，只有具体问题需要时才作为可选对照。

### Uw不足四对的处理补充

已接用户G002+G008、G003+G009同墙线判断，各合为3/24，不改变12票门槛或三个达票节点。当前`incomplete_consensus_observed`表示反馈已解释，但未形成完整可用布局。几何可算不解除这个状态，也不再要求用户重复回复原缺点问题。

先修正有依据的对应，再如实保留未达票，不自动补成四对。四对是本流程中的完整性复核线索，不是所有非Manhattan空间的普适正确性条件。用户进一步明确：未形成4对可以是其“未收敛”概念的一种表现，但不是唯一表现。操作上记录“当前人员池与规则下未形成完整共识”，并保留已知对应限制；不据单个终点推断人数过程或无限新增人员的结果，也不据此自动改写人工难度标签。

流程可以完成并交付这个结果；该图尚无完整多数布局，不代表必须继续补到完整才允许收尾。完整来源环约束融合降为可选方法探索，当前不启动、不覆盖MV50；如以后采用，低于半数的节点必须明示。人数轨迹和全员结果解释统一见研究模型第3.3节。
