# 新增合法空间：分类结果比较

本目录比较既存的原 v2.1 分类与同算法的扩展范围分类。读取上级 `joint_history_classification/ALL_METHOD_LABELS_LOBO.csv.gz` 和 `fusion_role_classification/LABELS_ALL_LOBO.csv.gz`；原版读取 `research/data/releases/v2.1/` 的同名目录。分类由其它流程生成；这里不拟合模型、重评分、融合或重新选队。DSTRUCT 及 V3 行为特征保持既有身份，新增空间未分级，不假定它已纳入 DSTRUCT。

待两个扩展分类的最终文件均已产生后，运行：

```text
python -m tools.thesis_main.analysis.compare_admitted_space_classifications_20261029
python -m pytest tests/test_compare_admitted_space_classifications_20261029.py -q
```

脚本先检查两版方法、条件、楼外折和标签层级的完整身份网格；发现字段、方法网格、重复键或已知标签缺失时停止，不能静默忽略。人员范围允许变化，并分别统计新增和丧失支持。V3 同时比较粗类与细类，RFUSE 比较 `class_id`。`ALL` 是全体描述折；各建筑折是排除该建筑的训练结果，不能以全体折类别代替目标建筑的楼外类。

## 文件与口径

- `FOLD_COMPARISON.csv`：方法×条件×楼外折×层级，列出两版可用人员、共同可用、新增和丧失支持；列出原编号直接相同／变化、最优编号对齐后相同／变化、ARI，以及新版编号到原版编号的对齐映射。ARI 只在至少两位共同已知人员时计算，否则留空。
- `PERSON_FOLD_COMPARISON.csv.gz`：保留所有人员各折的原版、新版、映射后类别与支持状态。`ALL_PERSON_COMPARISON.csv` 是全体描述折对应表。新增或丧失可用标签的人不被当作“换类”；两版均已知但对齐后不一致的人才计入映射意义下的变化。
- `*_old_sum_paired`、`*_extended_sum_paired` 和 `*_delta_sum_paired` 只对同一人员、两版均有该支持字段的记录求和，并标明配对人数；它们是人员支持计数之和，**不是去重后的图片或建筑总数**。逐人原支持和新支持保留在人员表中。
- 最优对齐只是在同一折共同人员上最大化编号对应，用于区分编号重排与分区改变；它不证明两版类别具有相同语义。若有多个同样最优的对应，`mapping_ambiguous=true`，人员“变化”依赖选中的最优映射，应结合交叉表与类中心解释。不同 K 的拆分和合并不能靠编号一一对应完全解释；ARI 同样不能替代类别角色分析。

## 下游实验身份

原版分类产生的固定团队、原模型、原人员进入策略、原楼外换类结果与其原训练范围绑定，保留原身份和实际分母；有扩展分类并不自动把它们升级成扩展范围验证。

如果要宣称某个换类或选队实验采用扩展范围分类，须在该实验的目标建筑折核对实际人员新旧标签及角色；相关类别划分、人员支持或角色发生变化时，按既定设计重新登记可行成员、背景和团队，并单列新旧结果。即便标签对齐后未变化，新增空间的团队与曲线也仍需其独立结果，不应由旧团队推断。依赖旧 Q/T 历史或 RFUSE 训练结果的策略应核对扩展版本的输入和预测；单纯展示原标签固定队重评分继续保持原标签身份。

本目录比较完成不等于扩展范围已重新完成全部下游实验，也不意味着全部新增空间已有正式难度。具体模型支持和映射请以生成后的表为准。

## 本次结果摘要

两版共有 276 个方法×条件×折×层级单元。`ALL` 折的 V3 行为类（Manual 和 Semi、粗细层）对齐后一致；Manual V3 联合粗类原编号有29人变化，对齐后是2/57人变化，ARI 0.899，说明不能把编号重排当成29人换类。Semi V3 联合细类对齐后14/54人变化，ARI 0.699；粗类一致。具体标签的可用支持分别见表。

RFUSE 几何 K2 的 Manual `ALL` 折 59 人对齐后一致，K3 有2/59人变化；含质量的 GEOMQ K2 和 K3 分别有3/59、26/59人变化，ARI 分别约0.657、0.185。各楼外折不等同 `ALL`：例如 GEOM K3 部分折变化更多，必须按目标建筑折检查。V3 联合 Manual 的两个粗类折及对应两个细类折有最优映射歧义；这些折逐人变化需结合类别中心解释。

上述是两次已存拟合的内部比较，不意味着新分类已通过外部验证，也不自动改变已有团队或策略。下游使用扩展标签时应按其实际折与方法检查，而不是套用 `ALL` 分区。
