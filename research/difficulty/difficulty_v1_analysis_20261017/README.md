本包使用数据v1的3222份作答、261图和27个源人员身份，按[共同评分v2](../../quality/quality_b8l2_d10_20261017/CROSS_MODULE_INPUTS.json)读取B8L2与D10。评分包名中的`v2`是分析修订，不是未来补标的数据v2。当前261图沿用人工粗类；两张新图为中等（“偏简单”仅备注），b8cTxDM8gDG-04仍暂停。质量记录要求评分参考与该图的难度目标完全相同；1911份当前可用记录均通过检查。质量用途为1699普通、188门洞、24其它；OOS分数只作诊断。

## 已观察到什么

Manual普通难度的两种权重方向一致：

|粗类|可用作答／图|B8L2作答等权|B8L2图等权|D10作答等权|B8L2标准差／第10百分位|有质量且来源用时|
|---|---:|---:|---:|---:|---:|---:|
|简单|846／66|74.20|73.11|75.77|17.26／48.15|451份；中位100秒|
|中等|134／17|62.50|62.63|64.32|19.01／39.09|92份；中位122秒|
|困难|278／20|49.24|50.35|50.96|22.19／16.35|221份；中位181秒|

按图等权后趋势仍在；困难组的低尾更低、分散更大。它是人工粗类与现有作答结果的**相容性描述**。部分人工标签曾参考作答；不能以这个梯度证明分组独立有效，也不能把不同图片间的均值差当成难度的因果效应。

固定人员身份后，24名Manual人员同时有简单与困难图质量记录，全部各档至少3份。逐人先算两档均分，再比较：困难−简单的B8L2中位差为−25.76分，23人下降，1人上升。W002是反例：简单31份、困难11份，差为+8.72分。D10在同一人员、同一作答与参考上给出相近方向（24人中同样23下降、1上升）；这只是改变方向尺度的敏感性。两档仍是不同图集，且人员在图上的分布不同；逐人配对控制了人员名单，未控制具体图、建筑和标签制定时看过作答的问题。

来源任务用时仅在质量可用且有效来源时间的记录中比较：简单451份中位100秒，困难221份中位181秒。23名人员两档都有来源用时，逐人均值的困难−简单中位差+88.96秒。新增任务时间属于任务人员总时间，未拆给某个空间目标；同目标审计时间单列，普通Manual三个难度档分别只有305／45／68份，不能代替来源时间。缺失用时不填0，不用lead time替换。

门洞与OOS按两轴交叉，而非互斥场景。Manual门洞且非OOS有223份库存、188份质量可用，B8L2均值37.68；非门洞且非OOS有2021份库存、1258份质量可用，均值67.44。24名人员在两层都有质量，逐人门洞−非门洞的B8L2中位差−24.36分。门洞的图片组成与目标表示有自身差异，这一数值不能单独归因于“门洞必然难标”。门洞×OOS的23份Manual作答全部留在库存，质量用途为0；OOS仍可有数值诊断。`doorway_status`原样列出`annotatable`、`difficult`、`suspected_user_review`等记录，未把“难标”改写成“不可标”；未知状态继续未知。

Semi的困难层只有1图4份作答，现阶段不足以比较总体难度规律。Semi中等层4图15份，作答等权B8L2为84.88，高于简单层24图422份的79.28；12名同时出现于简单／中等层的人员在中等层各自支持很少（没有一人两档各≥3份）。这是粗类均值不必严格单调的现成例子，不按分数反向修改人工标签。

## 分母、低尾与缺失

全库存的计算状态为2774份完整可计算、298份仅底面、122份输入不可算、28份待目标，四者相加为3222。完整算出但不能用于质量评价的记录仍单列；GT错误、图级暂停、人数不足、参考不足、OOS和目标用途限制的原因可重叠，不把原因计数相加当作作答总数。122份`input_uncomputable`都记录`final_paired_points_missing`；另有7份同原因目前属于`pending_target`，因此“上下点缺失”原因总数与不可算状态数不是同一个量。

Manual普通三档输入不可算率以**各档全部库存**为分母，简单34/1245=2.73%，中等5/284=1.76%，困难9/471=1.91%，没有随人工粗类单调上升。仅底面分别为136、43、102份；这些记录不能拿底面诊断冒充完整B8L2。低尾用评分第10百分位，仅当组内至少5份质量作答才给值；每人每档样本不足5份时保留缺失，不宣称人员低尾已稳定估计。逐组人数、图数、建筑数、计算状态、时间覆盖及分位数见底表。

固定104个普通Manual池、104张图，全部有4条真实随机人员路径的k=3、4、6节点；面板身份锁定在[fusion_panel.json](fusion_panel.json)，再次运行本脚本不会因为过程包新增池而静默扩面板。结构为69简单、16中等、19困难。以下每个数先在池内汇总，再让池等权；完整率以该组4×池数个实际路径节点为分母，缺失参考分不填0。

|难度／图数|k|原答R均值|同k换组V均值|完整几何／路径|可评价质量／路径|B8L2池均值／有值池|

R是**当前k名人员原答之间**的归一化底面对称差，V是**同一池、同k不同成员路径的融合结果**的平均`1−IoU`；两者与参考B8L2是三种不同量。固定面板中，困难组R和V均值较高；V随k增大在三组都降低。但困难组完整几何率从74/76降到67/76，可评价质量节点从50/76降到39/76，说明不能只看成功节点均分讲“随人数稳定趋近GT”。R在这三个k上没有共同单调下降的规律；增加人数不会让已经提交的原答自动变一致。

同池k=3→6都有参考分的图中，简单49图、中等7图、困难12图的B8L2差值中位分别为+2.56、+3.14、+3.24分，但简单10图、困难4图反而下降。困难图`uNb9QFRL6hY-60`在同池路径均分下降18.50分，是反例。B8L2只在质量适用且完整可算时出现；各组有值池的构成仍可能随k改变。4条随机路径共享人员和图片，只表示有限池内的过程，不是独立图样本或统计显著性证据。
