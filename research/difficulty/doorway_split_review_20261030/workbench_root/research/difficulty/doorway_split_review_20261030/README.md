## 坐标与数据约定

- 原图：ERP 等距柱状全景，**1024×512** 坐标系；`data.js` 里的 `points` 就是该坐标。
  页面 canvas 按 1.5 倍显示为 1536×768。
- 俯视：BEV 米制 `(x, z)`；相机在原点、朝 `-z`；`floor` 为原参考底面多边形。
- 停止边（`cuts`）：BEV 直线 `[[x,z],[x,z]]` + `side`。法向 `n = normalize(-dz, dx)`；
  保留侧为 `side * cross(A, B, p) >= 0`。`side=+1` 保留法向正侧，`side=-1` 保留负侧。
  两条停止边分别对应空间1/空间2 的停止边，中间留门框厚度区。
- 相机通常正好落在门洞中，因此可能“在停止边上”（状态栏会这样显示，而不是误报在/不在保留侧）。

首图（`2t7WUuJeko7-07`）预切：空间1 `水平线 z = 0.021，保留 z ≤ 0.021`；
空间2 `水平线 z = 0.088，保留 z ≥ 0.088`；门框厚度区 0.067 m。

## 界面与操作

1. **俯视图（左）**
   - 彩色实线＝当前空间的停止边；虚线＝另一空间的停止边；方块＝拖动柄。
   - 拖动方块：沿法向平移该停止边。
   - 在俯视图空白处点两点：为“当前空间”重新定位停止边；勾选“水平／垂直切分”时
     自动吸附到水平或垂直，取消勾选则允许斜线。
   - 点击某条停止边可切换当前空间。
   - 紫色＝原参考底面；黑点＝拍摄点位（相机），带朝向短线。
2. **原图（下）**
   - 粗实线＝停止边；细线＝裁后底面轮廓（按各自保留侧裁剪后的底面边）。
   - `全景水平旋转`：左右旋转全景，方便把门洞转到画面中央。
   - 勾选“在原图地面点两点调整当前空间停止边”后，在原图地面（地平线以下）点两点，
     即可按地面反投影重新定位当前空间的停止边。
3. **切分状态栏**：显示每个空间的停止边方程、保留侧、相机是否在保留侧、门框厚度区。
4. **图级备注**：`图级备注` 输入框，输入即保存。
5. **标注逐份核查**：`#answers` 选择该图的工人标注（35–38 份）；下方 `#viewer` 用
   geometry-view 组件显示 原图叠线 / BEV / 3D；`可用 / 需修正 / 无法判断` 为判定，
   进度显示“已审 x/20 图 · 本图标注 i/N · 已判定 k/N”。
   改了该图切分后，旧判定会提示“边界已改，旧判定需重看”。
6. **按钮**
   - `翻转保留侧`：当前空间保留侧取反。
   - `恢复本图预切`：恢复 `data.js` 的原始 `cuts`。
   - `撤销切分`：按历史退回上一步（最多 50 步）。
   - `恢复待切分`：两条停止边清空（该图回到“待切分”状态，再分别点两点定义）。
   - `标记本图已审`：手动计入 / 取消“已审”。

所有改动 **选择即保存** 到浏览器 `localStorage`（键：`doorwaySplitReview.v2`），
刷新不丢；`导出审核` 下载 JSON，`导入审核` 可回灌。

## 快速判定卡（审核时怎么选）

**每图固定流程**：① 看俯视图预切 → ② 必要时调停止边 → ③ 逐份看标注给判定 → ④ 写备注（可选）→ ⑤「标记本图已审」→ 下一图。最后点「导出审核」。

### A. 停止边怎么定（左上「修改」「水平／垂直切分」「翻转保留侧」…）

| 你在原图/俯视图看到 | 怎么选 |
|---|---|
| 两条预切线正好贴着门框两侧墙脚，保留区互补 | 不动，直接标记已审 |
| 线偏了几厘米到几十厘米 | 拖俯视图方块；更准的办法：勾选「在原图地面点两点…」，在**墙脚与地面交界**上点两点（地面、地平线以下、近处） |
| 门洞在 BEV 里是斜的 | 取消勾选「水平／垂直切分」后再点两点，允许斜线 |
| 状态栏出现「⚠ 两空间保留区重叠」 | 无效切分：先把两条线调到互补（空间1 与空间2 各占一侧），再顺序检查 |
| 相机明显不在门洞里/图里没有清晰门洞 | 「恢复待切分」并在图级备注写原因 |
| 预切的保留侧明显反了（保留区盖住了另一个空间） | 「翻转保留侧」；注意只改当前空间（先选「修改：空间1/空间2」） |

判定标准：**每条停止边应落在该空间一侧的门框/墙脚线**；两条线之间的空隙就是门框厚度区（预切给的是初始间距，可按原图调整，不必当测量值）。状态栏「相机位于停止边上」对门洞拍摄是正常现象。

### B. 标注怎么判（「可用 / 需修正 / 无法判断」）

| 该份工人标注的情况 | 选 |
|---|---|
| 墙角/底面与该图实际墙面吻合，且能支撑当前空间1/2 切分 | **可用** |
| 有明确错误：漏墙、角点偏移、两个空间被当成一个、门框处多/少一段 | **需修正** |
| 点缺失/坐标不可用（如 `pairing_unavailable`、0 点）、图像太糊无法核对 | **无法判断**（也只能选这个） |

判定以**当前切分**为基准；若之后又改了切分，旧判定会提示「边界已改，旧判定需重看」，需重新确认。逐份进度看「本图标注 i/N · 已判定 k/N」。

### C. 什么时候算“审完”

- 改切分、写备注、加判定、或手动「标记本图已审」都会计入已审；「恢复待切分」不计入（待切分状态下即使手动标记也可强制计入）。
- 全部审完 → 「导出审核」得到 `doorway_split_review_*.json`，交回即可；中途刷新不会丢（localStorage）。

## 导出 JSON 结构

```json
{
  "schema": "doorway_review_result_v2",
  "source_schema": "doorway_review_v2",
  "exported_at": "2026-10-30T01:23:45.000Z",
  "reviewer": "local",
  "counts": { "total": 20, "reviewed": 3, "verdicts": 5 },
  "cases": [
    {
      "image": "2t7WUuJeko7-07",
      "image_id": "2t7WUuJeko7_…",
      "status": "difficult",
      "photo": "../../../data/mp3d_layout/valid/img/….png",
      "reference_id": "gt:…",
      "cuts": [ { "line": [[-100, 0.021], [100, 0.021]], "side": -1 }, { "line": [[-100, 0.088], [100, 0.088]], "side": 1 } ],
      "cut": null,
      "note": "",
      "mark": null,
      "reviewed": false,
      "verdicts": [ { "record_id": "new_95_…", "value": "pass", "cuts_hash": "…", "at": "…" } ],
      "precut": [ … 原预切，便于追溯 … ],
      "proposal_note": "已对照原图预切；…",
      "updated_at": "…"
    }
  ]
}
```

- `cuts` 中 `null` 表示该空间待切分；`cut` 为旧版单切线字段，本页面不使用，保持 `null`。
- `mark` 为手动“已审”标记（`done` / `todo` / `null`），用于导出→导入往返保持人工处置状态。
- 两条停止边都为空（待切分）时不计入“已审”；“恢复待切分”不会增加已审数。
- `side` 语义见上；导入时只校验结构（schema、line 数值、side 必须为 ±1），不校验业务合理性；
  非法记录会被跳过并在提示里给出条数。未知 `image_id` 同样跳过；一条都应用不了时报错。
- 导入不会给未改动的图重写 `updated_at`。
- `verdicts[].value ∈ {pass, fix, unsure}`；`cuts_hash` 用于判断判定是否过期。
