## 当前GT是否用了HoHoNet的遮挡处理版

本次四张图原目标都来自 `data/mp3d_layout/test/label_cor/`。不是 `test_no_occ/label_cor/`，也不是模型预测。

官方HoHoNet数据准备说明明确分两步：先把MatterportLayout原始JSON转换成上下角点TXT，再单独生成`*_no_occ`的遮挡裁剪版本。[官方转换说明](https://github.com/sunset1995/HoHoNet/blob/master/README_prepare_data_mp3d_layout.md)

本轮找到本地 `C:/Users/ASUS/Downloads/label_data.zip`，按官方JSON→TXT公式逐点重建、保留两位小数，与259图的原始基线TXT比较：**259/259完全一致，包括原点序。** [逐图核验记录](provenance_259.json)。这是原始基线核验，不代表当前所有图都采用原始GT；其它图的用户旧修订/替代范围仍分别保留。

所以不应笼统写“完全没经过处理的MP3D原文件”。准确称呼是“**MatterportLayout原始布局JSON的坐标转换版，未使用HoHoNet遮挡裁剪版**”。MatterportLayout是基于Matterport3D图像的布局标注数据集，原始发布格式为JSON；转换格式不等于删掉隐藏角。[原始标注项目](https://github.com/ericsujw/Matterport3DLayoutAnnotation)

原始标注也可能有错误。7y-26的错误角存在于原始JSON的对应位置，来源正确不能证明其几何标注正确。本次按用户裁定独立修订，正是要区分数据集原注与认可参考。
