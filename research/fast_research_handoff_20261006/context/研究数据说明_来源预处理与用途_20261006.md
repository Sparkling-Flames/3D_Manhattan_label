# 研究数据说明：来源、预处理与用途

整理日期：2026-10-06。配套[完整研究交接](线程交接_连线质量与完整共识_20261004.md)。本文解释现有数据，不重定义 schema、资格或研究路线；精确字段以[当前方法合同](PAPER_A_METHOD_CONTRACT_CURRENT.json)及包内字段合同为准。

## 1. 最重要的读取原则

**当前几何和共识研究使用的是已预处理、已接入最终审核状态的数据。** 不直接将 Label Studio 原导出坐标当现行输入，不重复拉齐上下 x，不用某次融合结果替换人员源标注。

正式读取入口：[research_input_20260929/manifest.json](../../analysis_results/research_input_20260929/manifest.json)。日期是包名，不代表后来全部研究都应退回当时旧结果。合同的 data.analysis_bundle 指定这个入口：

```python
from tools.thesis_main.data_prep.consolidate_research_input import load_current_bundle

bundle = load_current_bundle()
data = bundle["data"]          # 人员、GT、坐标及最终审核状态
research = bundle["research"]  # 研究解释与交叉汇总
comments = bundle["comments"]  # 原评论及每次出现的来源
```

这是读取，不是重建。旧 load_current_input() 只返回坐标／状态视图，不包含完整研究表和评论。不要为了查看数据运行合包模块的重建入口；重建会重新生成工件，不是本次整理所需操作。

以下路径均相对于 research_input_20260929/，实际文件由 manifest 登记。

| final_review/summary.json | 最终数量和审核汇总，不能替代逐对象名单。 |
| final_review/received_orders.json | 明确确认的环序及记录；默认顺序不等于人工确认。 |
| final_review/ 内 JSON／CSV | 全量 3152 台账、逐图覆盖、逐对象来源、GT 审计、同房、OOS、门洞、范围／细节和模型影响等专题数据。 |

| research_tables_field_contract.json | 研究解释与交叉表字段定义。 |
| validation.json | 包生成时机器一致性检查结果；不是全部几何／语义正确性的证明。 |

读取函数会重新检查跨表一致性，但不重新做人工审核或证明某个融合方法可用。

## 4. 预处理到底改变了什么

数据链条是：**原导出与已确认删补 → 完整配对 → 上下周期平均 x → 最终环序视图与审核状态 → 当前统一包 → 特定实验名单 → 输出**。

1. 已有审核确认的删点／补点保留 repair_evidence、删除索引和来源。某些补点借用了另一份作答，不能伪装成一份独立完整原答；借用来源单列。
2. 每个对象保留配对前视图 before_preprocessing_points 及点对 links_zero_based。这里的“预处理前”处在该处理链的阶段，不保证等于最初原导出的未清洗字节；原始导出仍单独保留。
3. 对已确定的一对上下点，以 1024 周期计算最短横向差并取中点；两端共享这个 x，**各自 y 不变**。跨接缝不能用普通算术平均把点移到图中央。不是对所有人的角点做融合。
4. preprocessed_points 保持源身份顺序；再根据确认环序或保留的默认顺序生成 points_1024x512。只是另一个有映射的消费视图，不丢掉源点身份。
5. 无法完整配对的对象保留，但预处理／最终环坐标为 null，不悄悄回退原点冒充可计算输入。未审默认环明确标记，近 180° 中间点不自动删除。

这一步没有认证所有墙角语义、拟合完美 Manhattan 房间、消除所有 GT 争议，也没有把不同合理空间强行合并。

### 两套数组及索引不得混用

| 字段 | 含义／配套关系 |
|---|---|
| preprocessed_points | 共享 x 后、保持源身份顺序的点坐标。 |
| links_zero_based | 在 preprocessed_points 中引用的上下点索引。 |
| point_labels | 源身份标签，供回溯。 |
| points_1024x512 | 最终环序视图，按 top、bottom 成对排列，几何消费常用。 |
| matterport_links_zero_based | 对应最终环视图的配对索引，如 [0,1]、[2,3]；不能用于源顺序数组。 |
| ordered_source_point_indices | 最终视图各点到源点索引的映射。 |
| ordered_source_pair_indices | 最终环各点对到源点对索引的映射。 |
| ring_confirmed、order_status、order_record | 有没有确认、当前顺序状态、确认依据；可绘制不等于已确认。 |

例如“处理后点对索引 4”和“源点对索引 4”可能不同；报告人工判断必须说明数组、点对还是端点、零基还是一基。rpc 曾误圈点的修正见[交接的人审记录](线程交接_连线质量与完整共识_20261004.md#9-已有人审判断)。

坐标视图为 1024×512 ERP。原 GT 使用连续坐标 C 已核验；原生 HoHoNet 的像素中心输出需要对应适配，不能重复加半像素。三维及 BEV 的 h=1 是相机高度归一化，h²／h³ 不是未经标定的平方米／立方米。

## 5. 对象、人员、图片和资格

对象用 object_id 连接；原审核常用 canonical_annotation_id，需要保留明确映射。worker_id 是人员，image_id 是图，condition 是采集条件；不要把对象数叫人数。建筑、同房和图像层级也不同，同房不保证同视点／同空间范围。

统一包保留 3,152 份人员记录、259 份原 GT、30 份手工 GT，共 3,441 对象；27 名人员，259 张研究图，加 2 张仅手工 GT 参考图。共有 3,298 个对象具备 ready 坐标，不等于 3,298 张图或合格投票。

合同中的清洗状态统计为：2,923 保留、11 保留待定、85 排除、133 历史未纳入；总计仍为 3,152。记录保留在包中不等于纳入所有分析。

| 状态／字段 | 说明 |
|---|---|
| cleaning_disposition | 承接清洗裁决；历史版本和排除记录留作追溯。 |
| independent_vote_eligible／reasons | 独立投票候选，检查保留状态和借用点等；仍需真人去重。 |
| canonical_unit／person_image_unit | 人员—图—条件及人员—图单位；同一人多版本不自动成为多票。 |
| main_quality_gate | 既有主质量分析资格／原因。 |
| main_consensus_gate | 既有主共识分组／范围政策，不等同于质量资格。 |
| geometry、method_evaluability | 表示和方法适用状态；候选不等于所有方法均可计算。 |
| condition | manual／oos／semi 分开解释；混合面板应报告各自覆盖，不能抹掉模型辅助条件。 |

确认环 1,295 份包括 1,265 份人员环及 30 份手工 GT 环；不是 1,295 份全部正确标注。全局不能声明 all_annotations_individually_confirmed=true。

## 6. GT、评论、难度和模型数据

**GT 是带版本的参考对象。** object_kind 区分 annotation、gt_original、gt_manual_revision，图片 references 指向相应对象。30 份手工 GT 不代表全库原 GT 全被替换。比较时说明用哪个版本；不是因为某结果分数更高就更换参考。原 GT 也不参与人员多数投票。

审核原件在 review_final_20260928/evidence/ 的 user、yizheng、second、previous_return、latest、continuation、coverage 等 JSON。评论含图片级、逐答级、历史和当前裁决，保留作者、来源、出现位置及绑定。不以 view_context.annotation_id 自动认定评语对象，不把“没文字”写成“没审核”。

较新难度汇总入口为 [review_source_audit_20261004/difficulty/summary.json](../../analysis_results/review_source_audit_20261004/difficulty/summary.json)；逐图变化在同目录 image_difficulty_comparison.csv，来源在 source_events.json／source_catalog.json。历史评论补充在 [historical_image_notes.json](../../analysis_results/review_source_audit_20261004/historical_image_notes.json)。这些是恢复的既有证据，未自动重写全部旧实验分层结果。

人工难度、空间／细节审核、GT 问题和模型线索分开。人工三档最新 101 图有明确标签，另 6 待定、152 无明确标签；不能把后者一律归为简单。d_model_feat_static 及 BiLayout 差异的现有覆盖分别为 163/259、153/259；使用前须沿原字段来源核对模型、定义和版本，不能只凭名称认作已验证的难度。

同房数据见统一包的 room_registry 及 final_review/ 同房分类系列；建筑留出和同房比较不是任意按图片文件名前缀猜分组。active_time 数据来自原日志，不由评论或点击次数补造。

## 7. 为什么实验数量不同

| 实验／输入 | 实际含义 |
|---|---|
| 全量 259 图、3,152 人员记录 | 当前包的研究总体，保留排除／历史／不可计算状态，不是全都进入每项实验。 |
| Lee 扩展 137 图尝试、136 图可计算，1,496 票、25 人 | 该研究名单和区域可计算结果，不能与点路线票数直接混用。 |
| 全库点路线 137 图、1,520 份 | 点路线诊断名单；源记录均至少 8 端点，融合仍可能不足四对。 |
| 24 人 × 10 图、8 建筑 | 共同人员画像和真实组合面板，用于控制人员池比较；不是全库随机独立抽样。 |
| 四图 66 份、24 人 | 点路线／外部对应研究小面板；66 份不是 66 名独立人员。 |
| 两图 3 人和 24 人，共 27 份 | 精确全员曲线早期实算；27 份不是 27 名不同人员，不是全库成功率。 |
| 九图 150 份、108 基线状态 | 较新的结构约束交接面板；108 是参数／方法状态，不是新增标注。 |
| 难度旧 45 图、新候选 52 图 | 不同阶段的分析面板／预选名单；新候选不等于新实验已完成。 |
| N≥20：47 候选、44 BEV、33 主质量图 | 按不同可计算／质量口径形成的层级，不得只报最终数而隐藏分母。 |
| 合成控制与 524 条局部替换等 | 检查数学性质或构造行为；不是新的真实受试者或独立房间。 |

实际复用应读取对应实验名单和选择理由，不根据以上数字重新猜一份相同大小的样本。历史八图、40 图等保留当时冻结输入，不能自动声称满足当前全部资格。

## 8. Pro 交接、结果和使用边界

[九图结构交接](../../research/structure_constraints_20261006/README.md)中的 inputs.json 是从当前数据选出的冻结人员输入，images/ 是对应原图；human_review.json 是已有人审判断；baselines.json 是当前算法输出；evaluation/references.json 是评价参考，不能混进人员输入或用来暗中选对应。manifest.json 与 VERIFICATION.json 说明交接范围和已检查内容。

research/structure_paths_20261006/ 中保存的 Pro／dot 包和旧四图研究不是九图新基线的自动验收。analysis_results/structure_paths_review_20261006/ 是本地复核输出。测试数量、字节复现和视觉语义判断各自回答不同问题。

共识多边形、配对表示节点、压缩节点、融合中心和候选跨接均是派生输出，不能记为新人员原标注。逐段来源支持、完整作答支持、点身份支持分别保存和解释。

本说明只整理已有内容，没有重建输入、修改资格、重算实验或新增公开授权。当前材料按用户要求留在本地，由用户自行推送；历史文件中的发布状态只代表其当时记录。
