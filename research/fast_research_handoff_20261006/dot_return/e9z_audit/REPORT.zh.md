# e9z 与困难面板：独立结构证据审计

## 结论先行

用户提出“汇集全体人员的局部结构，再按有依据的对应构造和删改候选”值得继续，尤其适合揭示遗漏观察、分段不一致和错误跨接。但本轮证据不支持把它简化为“距离合格后再要求邻接相似，就能恢复正确布局”。e9z 给出一个可以穷举验证的更强限制：**绑定距离门限固定在 5°或9°时，现有8份右侧观察中，任何4份都不能同时通过 complete-link 门限。只删除兼容边的结构筛选，无论如何换分组搜索，都无法恢复4票右侧身份。**

因此，本例中应把三件事分开：右侧观察是否被保留为身份候选；右下端到底在哪里；候选如何接成范围。现有上端锚定能做第一件事，不因此完成后两件事。用户拒绝错误接缝转折的判断不应被较高参考 IoU 推翻。

## 1. 已独立复现的 e9z 事实

8人均有一对右侧观察，连续坐标 x=1003.911—1008.800。其上端最大球面角距为2.425742599°，下端为29.030599424°。最大角距按1024×512连续坐标公式直接计算。

5°绑定的右侧分区为：

- R03366/p3、R03364/p3：2票
- R03368/p3、R03362/p4、R03363/p4：3票
- R03365/p3、R03361/p4：2票
- R03367/p3：1票

所有 p 为处理后零基索引，源索引保存在机器文件。8人分母要求至少4票；这些分区无一达票。8种7人子集在5°也全部只有3对，门槛仍为4票。这排除了“仅删除某一人就恢复”的解释，但不证明新招募一定无效。

9°新增接缝簇的5票为：R03362/p0、R03361/p0、R03363/p0的3个左侧观察，加 R03366/p3、R03364/p3 的2个右侧观察。其周期中位数 x=1.224880383，bottom_y=322.487670733。这里不是5人都画了最左位置。周期距离正确处理接缝，并不赋予这5个观察相同目标身份。

5°上端锚定把8个右侧观察放在同组，中心为 x=1005.688953639，top_y=223.414840648，bottom_y=334.843835366，输出4对。这只说明上端匹配可以保留此观察群；不能把8票解释为对生成下端位置的8票。

## 2. 门限限制不是单纯贪心分组问题

穷举右侧8份观察的255个非空子集，每组同人唯一，检验组内所有两两距离是否不超过原门限：

|距离定义|5°最大组|9°最大组|12°最大组|
|---|---:|---:|---:|
|绑定 max(top,bottom)|3|3|4|
|下端|3|3|4|
|上端|8|8|8|

5°唯一最大3人组为 R03368/R03362/R03363。9°有3个3人最大组，但仍不存在4人可行组。12°恰有两个4人可行组：

- R03366/R03365/R03361/R03364，直径9.944393732°
- R03368/R03362/R03367/R03363，直径10.434677467°

形成任意4人右侧组的最小 complete-link 直径为9.944393732°。这只是本图诊断值，绝不是推荐门限，也不能认证这些4人组的语义身份。完整分区还受其他左侧观察竞争影响，单个可行组不等于自动分区必然选出它。

**已证明的条件性结论：**固定完整8人池、4票门槛和绑定5°/9°两两硬门限，结构信息若只能删掉旧兼容边，便不可能生成仅由这8个右侧观察构成的多数组。换优化器或扩大原分区内搜索也不能突破这一点。要检验右侧恢复，必须把候选准入改变（如上端候选域）单列为消融，再测结构是否带来独立收益。

“右侧”在本控制中是一个可核查的坐标带，不是新增人工认证身份。

## 3. 独立范围补偿重算

地面半径公式为 r/h = cot(π(y_bottom/512−1/2))，地面方向来自连续经度；结果以相机高度 h 为单位，不是米。

|候选|对数|参考IoU|遗漏 h²|外扩 h²|
|---|---:|---:|---:|---:|
|原12°绑定|5|0.917145510|0.570929922|0.041357196|
|按用户要求仅删左接缝点|4|0.778668262|1.594340953|0.041258564|
|原5°上端锚定|4|0.873725524|0.897574749|0.034747464|

删除只损失面积1.023509662 h²，没有增加任何区域。其中1.023411030 h²，即99.99036%，在固定参考范围内部。外扩几乎不变，遗漏显著增加。这直接展示了范围补偿，而非仅从IoU升降猜测原因。

右侧12°下端 y=356.329216，在此模型下半径1.413816 h；固定参考 y=319.26，半径2.445562 h；5°上锚 y=334.843835，半径1.903223 h。右侧 y 增大代表声明地面点更近。原左接缝额外转折维持了一部分较远面积，所以删除后会缩小范围。这里“更近/更远”和“偏差”均是相对于固定参考的几何描述，不把参考当新的语义裁决。

用户关于5°范围更合理但不完整、9°新增左点不合理、应删12°左点的既有判断完整保留。低IoU不能反证其结构判断错误。

## 4. 图像像素能支持什么，不能支持什么

`e9z_seam_sources.png` 只将原图水平循环移位128个连续像素，展示接缝两侧与原始端点，没有画参考点。

直接视觉观察：

- 原 x≈1005 的上端集中在可见墙顶转折附近
- x≈1.225 新线位于旁侧墙面的延续区域，与可见转折横向分开；这与用户拒绝该位置的判断一致
- 下端散布区域被灯、床和柜遮挡，多数源点落在前景物体覆盖的像素上，因此无法在这张图上直接读出唯一墙脚位置

推论而非新标注：可见上端集中、下端遮挡支持“身份恢复”和“下端定位”分开处理。它不能证明8个下端都针对同一个不可见目标，也不能证明中位数就是墙脚。需要保留位置不确定性或多个位置假设，不能用四对数量、矩形拟合或参考IoU补足缺失的语义证据。

3份记录同时含左、右观察，因此同人唯一约束不会允许各自两点合并；但它仍挡不住“3人的左点+2个别人的右点”混簇。原邻接可揭示这类竞争，却不自动完成语义裁决。

## 5. 新生成结构实验的成员级交叉核验

另项工作生成的 `oct6-nine-structure-study/results_run/e9zR4mvMWw7-15/pair_12.json` 经本文独立查看成员和中心后：

- three-state的4对保留 x≈1.225 的原5人混簇，删除的是 x≈1005.266 的原4人右簇。它不是用户指定删左保右的结果，不能把“四对”当作本例修复
- strict的5对移除了原左混簇，并保留另一组右侧4人（bottom_y≈305.954627），但原 x≈599 的共同8人组被拆成两个4人组，中心 x≈598.512675 与601.518671，产生新的近邻双转折
- 后者是“原同组被拆为两个近邻转折”的可计算事实；本文没有把这两个新点授予新的物理身份或人工标签

完整交叉核验保存于 `e9z_structure_member_crosscheck.json`。这些失败说明“更多结构证据”如果作为硬过滤，也会损坏原有强支持身份。仅报告对数或“去掉一个不合理点”会漏掉副作用。

## 运行与验证

在已安装 numpy/scipy/shapely/matplotlib/Pillow 的环境，保持同级 `oct6-handoff-intake`：

```bash
python oct6-e9z-audit/audit_e9z.py --handoff INPUT --out OUTPUT && python oct6-e9z-audit/clique_gate_audit.py --out OUTPUT && python oct6-e9z-audit/render_audit.py --handoff INPUT --out OUTPUT
```

将 INPUT 换成权威交接包目录，OUTPUT 换成输出目录。上述命令生成主审计、门限穷举及3张e9z关键图；`render_audit.py --include-panel` 可补9图叠加。可选新增问题图及成员交叉核验：`python oct6-e9z-audit/summarize_followups.py --handoff INPUT --out OUTPUT --structure-file STRUCTURE_PAIR_12_JSON`，最后一个参数为另一项结构实验已生成的e9z/pair_12.json；省略时仅生成B6By问题材料，不伪造结构结果。脚本没有写死云端绝对路径。字体缓存受限时可将 MPLCONFIGDIR 指向可写临时目录。实际 Python 3.12.14、numpy1.26.4、scipy1.17.0、shapely2.0.4、matplotlib3.10.8、Pillow12.3.0。尽管与来源Scipy版本不同，六状态成员和中心仍完全一致。绘图有字体缓存不可写警告，输出完整；关键接缝、BEV及五张困难图叠加已实际查看。未运行全仓测试，也没有用GT调整门限或参数。
