## 本地与 Pro 怎样分工

| 工作 | 本地负责 | Pro负责的研究目标 |
|---|---|---|
| 现有人工判断与当前数据 | 对齐历史审核对象与当前记录，核对点、配对和环序变化；缺失与不在面板者保留原因，不能为扩大样本恢复资格 | 判断历史证据对当前问题能支持什么，识别阈值、对应或分组规则的解释缺口 |
| 完整标注共识 | 在原图上检查不同标法、局部两对／三对、上下差异和连接；展示原候选与改序候选 | 深入研究怎样得到有观测依据、能表达上下角点及连接的共识结果，哪些情况应保留多个结果或不确定状态 |
| 稳定性基础 | 复用既有Lee，分别研究同人数换成员、增加一人的融合变化；先小规模核验，再扩展高人数固定面板 | 说明所提出完整共识结果能否支撑后续人数、人员子类与组合比较，指出哪些结论依赖尚未解决的方法问题 |

Pro不需要等待本地先判定全部视觉正确性；本地也不等待完整点融合成为通用算法才继续已有Lee下的人数研究。双方避免同时改写现有基线；新输出另存，回收后由本地核对再决定是否纳入。

## 本地接下来三步

1. **先补当前开发面板。** 复用历史人工审核，不只用按结果挑选的四个demo。逐条核对历史ID到当前ID、坐标、点对及环序；旧“相近／不同”的判断能否沿用，和旧数值能否沿用分别记录。对齐后先固定当前输入，再比较阈值与对应，不把旧人员口径带回当前研究。
2. **再做可解释的小规模对照。** 在同一当前人员集合上查看原点、融合点和连接来源；核对不同阈值下变化的是定位、结构还是分组。新候选几何合法仅是检查之一；异常提示不自动改序，人工介入版本单列。原图视觉判断留在本地，Pro无原图时只做可获得证据范围内的研究。
3. **同时补既有Lee的稳定性。** 区分同k换成员与嵌套集合增一人，固定图片集合和抽样对象，为选择的量单独核查计算精度。既有参考IoU均值的误差保证不自动覆盖新的稳定性量。全员端点、成员池重叠、奇偶和平票随结果解释，不先规定“足够人数”。

Q／T／S／B先同步核对来源与覆盖，后续先单项子类、再有限组合；标签是否稳定、子类标注是否稳定分别检验。不在这一轮同时加入人员权重、完整3D总分、精细难度和新同房预测模型。

## 共同汇合点及后续顺序

第一轮汇合交付是一个**可以解释成功与失败的小规模方法比较**：同一当前输入和成员集合，展示完整输出、不同标法、阈值及环序的影响；分别报告范围差距、上下信息、成员变化与方法覆盖。没有上边输出的方法不编造顶部结果；多个候选不凭目标GT选最好一个。

若结果支持推进，再固定一个可复算的工作版本，并保留关键敏感性对照，逐步扩到既有难度／高人数面板。之后依次研究人员子类内部人数过程、固定人数的真实构成、同构成更换具体成员，最后联系粗难度与同房。若完整点方法仍局限于部分结构，报告适用域，已有Lee研究继续推进。

## 给 Chat Pro 的提示词

请从仓库 `research/full_layout_consensus_handoff_20261003/README.md` 开始，独立推进完整全景布局标注共识的深度研究，而不只是复述或审核现有方案。

我们的目标是：从存在点数、上下点位、空间范围和连接差异的多人标注中，得到有观测依据、可解释、能回到上下角点及连接的共识结果；判断什么时候适合给出一个结果，什么时候需要保留不同标法或不确定状态。研究结果最终要服务于图片难度、人数增加、人员子类及真实人员组合的比较。

请重点弄清现有分组阈值、点对应与连接顺序在多大程度上影响结果，历史人工判断能支持哪些选择，以及怎样区分真正的质量改善、成员波动降低和方法自身造成的表面稳定。现有算法、报告和我们的预想都可以被质疑，不要求得到某种显著结果，也不预设优胜方法。

你可以自由选择研究方法，尽可能利用现有数据开展数值研究或有针对性的反例分析，给出可复算的新证据、能支持的结论、仍不能回答的问题，以及最值得本地继续实测的目标。若提出可运行原型，请一并返回实现与适用范围。

本地正并行做历史案例与当前输入对齐、原图及候选环序检查、既有Lee稳定性基础分析。你没有原图，不需要替本地作视觉GT裁决；请明确需要本地补充观察的事项。已有预处理、人工确认和人员独立性按交接说明理解，缺失与失败如实保留；不要借目标GT或尚未加入的人员替当前结果选优。请用中文交回研究结论及证据。
