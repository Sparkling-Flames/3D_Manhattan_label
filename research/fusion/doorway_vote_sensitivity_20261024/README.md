## 六个正式失败如何变化

正式门槛 6/17 不完整：`7y3sRwLe3Va-06`、`B6ByNegPMKs-42`、`B6ByNegPMKs-43`、`S9hNv5qa7GM-08`、`b8cTxDM8gDG-08`、`jh4fc5c5qoQ-09`。下调一票，其中 `B6ByNegPMKs-43`、`S9hNv5qa7GM-08`、`jh4fc5c5qoQ-09` 分别得4、4、5节点并可评分，但 B8L2 仅 **14.678、13.179、31.718**（底面 IoU 0.428、0.466、0.555）。这是“节点救回而参考质量仍低”的直接证据，不能称方案成功或语义正确。

另三图下调仍失败：`7y3sRwLe3Va-06`、`B6ByNegPMKs-42`、`b8cTxDM8gDG-08` 均只有3节点。7y-06 全员 N32，正式16票、下调15票；14个身份组中入选仍是支持19/25/26的3组，**11组未选**。本轮原生重放将支持19/25/26分别绑定到 `node_001/003/004`，另五组为13或14票，故只降一票无法救回第四节点。旧 `selected_node_supports` 列表本身没有 `node_id` 绑定；这里的绑定来自本轮重新执行身份分组，不能按旧数组顺序配点。该图三臂 Q/D10/3D代理均缺失，不记0分。

## 机制判读与不能越过的界线

同一池内原答有无某个**语义必要角点**，仅凭点对坐标不能自动裁定；不能把票数低叫“人没画”。身份组可能把同一物理角拆开，本账可定位低支持组及成员，但没有逐组原图语义裁定时只称候选机制。已确定的是具体组的票数淘汰、节点数、来源环是否能连接，以及完整输出相对当前冻结参考的分项质量。正式 `b8cTxDM8gDG-08` 仅2节点且无连接；下调一票成3节点、有来源环，但仍不完整。`B6ByNegPMKs-43` 和 `jh4fc5c5qoQ-09` 上调后仅2节点且无连接。其余失败主要为节点不足，不能混写成连接故障或低Q。无人工原图确认时，输出与参考偏离也只称**相对参考**。

重放入口：`tools/thesis_main/analysis/doorway_vote_threshold_sensitivity_20261024.py`。来源为 `personnel_population_curves_v2_20261023/inputs/INPUT_SNAPSHOT.json.gz`、冻结评分模型与正式全员状态表。全部17图先比对正式臂才写敏感性；本实验只覆盖满员门洞和相邻一票，不代表普通困难整条人数曲线或其它融合方法。OOS 不参与。

字段合同：`ALL_17_THRESHOLD_ARMS` 一行=精确满员池×三条实际整数门槛臂；`complete_evaluable=false` 时完整Q/D10/3D代理保持空，节点与连接诊断仍可读。`ALL_17_IDENTITY_GROUPS` 一行=该满员池中一组冻结对应身份，`group_id` 只在池内稳定，`workers` 是该组实际投票人员，三列 `selected_*` 表示相应门槛是否入选。`ALL_17_PAIRED` 一行=池，Q差仅在正式及比较臂都可评分时定义；失败救回须读取两臂 `complete_evaluable`，不能将缺失Q相减。

## 普通 Manual zs-16：已知 n20→21 相邻门槛路径

另对既有严格 ABC 案例 `zsNo4HB9uLZ-16` 的 B/C 四个保存团队各固定成员、身份组、点位与环序，仅将整数门槛设为10或11并重接、重评。结果独立存于 [`ZS16_20_21_FIXED_TEAM_THRESHOLD.csv`](ZS16_20_21_FIXED_TEAM_THRESHOLD.csv)，不并入上方17个门洞满员池。n20 正式10票：B六节点 Q **91.959**、C六节点 Q **82.864**，净 C−B **−9.095**。n21 正式11票：B的10票组失选，六→五节点，B Q **45.844**；C仍六节点 Q **81.544**，净 C−B **+35.700**。把同一个 n21 B 团队单独改回10票，六节点 Q **92.467**；C同门槛两臂均六节点 Q **81.544**，净 C−B 变为 **−10.923**。反向固定 n20 B 改用11票，也从六→五节点、Q **45.394**；n20 C不变。这是门槛足以令同一团队原正式入选的10票组退出、使Q方向翻转的精确重放；本轮未重新裁决该组的语义必要性。实际 n20→21 还增加 W125、改变中位位置，不能把两个人数下全部分差直接归给门槛。

zs-16 来源为 `personnel_effective_exchange_conditions_20261022/mechanisms/positive_cases/cases/E20261022_zs16_n20_m6.json` 及 n21 同类案例；重放入口仍为本目录前述脚本。两组正式臂的节点、完整性和 B8L2 均与存档逐团队一致。`ZS16_20_21_FIXED_TEAM_THRESHOLD` 一行=旧案例人数×B/C团队×实际整数门槛；`official` 标明原门槛。跨 n 的成员和定位不同，纯门槛比较只限同一 n、同一 arm 的两行。此例不代表普通困难整条人数曲线。
