## 主要发现

**当前墙线融合没有在本面板上普遍优于不看 GT 的完整原答 medoid。** 普通 Manual 的 4 人团队均值较好，16 人团队均值较差；人数、场景和失败需要并列解释。Lee 的输出职责是底面区域，完整顶部指标不适用，不能把它记为完整输出失败。

48 个声明池来自 45 张图、19 栋建筑，固定 138 支实际团队。当前墙线产生 130/138 份完整可评输出、131/138 份有效底面；其余为 7 次缺连接和 1 次不足四对。medoid 为 138/138 份完整输出，Lee 为 138/138 份非空有效底面。medoid 在本面板没有剔除不合法候选；接口和排除表仍保留无可用代表的状态。对有连接的 131 个墙线底面未发现自交，缺连接的 7 队不能因此记作“已确认无自交”。

## 面板如何固定

源为 `research/workers/personnel_population_curves_v2_20261023/` 的 `ACTUAL_POOLS.csv`、`INPUT_SNAPSHOT.json.gz`、`REQUESTS_INITIAL.json.gz`、`ENDPOINT_SCALARS.csv.gz` 和 `ENDPOINT_GEOMETRY.json.gz`。池选择只读场景、难度、建筑和容量：普通 Manual 简单/中等/困难各8池；普通 Semi 简单8、中等4、困难1池；门洞8池；原来源的 special 条件3池单列。每层先分建筑轮转，再按固定池 ID 的确定性顺序取样。使用原有 `uniform_prefix/draw0` 路径的 n=4、8、16，人数不足时不补造团队，最终48池/138队。**没有按任何方法的输赢、成功状态或 Q 选择图片或成员。** `POOL_REGISTRATION.csv`、`TEAM_REGISTRATION.csv` 和 `DESIGN.json` 保存先登记的规则与精确身份；后续仅补齐原对象 ID 字段，没有改选队。

门洞源难度为“单列”，其 scene 仍区分 `doorway_difficult`/`doorway_annotatable`。普通/门洞/special、Manual/Semi 均分层保存。此来源快照不含 OOS，故本包没有 OOS 正式 Q 结论。special 只有3池、9队，数值保留但不混入普通层。普通 Manual24池/14楼，普通Semi13池/10楼，门洞8池/8楼。

## 方法与合法输入

- **墙线自动：** `consensus_delivery_20261008.fuse`，gap7.5、全团队 MV50、周期匹配、身份组中位位置及来源建议环，直接复用 v2 精确团队键保存端点。本包新增墙线融合运行数为0。人工对应或排序的结果不进入自动性能表。
- **完整原答 medoid：** 仅在该实际团队内，从原已处理点对和声明环中保留完整且几何有效的原答，最小化与其它合法原答之间的平均 `1−BEV IoU`；没有目标 GT、Q、人员类型或最好人入口。距离四舍五入到12位后并列按原对象 ID 排序。输出是选中人的完整原答，不平均顶界。若没有合法代表则保留失败，不临时选高 Q 或修点。本面板138份代表重测 B8L2 与来源数值的最大差小于1e-7。
- **Lee 底面：** 复用 `lee_tile_stage1_20261002.tile_consensus`，每人每块至多一票，保留 `2×support≥N` 的 tile，允许区域并集，不删小片、不补顶部。遇到某成员不可用底面则保留该团队的基线失败，不偷偷删人改变 N。

原早期三人2t7的点法对照仍见[历史方法比较](../../fast_research_return_20261006/README.md)。其输入和表示支持不能直接推广到本次 v2 多场景团队，因此没有另加一个明显弱的完整融合或以旧单例冒充全新基线。
