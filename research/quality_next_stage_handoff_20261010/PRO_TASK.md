# Pro独立研究任务 质量定义与可靠性验证

请先读 [README](README.md)、[已定要求与开放问题](DECISIONS_AND_OPEN_QUESTIONS.md)、[GT排除登记](GT_REFERENCE_EXCLUSIONS.md)，并恢复 [最新35图范围包](../quality_scope_review_complete_20261010/README.md)。你的任务是独立研究，不是替既有Q、分阶段惩罚或任何已讨论想法找支持证据。可以否定候选或给出更好的简单方法。

## 研究目标

我们需要一个简单、可解释、对相同几何与任务规则一致的质量评价，首先用于标注者不确定性研究，并结合数据与图片条件分析差异来源。以GT减少评价噪声，不能据此宣称已完成两类不确定性的因果分解，也不为本轮扩建数据噪声分解模型。本轮不开发融合共识算法，不建立复杂新模型，不拟合每条主观偏好，也不要求困难图均分必然低。

请回答：现行v1.1是否足够；若不足，怎样以尽量小的变化提高实际可靠性？哪些场景仍无法获得可信单分，粗质量档次和细粒度排序分别能信任到什么程度？

## 第二步 先研究目标协议

新确认地面仍floor-only、top_pending。先核允许目标及完整参考的最低需求，再谈完整Q。地面扩大/缩小/混合增删分别报告；不能把修改都叫裁小。

可比较的候选包括：

1. 经人工核准的固定允许目标集合，依据BEV/覆盖/边界几何自动归属；含混者列最小人工队列。
2. 事前固定允许集合上的maxQ协议，作为研究对照；报告选择与覆盖，检验是否掩盖遗漏。不能把最高分当历史意图。
3. 你提出的更简单、证据更好的协议。

逐份保留候选目标ID、所选目标或含混状态、各候选匹配量及分数，不能只留下最高Q而丢失目标选择差异；这些标签是几何归属，不是真实历史意图。

有效原GT与新目标是候选来源，不代表所有原GT自动合法。新地面批准只适用于已确认空间，不构成新顶界或完整GT正确性证明。顶界无法可靠构造者可以先保留BEV诊断；如运行条件顶界实验，须明示构造、局限、敏感性与未获人工确认，不生成貌似正式的完整分数。

旧三图18份双参考同选16T/2G只能作为条件实例；旧三图地面后续微调，需绑定版本。请用最新可验证案例检查归属冲突、重叠目标、严重错画及选择简单小目标的反例。

## 第三步 做四类公平对照

在每个固定输入/GT/目标协议层内，对同一记录集合比较：

| 对照 | 定义与边界 |
|---|---|
| A 传统3D IoU | 复现HoHoNet官方角点均高柱体定义；不静默规整人工输入 |
| B 原v1.1 | 冻结当前公式、参数和采样；Hstar局部高度机制已实现 |
| C 仅提高规整强度 | 只改规整最大折扣，其余固定；0.15/0.30/0.45只是未执行的候选网格 |
| D 分阶段候选 | 少量连续分段线性、超额平方等候选，事先写清局部/汇总层、阈值含义与最大惩罚 |

尽量先锁定有限比较方案，避免看了结果再不断加权或找阈值。若更换损失定义，说明数值尺度为何可比；不能沿用旧数值便宣称同样约束。新目标协议与新评分公式应分别对照，不同时改变后只归功于一个因素。报告方法各自可算集合和共同可算集合，避免样本变化制造改进。

传统基线的定义来自官方 [eval_layout.py L65–101](https://github.com/sunset1995/HoHoNet/blob/master/eval_layout.py#L65-L101)：地面多边形与角点均高构成柱体。人工非平顶的局部误差可能被均值掩盖，这是需要实测的解释限制。官方 [post_proc.py](https://github.com/sunset1995/HoHoNet/blob/master/lib/misc/post_proc.py)包含Manhattan轴向后处理，不能因此先把人工答案强制规整再称“原始人工3D IoU”。周长均高改版须另命名。官方异常回退值可以保留在兼容字段，但本研究不可算主字段仍为空并带原因，不能把异常当真实0分混入统计。

## 第四步 检验实际质量与反例

至少覆盖下列机制，优先复用已有真实案例、照片、评论与受控例子，不要求全库重审：

- 合理范围选择、真实少标、严重错定位、扩大和混合增删目标；目标内质量和覆盖贡献是否被混淆。
- 轻微规整偏差与严重Manhattan违反；单个严重墙段/短边错误在整体RMS中被稀释；大量正确墙段是否稀释惩罚。
- 真实非正交x8-09、真实非平顶/顶界模型不适用，避免把真实结构罚成错误；x8-01不用作可信GT调参。
- 均高相抵但局部高度错误，确认Hstar已有改进；检查更短局部脉冲等剩余盲点，不把已有机制当新发明。
- 环起点、方向和精确共线分段的表示稳定性；采样密度、极短墙段及数值极端情况。
- 修复了连接但固定GT分数下降的yq-07反例：原hold保留，分析几何和参考一致性，不强行让确认操作涨分。

给出每个候选改善和退步的真实案例，保留强反例。适用时提供误差分项、前后分、粗档次、同图排序反转、计算失败与异常数量；分数变化本身不是质量改善。规整绝对扣分在边界扣分后计算，顺序分解不是独立因果贡献。

粗分档先用现有证据评价可分辨程度，必要时提出很小的独立/盲评核验，不要按本候选得分反过来选择“真值”。旧95/85/50只作历史冻结对照。若证据只能支持“明显好/中间含混/明显差”，请明确，不强求精细等级。若比较受开发集反复使用影响，如实列出，不把事后诊断称独立验证。

## 交付与验收

1. 简体中文主报告：关键结论、可支持与不可支持之处、最小建议、负结果及待用户决定的问题；明确推荐方法是否已可靠到可用。
2. 可运行代码、配置、依赖与命令；每个候选有版本、参数、来源和真实运行日志。没有运行的候选只标计划，不填结果。
3. 逐记录机器结果与分母表：输入/GT/参考规则版本、gate、可算状态、原因、分项、总分和粗分档，所有缺失留空。
4. 真实案例与反例对照，附稳定记录ID、照片/几何证据和结果来源；提供足够覆盖失效方式的例子，避免只展示获益样本。
5. 参数敏感性、最少必要的数值与表示不变性测试，并说明哪些结论只能用于有限案例。
6. 与原v1.1及传统3D IoU的可复算对比，任何方法和协议变更分别归因；不覆盖原始输入、GT、历史分数或资格。

允许结论为“暂保留v1.1”“只修目标/参考规则”“简单加重足够”“分阶段无可靠收益”或其他有证据的简单替代。研究不必把所有开放问题当场解决，但必须说清什么已知、什么未定、下一步最小证据是什么。
