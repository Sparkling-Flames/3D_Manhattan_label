# 工作台使用与评分结果

本轮工作台用于对冻结的 36 份完整作答逐份打分。评分规则见[RATING_RUBRIC.md](RATING_RUBRIC.md)，选样规则见[SELECTION_PROTOCOL.md](SELECTION_PROTOCOL.md)。[工作台已上线](https://panorama-quality-review.fringnb.chatgpt.site)，v3 于 2026-10-07 17:23:06 UTC 成功部署，仅账户所有者可访问。42 项技术检查通过；因私有站点登录门槛，真实浏览器／WebGL视觉验收尚未完成。

## 评分流程

1. 先核对当前图片和作答 ID，查看原图中的上下边界、范围和细节
2. 结合俯视及三维视图检查表达是否可用；需要时分别查看原 GT 和修订 GT
3. 依据整体可用性填一个 1–5 分；证据不足时选“无法判断”，建议留下原因，分数留空
4. 用简短原因说明主要范围／内容或几何问题；不要求另外制造多个维度分数
5. 保存并导出结果。重新打开或导入后核对已评数量与记录 ID，确认没有丢失或覆盖

先完成自己的判断，再查看可选算法诊断。算法分项及历史案例说明只是辅助证据；它们不会自动写入人工分数。评分期间发现渲染或绑定错误，可先标为待处理，修复后再判断。

## 初始结果状态

初始 36 份记录的总体评分全部为空，完成数为 0。“未评分”和“无法判断”是两个状态，不能都按 3 分统计。历史六对人工比较只作为 prior evidence 保存，没有换算或预填本轮评分。

本目录随批提供的初始模板不代表已经取得用户评分。新的导出返回后，应先验证版本、记录 ID、唯一性、分值和缺失状态，再保存接收版本。不能从界面默认值、算法排名或过去的聊天判断推造新评分。

## 最小结果字段

结果至少应能追溯：选样版本、作答 ID、已评分／未评分／无法判断状态、总体分数、判断原因及更新时间。当前更新时间也会随查看事件变化，不等于评分修改时间或完整修改历史。工作台保存算法诊断的累计查看状态；无法证明未看过时不宣称严格盲评。

原因可以为空；选择“无法判断”时，建议写一条足以解释缺失的简短说明，界面不强制填写。CSV 中空分值保持空；JSON 中用 null，不把字符串“NA”、0 或 3 当作数值替代。具体字段名遵循工作台导出合同。

当前结果合同：JSON 导出已经建立的 rated／unable／draft 记录；CSV 输出全部 36 行，未建立记录记为 unreviewed 且分数为空。导入只接受 JSON，按 updatedAt 合并：仅严格较新的入站记录覆盖本地，相同时间保留本地值。JSON 中没有某条记录不表示已删除或已评分。

先查看算法指标而尚未评分时，会建立 draft 记录，但不会自动给分。换一份作答会收起算法指标；原／修 GT 选择与 GT 显隐状态可以恢复。保存失败或本地存储损坏时有明确提示，遇到提示应先保留导出备份，不能把界面仍显示内容当成已持久保存。

JSON 的 lastViewingContext 记录最近一次查看的参考版本／对象、GT 显隐、显示模式和指标显隐；它与评分时保存的参考版本／GT 显隐分开。CSV 不含这个完整对象，只保存评分时参考及累计看过的相关字段。因此需要恢复完整查看状态时使用 JSON 备份。

本目录 data/ratings_initial.json 是全空归档模板，不是工作台已建立的用户备份。恢复评分进度应使用工作台自己的 JSON 导出。

## 接收后分析

首先报告实际收到多少份、各状态数量和分值分布，再按图及选样路径检查与数值诊断的对应。相近评分不强制精确同分；同分也不代表范围、结构和几何缺点完全相同。

若以后用这些分数选特征或权重，结果仍属于同批探索。未用于调参的图片／房间验证需要另行明确；不能靠重复导出或拆开同房视角制造新独立验证。人员、图片、构成和人数分析仍需自己的面板和误差口径，不由这 36 份直接推出普遍结论。
