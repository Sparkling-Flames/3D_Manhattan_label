# 执行中明确的支持口径

设计、类别、人员、n/m和端点请求保持R01冻结版本。以下是分析字段的明确化，不产生新团队。

首个按事件ID选择的完整实例中，A包含v1 audited与new reported两种记录来源，B/C各自只有同一种new reported来源。因此三臂统一劳动比较不可用，但B→C的两视角四端点劳动比较可用。主三臂幅度与Q/T结果继续要求全部六端点同来源；另保存`QT4_*`比较级共同支持字段，不用它替换六端点主表。通用劳动差值与幅度也同样限定六端点统一来源。

关键成员匹配的效应比较逐指标要求present/absent两侧都可评，并使用完全相同的匹配strata；合法匹配事件总数、质量共同支持事件数分别保存。不能把合法匹配但一侧Q全缺失的stratum混入单侧效应均值。

人数路径旧`source_time_total_seconds`的known-only汇总与单一时间记录语义是不同条件。新增重抽采用逐人来源还原的相容时间支持；旧known-only中间结果保留其身份，不作为同来源成本结论。

## 源阈值条件率的配置计权

在全量主分析运行前明确：主图对等权源阈值条件率先对每个方向/n/m配置的共同六端点支持求平均触发数和同向数，再在图对内等权配置后求比率，最后图对或建筑等权。小空间全枚举因此不会仅因事件更多而获得更高配置权重。另保留逐事件触发计权率，以及图对等权但图对内按实际触发次数合并的辅助率；字段名区分。两端同时响应的条件率用同一层级，不能与只筛源端的条件率混称。

## 质量与结构的联合陈述

全量执行状态表显示，`geometry_status=ok` 还包含低于四节点的候选几何，并不等于完整可评融合。主事件表继续保留所有状态和各指标自己的有效支持；另由 `build_reader_tables.py` 给出 `QUALITY_STRUCTURE_COMMON_SUPPORT.csv`，专门在六队 Q 均可评的事件上并列质量分项与结构变化。联合解释使用该表，不把候选结构计数自动当成可评分的正式完整结果。此项只重新汇总已登记结果，不增加团队或修改失败定义。
