# 当前 ZIP 使用的定向核对

盘点不是仅按日期把包判为旧版。对主线代码及已展开人员/同房/融合代码的 ZIP 调用进行了定向检索，区分以下用途：

|用途|例子|本轮处理|
|---|---|---|
|当前运行需要测量代码|`scope_quality_scoring_20261016`，画像/融合/同房通过它读取 shared `measurement_engine.zip`|13 个实现/配置普通目录；默认入口改目录，旧 ZIP 参数自动优先目录。禁止 ZipFile 的实际重放通过|
|当前数据的来源凭证|shared 测量引擎原 ZIP；与 closeout 原包相同的测量实现|原件保留；新清单逐文件核对，不改评分身份|
|旧 3152 份/v1 研究重放|`descriptive_statistics_20261015` 等从 closeout 读旧 ledger 和历史几何快照|保留旧来源，不能假定新 v2 数据能替代该旧快照。本轮不宣称旧实验全部脱离 ZIP|
|原图 Release 分发|人员案例代码从 Release ZIP 提取指定原图|这是原始输入分发，不是当前分析代码/结果藏在 ZIP；不展开原图全集造成重复|
|原阶段打包器与交付核验|`package_deliverable.py`、`package_results.py`、旧 `recompute_metrics.py`|已展开的分析源码仍可直接读取；保留历史打包工具身份，不当作当前首选交付入口|
|已同时展开的包|`quality_component_return_review_20261014`，已有代码与关键结果表|不重复复制整个归档|
|未采纳的旧候选|Q-Profile、scope 模型的精简来源包|保留为历史研究来源，不升级成现行算法|

本核对覆盖的是指定主线入口及匹配到的调用，并非完整静态导入图，也没有证明每个历史 ZIP 都再也不会被调用。`ZIP_INVENTORY.json` 保留未判定条目，避免把不确定性包装成“全库整理完成”。当前修改的目标是拉取后主线评分与关键表不再要求解包，不是清空所有压缩文件。
