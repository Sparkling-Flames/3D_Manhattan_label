## 3. 新方法确有一个狭义身份分区诊断缺口

最小输入：3名不同人员，各4个上下点对；上/下y固定120/390，后三个x固定384/640/896；第一对的x分别100、116、132。阈值为默认5°。

最大上下端点角距满足相邻两条同为3.8275550165074015°，两端为7.650148889238645°。相邻距离是源码计算的原始浮点**完全相等**，十六进制均为 `0x1.e9ed52a1c51fbp+1`，没有四舍五入或预先round制造并列。

只双射交换记录与人员标签，所有非ID字段逐值相同，原环、坐标、票数和人员独立性均不变；两次所有来源几何都通过。输出第一对中心却由x=108变为124像素，其余三对不变。两次状态均为ok、支持为[2,3,3,3]、竞争对应计数均为0。

原因：节点按worker/id排序（源码27、45—47行），complete-linkage以等距并列选合并（61—62行）；当前竞争诊断只统计一个观察对同一其他人员有两个以上阈值内候选（89—104行），并不会检出这种每人最多一个局部候选、但整体分区有并列解的情况。状态仅据此计数等标记降为geometry_review（173—179行），所以此次没有警报。

正确解释是“确定性分区不等于与人员ID无关或对应稳定，现有竞争诊断不完备”，不是“ok在文档中承诺视觉正确却造假”。源码已经令 `uniqueness_established=false`；反例不推翻全员点路线，也不要求停止人数/人员探索。建议加ID重命名与等距分区敏感性回归，并把未穷尽的歧义诊断边界写清；仅把节点改按几何排可去掉ID依赖，却不等于解决分区语义歧义。

证据：`check_partition_ties.py`、`partition_tie_result.json`。该例是存在性反例，不估计137图受影响比例。未扩展随机搜索。
