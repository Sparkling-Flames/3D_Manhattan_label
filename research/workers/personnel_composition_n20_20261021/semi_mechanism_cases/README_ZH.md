# 新增机制案例：同图20人团队的尺度构成与位置中位数

本批在 q9vSo1VnCiC-15 的普通 Semi 任务中补充两个真实匹配对照：一例符合“同构成较稳、改构成变化较大”，另一例方向相反。案例从本次完整事件结果中事后选择，用于解释机制，**不估计发生频率、不选择或修改人员标签**。原图按已有 GitHub Release 索引取得，原始 PNG 为2048×1024，绘图沿用1024×512坐标合同。

这里 A、B、C 是三支具体团队的简称，与人员分几类无关。本例使用已冻结的 SP 两个粗类：SP_LOW 为楼外历史较低推导高度倾向，SP_OTHER 是其余尺度表达。最终全数据类名不能替代目标建筑外标签；本例实际使用冻结楼外标签。

## 1. 两个实际对照

|对照|A：基准|B：同构成换人|C：改构成换人|实际替换与背景|
|---|---|---|---|---|
|支持型个例|LOW 1、OTHER 19；Q69.9568|LOW 1、OTHER 19；Q71.4613|LOW 4、OTHER 16；Q77.4506|A→B、A→C均替换15人，共同背景同为5人；B→C换6人|
|反例|LOW 4、OTHER 16；Q73.3132|LOW 4、OTHER 16；Q69.7416|LOW 5、OTHER 15；Q73.4685|A→B、A→C均替换13人，共同背景同为7人；B→C换6人|

Q为原冻结B8L2。支持型个例的绝对Q变化为同构成1.5045、改构成7.4938；反例为3.5716、0.1552。D10保留相同判断，分别为1.5036/7.7584与3.7387/0.1014。不是把不同实际换人数的两条变化硬作比较；每个事件内部均严格对齐共同背景、n和m。

两例的来源构成都没有完全配平。第一例A/B/C的旧、新来源人数分别是9/11、7/13、11/9；第二例为8/12、8/12、11/9。因此它们说明实际构成及成员变化如何传到几何，不能将整队差异独立归因于SP类别，也不能从这两个事后案例推断总体优势。来源配平的总体结果见独立匹配对照汇总。

精确事件号：支持型 `927bb09d3927de85e8c3fe35`；反例 `cae738f17a9d1a72768717fb`。完整实际成员、原始作答、三个终点和票账在 `cases/*.json.gz`；原图出处与CRC/SHA在 `originals/PHOTO_RECEIPT.json`。本地SHA是取得字节的身份记录，不冒充发布者独立签名。

## 2. 新发现：角点和门槛没变，坐标仍会变

六支团队都输出4个角点，门槛均为10票。按不可变的“作答记录ID＋点对索引”核对，各比较中共同观察的同组关系变化数均为0。此次差异由实际位置与坐标中位数传递，不能解释成新增角点过门槛，或旧观察重新分组。

取靠近ERP x=460的选中位置组，支持型个例A/B/C的底点y中位数为324.0000、324.0000、328.5698像素；反例为327.9342、324.0000、326.6925像素。116条实际观察逐条列于 `POSITION_MEDIAN_OBSERVATIONS.csv`。图中每个点代表一个真实观察，保留两类颜色；两种类别内部仍有不同位置，类别人数相同并不固定中位数。所有观察都位于图的显示范围内。

支持型个例从A到C，平均推导高度/参考高度从1.01512变到0.99436，底面IoU从0.75405变到0.80478，extension由0.32618降到0.24202。B8L2因此提升，但方向误差从0.88411升到1.73296，Hcenter也从0.00860升到0.01584：质量分项并非全部同向。参考节点9°召回仍为1；该9°诊断不改变原生融合对应参数。

反例中A与B有相同粗类构成，底点中位数却回到324.00，底面IoU从0.77774降到0.75595，B8L2下降3.5716。改构成的C反而与A质量更接近。该现象说明SP类描述历史尺度倾向有价值，但具体成员、局部位置分布和共同背景决定本次贡献；它不是对人员心理动机的推断。

这两例时间记录均不完整，不报告虚假的整队效率。3D图的相机高度固定为1，墙顶水平距离从配对底点推导；它是沿用合同的三维代理，不是实测物理房高。图中冻结参考只提供既定质量比较，本案例不回溯裁定新范围、修改GT或恢复被筛人员资格。

## 4. 复现与保存

新增不同成员集合数为0。仅为恢复未保留的完整内部票账重放了6个已经计算的团队，每个结果都与缓存几何逐值核对一致；没有再次评分。`CASE_EXPORT_RECEIPT.json`记录输入池、结果源与输出身份。

从研究目录恢复两个 `cases/*.json.gz` 后，直接调用前阶段 `evidence/render_evidence.py --case ... --photos ... --out ...` 即可重画ERP/BEV/3D，不需要全量融合缓存。`render_position_mechanism.py`重画局部位置图。`export_n20_cases.py`记录最初从已算终点导出和重放核对的完整过程；原生缓存不重复打包，源终点可从分批结果及精确请求恢复。

本批单独保存，包含一张实际原图、两份完整案例、必要小表、绘图与导出代码、图片和校验清单。没有另起同房研究，也不将两个例子替代全部配置或匹配事件的统计结果。
