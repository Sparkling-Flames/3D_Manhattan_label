# 本轮薄封装、历史数值一致性与诊断口径独立审查

审查日期：2026-10-19。范围：`analysis/composition/fusion_runner.py`、`design_screen.py`、`INPUT_AUDIT.json`、`SPLIT.json` 及它们调用的恢复版冻结融合、评分代码。未读取本轮新验证集融合结果，未以本轮结果选择审查团队，未修改融合、参考、评分或主研究代码。

## 结论

在审查版本及 26 个预先按哈希选定的精确历史团队上，未发现改变冻结融合或 B8L2/D10 结果的实施错误。全部实际成员、完整 `compact` 融合状态、最终候选几何和离散状态完全一致；所有比较的数值分项最大绝对差均为 **0**。六个历史失败团队仍失败，缺失评分仍缺失。

这是实施一致性证据，不能用作人员分类规律的独立验证。审查团队限于旧普通 Manual 结果，覆盖 8/12/16/24 人四个旧节点；本轮其他人数、门洞、Semi 和特殊条件的科学结论仍须由其实际实验支持。

## 2. 冻结调用链与数值一致性

`score_status=complete_conditional` 表示满足当前评分计算条件，不是人工确认结构真实、顺序无歧义或身份无歧义。审查中常见 `geometry_status=ok` 与 `geometry_reason=source_order_and_identity_unconfirmed` 共存，报告应保留该限定。

## 3. 缓存与成员重建

内存评分缓存每池单独创建，键包含完整候选几何、节点数及是否为两人团队。冻结评分在固定池和固定参考下依赖这些字段；当前作用域内未见遗漏评分相关依赖。使用上述 26 队中的同一历史团队，第二次把请求人员顺序反转：team key、成员、几何及所有评分仍完全一致，评分函数调用由第一次的 1 次变为第二次 0 次。磁盘缓存同一请求二次执行 `new_teams=0`。这只是重复同一队的缓存检查，不增加独立团队或图片支持。

磁盘上下文保存池内容摘要、融合 gap、主仓库／科学版本文字及封装文件 SHA256，并要求完全匹配。需注意两个可复现边界：

1. 恢复版依赖的实际文件哈希尚未全部进入运行缓存上下文。如果有人在提交标签不变时改了依赖文件，现有缓存上下文不能自动发现。本审查另保存了实际融合、环序、评分、测量引擎 ZIP 和 working models 的 SHA256，足以锁定本次审核依赖；交付复现应检查这些实际内容哈希。
2. 同一调用内每池只交给一个进程，当前使用方式可行；不同程序同时向同一缓存目录的同一池写入并没有跨程序锁。不要让独立运行共享同一个可写输出池，或另加锁。

封装从池 ID 确定冻结参考；若未来请求显式附带 `reference_id`、`reference_version` 或 object ID 约束，目前新入口不会像旧请求验证器那样额外比对这些可选字段。当前生成器按冻结池构造请求，历史审查又单独比对了它们，未观察到错误。最终代表案例应直接保存封装返回的精确人员、object ID、实际参考和参数，避免把请求中未被执行的可选声明当作完成证明。

## 4. 新参考节点／邻接诊断的准确含义

`ref_*` 是新增解释性诊断，不属于冻结 B8L2。算法把候选上下端点与参考上下端点的球面角差取最大值，先做最小总成本的一对一分配，再分别保留不超过 5°／9° 的配对；只有候选多边形直接相邻且配对后也在参考环上相邻的节点对才计作参考边命中。

两个可以完全重建的合成例子说明，不能把它直接称为“必要墙段完整率”：

- **共线细分例。** 参考是一个正方形；候选仅在同一面墙上多加一个共线中点，墙面和封闭区域完全相同。节点召回仍为 1，直接邻接召回由 1 降为 0.75。该数值对冗余顶点和直接邻接编码敏感。
- **分配后阈值例。** 三个参考节点与三个候选节点的球面角成本中，前三个对角项为约 4.001°、4.000°、0°，可做到 3／3 全在 5° 内；但最小总成本解选中了一个 6.064° 配对和一个 1.000° 配对，阈值筛选后仅余 2／3。故它不是“阈值内最大可匹配召回”。

这两例的精确 BEV／ERP 点、成本矩阵和实际返回值保存在 `REFERENCE_DIAGNOSTIC_PROBES.json`。它们是算法边界，不是本研究图片上的发生率或科学反例。

建议继续使用“当前角匹配下的参考节点命中”“参考直接邻接命中”，把 5°／9° 写入图注。它可以帮助定位结构差别；必要结构结论仍应回到标记的参考墙段、ERP／BEV／3D 和原图检查。若共线细分影响主案例解释，可单列不改变 B8L2 的墙段几何覆盖诊断。

## 5. 输入、建筑拆分与筛选设计

从冻结快照独立重数得到 229 池、196 张图片、22 座建筑、60 人；层数为普通 Manual 177、门洞 Manual 17、普通 Semi 32、特殊 Manual 2、特殊 Semi 1。所有池内人员 ID 和 object ID 唯一，人数等于池元数据。10／6／6 座历史／发现／验证建筑两两不交且覆盖全部池建筑。普通 Manual 分别为 81／51／45 池、2,578／1,698／1,443 份，合计 177 池、5,719 份；易中难和门洞／Semi 数也与 `SPLIT.json` 完全一致。

这项重数不等于重新审完 10,439 份库存和 7,302 份质量结果的每一处资格细节；该部分仍依赖用户交接资格与已有输入审计。建筑拆分属于既有 v2 内的回顾性历史／发现／冻结后复查设计，验证图不是新的外部盲测，跨建筑重复的已知人员也不是新人员泛化。

`design_screen.py` 覆盖全部发现集普通 Manual 池；人数候选为 3、4、5、6、7、9、13、17、21、25、29、33 及该池全员数。每池每人数均匀抽取最多 24 个不重复具体团队，若全部具体团队不超过 24 才真正穷举；种子及总可能数、抽取数、穷举标志均有记录。这个阶段不以类别或评分选队，适合作为公共候选筛选底板。

但均匀抽具体人员自然聚集于该池原有类别比例，不能视为对纯类、稀有配比或所有类别构成的穷举。完整研究需要另外执行类别构成和配比定额、可比换人规模、共同背景和新具体成员组合的实验，并把实际覆盖与未覆盖列入台账。分类和比较规则必须先于验证结果冻结；本审查没有检查本轮新验证结果，不能为该后续科学环节背书。
