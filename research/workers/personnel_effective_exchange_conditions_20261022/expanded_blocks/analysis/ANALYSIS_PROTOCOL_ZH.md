# 扩展成员与背景实验：汇总口径与读取说明

本轮底层数据仍是 **v2**。`personnel_useful_taxonomy_v3_20261021` 是上一轮研究目录名称。本目录只分析冻结的扩展请求及其完成端点，不改变人员资格、原始标注、参考绑定、评分或融合参数。

## 本次实际检验的对象

注册对象是 253 个“图片 × 方法 × 方向 × 人数／换人数”单元，共 494 个背景面板、390,208 个有向 ABC。普通 Manual 是主结果，门洞和特殊范围另列。重点条件为 A2 的 n17／m9、旧 M 父类固定细分的 n10／m5 与 n10／m6，以及新行为分类的 n10／m7。A2 的 A02→A01、A02→A03分别报告；新分类按楼外训练中心角色、特征族及实际 K 对齐，不能把不同楼外折中的同名数字类直接相加。

A／B／C 表示基线、同构成替换、改构成替换三个团队角色；人员类别数量由各自冻结标签决定。每个 ABC 中，A 和 B 保持类别人数构成，A 与 C 改变一个完整类别块；两种比较使用相同共同背景、总人数和真实换人数。旧 M 细分保持粗类构成。源类块的 B 是 A 在冻结源成员库中的补集，因而完整枚举时 A、B 的有向身份对称。**有向 B−A 的平均值为零是设计性质；判断互换性应看 |B−A|、形状差异、尾部、失败和成员分布。**

小块 m5、m6 完整枚举冻结 2m 源成员中的全部 m 人子集。较大块 m7、m9 枚举冻结配对槽位的全部 2^m 种选法。目标块枚举冻结目标库中的全部 m 人选择。背景按事前规则选择；这是一套完整可复现的**有限注册成员空间**，并非全部正式人员池、所有共同背景、全部成员集合的穷尽。配置覆盖另见上级目录 `CLASS_CONFIG_MEMBER_COVERAGE.csv.gz` 与 `CELL_CONFIG_MEMBER_COVERAGE.csv`；按单元相加的配置数有重复，不能称为全局唯一配置数。

本目录另外提供 `CANONICAL_CONFIGURATION_MEMBER_COVERAGE.csv.gz`：按实际已知人员域、方法／层级、n 和类别人数向量，把多个方向及 M 的 m5／m6 重复格归并。4,969 个单元配置登记归并为 4,194 个配置，其中 783 个有实际成员覆盖。`CANONICAL_CONFIGURATION_TEAM_INDEX.csv.gz` 给出 134,901 个方法域—团队关联，精确去重后是注册的 134,869 个团队端点。不同方法对同一团队的解释身份保留，不能把这些关联数再次相加当作独立端点。`CANONICAL_DOMAIN_N_COVERAGE.csv` 同时给出注册方向兼容的向量并集、全部该人员域的 C(N,n) 成员分母及两种未覆盖数。

## 质量变化与变化大小分开

方向结果是 C−A。正的 B8L2、D10 或参考召回变化表示相应分项增加；有效转折、短边和冗余点的增加只是结构表达变化，不能自动等同正确性。遗漏、扩展、高度和位置等按冻结指标原定义报告。

同构成与改构成的变化大小只在相同成功资格上比较：

`within_abs = |Q(B) − Q(A)|`

`cross_abs = |Q(C) − Q(A)|`

`advantage = cross_abs − within_abs`

advantage 为正表示同构成换人平均变化更小，不表示改类能升质。方向 C−A 的成功评分分母与 ABC 三臂共同成功分母分别保存，不能混用。结构、底面和三维代理的共同资格比较采用对应的 `common_*` 字段。

失败不填成零分，也不从事件全集删除。A／B／C 失败分别有完整事件分母；成功评分下降超过 10 分单列；“目标失败或成功评分下降超过 10 分”作为另一个风险指标。成员层面还报告每个面板各构成的唯一实际团队数与失败团队数，避免只看因端点复用而膨胀的事件数。

## 推断单位与权重

所有主要效应先在一个实际共同背景内汇总，再对图片内不同背景等权，最后对建筑内图片等权，并对建筑等权。这使枚举容量更大的图片不会仅因事件多就主导结论。每个结果同时保留事件加权均值、背景／图片／建筑均值和中位数、有效分母，以及正向、反向和相等数量。

完整事件中位数仅为 `same_B8L2`、`cross_B8L2` 和绝对变化优势重新读原事件精确计算；其它分项表中的中位数是明确标注的背景、图片或建筑中位数。不会以“各背景中位数的中位数”冒充全事件中位数。核心结果的 95% 区间是按建筑重采样的描述区间，不把大量相关枚举事件当作独立样本。

`priority_seed_images` 与 `additional_images` 按各方法及 n／m 对应的旧候选图片清单区分。additional 是相对旧候选图增加的覆盖，不宣称新的外部数据、从未参与历史研究的建筑或全新盲测。扩展请求在这次端点结果产生前冻结；本次验证的是已提出条件在更多实际成员、共同背景和图片中的表现。

## 具体成员与背景敏感性

`MEMBER_RESPONSE_*` 每个面板报告 A、B、C 三臂的实际不同成员集合。A 与 B 在完整对称设计中枚举同一源集合，因此易读汇总只计源臂 A 一次。成员分布提供评分标准差、范围、5%／10% 低尾、90%／95% 分位及失败比例。

目标 C 只有一个实际团队时，均值和失败状态仍有效，**成员波动记为不可估计**。不能将单集合的数学零方差解释为类别可互换。`BACKGROUND_SENSITIVITY` 保留同图同方向两个背景的效应范围和符号是否相反；只有一个可行／注册背景的单元不形成背景稳定性证据。

## 历史质量、来源与时间辅助

总类别作用先用全部注册事件评价，来源或 Q 匹配不作为前置门槛。辅助表分别限制为 A／B／C 的历史旧批／新增批人数相同（冻结字段 `new_n` 一致），以及这一来源人数条件满足且同类与跨类的楼外替换块历史 Q 差均不超过 5 分。这并非对每个原始来源批号都逐一配平。后者只能解释已匹配支持中的附加信息，缺少支持的条件保留未知。

正式时间比较要求三臂时间来源相同、每臂所有 n 人均有记录、总值有限且为正。时间以源字段所记录的秒为单位，汇总为团队记录人秒；不称为自然完成时长或并行工时。时间合格样本的 Q 变化另列，避免将全样本 Q 与时间子样本的节时效果拼接。缺时间不按零处理。

本专题原有的 `cross_recorded_time_pct` 主值是 **算术百分比的分层均值**：先计算事件的 `100×(C/A−1)`，再按共同背景、图片、建筑等权。为与使用对数比的专题对照，`FINAL_TIME_AGGREGATION_COMPARISON.csv` 另给出 `100×expm1(mean(log(C/A)))`，其中均值使用完全相同的分层权重。两种统计量的有效事件、背景、图片、建筑分母均逐项核对一致；原有算术值不被替换。几何百分比是记录总人秒比的汇总，仍不是自然完工时间或预测误差改善对应的节时比例。

## 增量保存、状态与复现

`analyze_expanded_results.py` 只读取有 `COMPLETION.json` 的完成单元。每个单元的辅助结果先独立写入 `extra_cells/{cell_id}/`，保留源回执 SHA-256，后续运行直接复用。所有 CSV 先写临时文件、读至 gzip EOF 验行数／列数，再原子替换。

未完成时输出前缀为 `PARTIAL`，状态为 `PARTIAL_NOT_FINAL`，覆盖账包含全部注册分母及未完成数量。正式运行：

```bash
python expanded_blocks/analysis/analyze_expanded_results.py --require-complete
python expanded_blocks/analysis/prepare_readable_results.py
python expanded_blocks/analysis/make_report_tables.py
```

第一步要求所有注册单元完成；第二步要求正式完成回执。工作目录应为本轮研究目录，或使用脚本绝对路径。两脚本均固定 BLAS／OpenMP 为 1 线程，不调用原生融合，不重新评分。

正式主入口为 `FINAL_PRINCIPAL_CONDITIONS.csv`、`FINAL_CORE_SUMMARY.csv.gz`、`FINAL_COVERAGE.csv.gz`。全分项见 `FINAL_ALL_COMPONENT_SUMMARY.csv.gz`；历史匹配见 `FINAL_HISTORY_MATCHED_CORE_SUMMARY.csv.gz`；具体成员与背景见 `FINAL_CONDITION_MEMBER_VARIATION.csv.gz`、`FINAL_BACKGROUND_SENSITIVITY.csv`。原逐事件、团队标量、几何、请求及配置全集由上级目录独立交付，不在摘要包中重复存储。

若取得的是 `delivery/expanded_events/` 的 25 个完整逐事件分片，可以先运行：

```bash
python expanded_blocks/analysis/restore_event_inputs_from_delivery.py
```

脚本按 `CHUNK_PLAN.json` 及各分片回执验证输入，流式恢复到 `analysis/rebuilt_event_inputs/{cell_id}/`。上级资料包须同时保留原来的 253 份小型 `PANEL_SUMMARY.csv.gz` 和 `COMPLETION.json`；分析脚本在原逐格事件大表缺失时自动读取恢复路径。恢复文件保留所有 CSV 单元格值、空值、失败行和事件键，字节级 SHA 可能与原 gzip 不同，因此新写 `REBUILD_RECEIPT.json`，明确记录新旧 SHA，不伪造原文件身份。

这条恢复路径已用 A2 的一个完整 1,024 事件单元验证：487 列原 CSV 字符串全部相同；在原单元大表不存在的隔离目录运行辅助统计后，四张辅助表的原有字段精确一致。验证见 `RESTORATION_ADAPTER_VERIFICATION.json`。测试恢复产生的重复表不进入交付包。
