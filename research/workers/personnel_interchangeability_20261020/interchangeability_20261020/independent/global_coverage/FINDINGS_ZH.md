# 本轮全部正式融合的覆盖与重复审计

**17 个正式原生运行批次共记录 573,428 次新融合调用，跨批去重后为 569,529 个“冻结图片池 × 精确成员集合”任务。** 它们覆盖 195 个池、181 张真图片、22 栋建筑、60 位人员和 6,244 份不同冻结作答记录。图片和建筑才是跨图规律的独立支持；几十万支高度重叠团队不能换算成同等数量的独立样本。

## 1. 这些数怎样对应

| 计数 | 数量 | 定义 |
|---|---:|---|
| 请求行 | 573,645 | 每份请求文件中的全部行；同一精确任务可能出现在不同事件 |
| 批内唯一任务的加和 | 573,428 | 每批先按池与真实成员去重，再加和，尚未跨批去重 |
| 正式 native 新融合调用 | 573,428 | 17 份运行 receipt 的 new_fusions 加和；不同输出目录可能重算同一任务 |
| 全局唯一池×成员任务 | 569,529 | 全 17 批按同一冻结池和完整成员集合去重 |
| 真图片×成员集合 | 566,067 | 忽略同图不同冻结条件池的区别，保留真 image_id |
| 纯人员集合 | 536,228 | 完全忽略池与图片，仅数具体人员集合 |
| 批内重复请求行 | 217 | 同一任务在请求中重复出现；不再融合 |
| 跨批重复任务出现次数 | 3,899 | 批内唯一任务的加和减全局唯一任务 |
| 出现在多批中的任务 | 3,534 | 3,899 次额外出现涉及 3,534 个真实任务 |

所有 573,645 请求行的真实成员、k、有效池资格与精确成员哈希都已核对；所有请求任务都在对应原生池中。原生文件的冻结 pool_digest、参考 ID／版本、来源人数、objectID、科学代码版本和 wrapper SHA 一致。3,899 次跨批重复的全部科学字段指纹逐字一致，最大数值差为 0；没有未请求缓存队被计入。本审查不重新运行融合。

## 4. 排除与遗漏

冻结 snapshot 共 229 池、196 张真图。普通 Manual 的 177 池全部有本轮请求；未请求 34 池包括 13 个门洞 Manual、18 个普通 Semi、2 个特殊 Manual、1 个特殊 Semi。它们没有被当成零效果，也不能据未请求就判为数学上没有可行组合。逐池资格、方法容量及抽样遗漏以各批冻结台账为准；本覆盖审计不新造失败原因。`UNREQUESTED_FROZEN_POOLS.csv` 给出完整列表。

旧 A 保留的 122,082 个历史替换对观察属于训练／复用输入，不计本轮新融合。条件实验的全 phase union 请求、各重建目录副本、共同团队面板的竞争分类器和额外指标汇总都没有重复计成 native 批次。所有 17 个运行 receipt 均已定位，未发现漏记的新原生批次。

独立重放另列 `SUPPLEMENTARY_REPLAY_COUNTS.json`：旧 follow-up 抽样 30 队、基线机制 2,814 次仅状态重放、当时已有的案例重放 receipt。它们用于一致性和机制核验，不增加独立图片支持；这个补充表记录的是具名 receipt 中可核实的次数，不是对每次临时调试、标题重导出或绘图调用的累计性能剖析。正式科学运行的 573,428 次与这些重放分开。

## 5. 复现和交付依赖

`BATCH_REGISTRY.json` 给出全部精确请求、native 目录、运行 receipt、生成器及冻结文件路径和 SHA。`audit_global_coverage.py` 按批顺序读一份请求、按池读一个原生结果，核全部成员与全局去重；不需复制或保存全距离矩阵。精简交付可保留这组小表与 receipt，通过登记的生成代码／参数／种子重建大请求和原生缓存。若只重绘覆盖说明，运行 `summarize_global_coverage.py` 即可，输入仅本目录审计 JSON 与小 CSV。
