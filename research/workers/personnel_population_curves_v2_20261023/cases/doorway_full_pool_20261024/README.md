## 可以直接讲的结果

图片 **7y3sRwLe3Va-06，G013，Manual门洞单列**。库存35人，冻结实验池32人；“满员”指32个实际合格池成员，不是把库存所有记录全部投票。

全员时门槛为 **16票**，冻结对应形成 **14个身份组**，只有 **3个节点入选、11组未入选**。保存的三个入选支持数为 **19、25、26**。结果可保留三节点诊断几何，但少于当前完整评价所需的4节点，`score_status=below_four`，B8L2、D10和3D IoU均缺失，不能展示成0分或合格三角形布局。

此例说明：**增加到当前人员池全员，也不保证所需结构获得足够支持并组成完整共识。** 不据此推断所有门洞必然失败，或人类无法标注。当前17个门洞池全员中有6个不完整：5个只保留3节点，另1个保留2节点；完整列表见[全员状态表](DOORWAY_FULL_POOL_STATUS.csv)。24条自然顺序最终重复同一支全员队，不能算24次独立失败。

### `doorway_saved_full_pool_case_v1` 消费约定

所有`image_path`及`sources`以仓库根为起点。坐标尺寸为 **1024×512**，`points`按顶/底交替存放，保留原冻结环序；原图可能更大，按比例绘制。`annotations`每行含`worker_id`、`object_id`、完整点、来源及原资格；不是筛出的“代表角点”。`reference.points_1024x512`为8个点对，`reference.floor_xz_h`为相机高度单位底面。

`endpoints`依人数排列，`members`为实际人员，`metrics`缺失统一为JSON null；`geometry.points/footprint`可能为null，展示其`reason`并停止画融合连线。`geometry.feature_ids`仅属于该端点，不能当成跨人数的永久角点身份。`selected_node_supports`是保存的入选节点票数列表，**来源没有逐节点票数ID绑定，不按数组顺序把票数贴到某个角点**。可以显示票数分布及门槛。

本案没有附带11个未入选组的逐人员身份票账，不能从原答目测或最近邻重新拼出并当作冻结结果。现有材料足以展示完整原答、入选支持、节点不足与连接失败；不把算法未归组等同于人员没画，也不把满员失败全部归于某一种门口语义。需要研究每个失选组的精确成员时，另恢复对应历史状态原件；本次不以此阻塞已有结果展示。
