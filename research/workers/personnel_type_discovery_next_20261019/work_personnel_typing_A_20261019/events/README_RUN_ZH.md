# Part A：共同替换事件、固定身份四节点与原生重放

## 冻结的两组事件

本轮从当前 GitHub main 的 Pro 核心归档 bootstrap 恢复原布局，调用字节不变的冻结源代码。`DESIGN.json`、`REQUESTS.json.gz` 和 `event_design.csv.gz` 在任何本轮融合输出及新类别结果之前生成。注册摘要见 `REGISTRATION_RECEIPT.json`。

| 面板 | k8 | k12 | k16 | k24 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Pro 原精确背景事件 | 114,720 | 82,348 | 55,444 | 17,858 | 270,370 |
| A 新固定身份／嵌套背景节点 | 4,200 | 4,080 | 4,080 | 3,936 | 16,296 |
| 有支持图片 | 175 | 170 | 170 | 164 | 175 个不同图 |

两个面板共 286,666 个事件、58,882 个端点请求，实际涉及 58,679 个不同真实成员集合。新面板有 4,200 条固定人员对和背景排列，在人数支持时使用 7／11／15／23 个背景人前缀。它是四个偶数人数节点；本轮没有计算所有中间人数，也没有声称复现 main 缺少完整载荷的 Dot 设计。

旧主面板保留归档 26,290 个请求原值，包括对应背景只有一个候选 entrant 而无替换事件的请求。新面板按池随机选 12 对无序人员，每对两个独立背景排列，未依据新类别、Q、目标点数、实际簇或输出选事件。两面板都触及 60 个 entrant ID，但最薄人员的事件仅来自两图；这不能替代分类历史支持门。

新面板的两个独立排列偶尔产生相同背景集合：k8 有 48 个重复实际端点对、k16 有 1 个。因此 16,296 个注册事件对应 16,247 个不同实际端点对；请求保留，重复不增加独立背景或真人支持。旧主面板 270,370 个实际端点对没有重复。逐 k 清单见 `design_duplicate_actual_pairs.csv`。

新面板在每个 k、每个固定背景下只有该预抽人员对的一个事件，不能在同一背景内同时估计“同类组与跨类组均值差”。它用于同一事件上的方法配对预测、类内／类间分布、固定人员对的四节点变化和额外背景迁移。严格同背景类内／类间组对照使用旧主面板的全 entrant 对。

建议训练及类别数选择只使用 `panel_id=Pro_exact_fixed_background_v1` 中训练建筑的事件。`A_nested_even_v1` 留作外层目标建筑的额外背景评估。按外层折排除目标建筑后训练关系，不准读取该折验证事件来改类数。

## 直接读取

- `event_design.csv.gz`：冻结事件身份、两侧成员、同背景、参考和四节点链信息。
- `common_events.csv.gz`：同一事件对应的完整原生结果及上下角距诊断，所有候选类别在同一行附标签。
- `comparisons/<pool_id>/events.csv.gz`：按池拆分的相同结果，可逐池读取训练建筑，避免一次加载全部长字符串。
- `native_runs/pools/<pool_id>/states.json.gz`：每个真实团队的紧凑原生状态、节点来源、连接与最终几何。
- `native_runs/pools/<pool_id>/request_results.json.gz`：完整质量分项、D10、状态、时间及缺失；`requests.json.gz` 保留精确请求。
- `nested_chains.csv.gz`：完整背景顺序、种子和可用 k；`nested_coverage.csv.gz` 保留无支持机会。
- `FIELD_CONTRACT.json`：字段含义、质量差与几何差的区别、信息阶段和缺失规则。

`worker_a`、`worker_b` 按匿名 ID 字典序固定，有符号质量变化为 B−A，不表示好人替坏人。绝对变化是对称量。按训练侧 Q、成本或类别选人时，应另明确政策方向。

`complete` 表示可计算完整几何，不表示新增人工审核通过。失败进入所有尝试分母：联合稳定为 False，未知质量／范围／时间组件保持缺失。旧来源时间、新报告来源时间、同目标时间及其覆盖均可分开读取，不互相填补。

## 原生函数与新增计算边界

调用 `fusion_engine.run_pool`，其中实际几何为 `compact(fuse(selected,gap=7.5)['automatic'])`；对应、MV50、等人权中位、连接规则及 N1 未接入状态均保持。只把派生输出目录重定向到本目录的 `native_runs`，不修改函数源码或用户数据。每次入口逐项检查冻结引擎和评分源 SHA。

两队比较直接调用归档 `compare_fusions.ComparisonPool.pair`。新增的上／下端点最大和平均角距仅沿用该函数给出的**同一个绑定循环偏移**，不单独为顶面／底面寻找更有利对应；最大上下角距等于原生整体绑定角距的断言逐事件执行。

主容忍范围为 |ΔB8|≤2、两输出底面 Jaccard 距离≤0.05、同节点数、绑定循环角距≤3°，且两端完整可评分。严格／宽松使用 (1,0.02,2°)／(5,0.10,5°)。各项独立变化、坏尾、原观察连接和失败仍保留，不把“统计不显著”解释成相近。

## 运行

先按上级 README bootstrap 恢复 `recovered/work_v2_20261019` 和相邻的 `recovered/repo_main_20261019`。Shapely 2.1.2 安装到上级 `deps` 时，入口会自动加入该路径。

```bash
python work_personnel_typing_A_20261019/events/register_events.py
python work_personnel_typing_A_20261019/events/summarize_design.py
python work_personnel_typing_A_20261019/events/run_events.py --stage pilot --jobs 3
python work_personnel_typing_A_20261019/events/run_events.py --stage full --jobs 3
python work_personnel_typing_A_20261019/events/verify_replay.py
```

注册重跑只接受与已冻结字节完全相同的名单，改变设计必须另设版本路径。实际重放会复用**本轮目录已经成功生成**的状态；未取得的历史大状态缓存没有被冒充复用。每次 `*_RUN_RECEIPT_*` 分别记录新融合、新评分、已有状态及异常，首次 100 个团队计时另存 `PILOT_TIMING_RECEIPT.json`。100 个 pilot 请求分布在 74 池，因此其平均耗时包含较多跨池初始化；大批同池请求的冻结匹配缓存会被重复使用。

从空 `native_runs` 重放会再次执行全部真实融合；已有缓存运行不能称新鲜重算。几何状态是新运行输出，时间戳、运行耗时与 gzip 字节无需与历史包相同。

`verify_replay.py` 独立核对全部事件名单、共享背景、嵌套身份和稳定阈值；同时与归档保留的旧普通 Manual 逐事件候选结果核对 Q／几何／状态。这是保留旧输出子集的数值 parity，不是已省略全部历史状态的字节复现。当前科学任务依赖本轮全量新生成状态和精确请求，不要求用户重新提供 Dot 完整包。

## 主要支持单位

类别方案比较应首先用共同事件支持，再给每个方案的完整支持。主不确定性按建筑聚类，图等权和事件等权并列。大量请求和背景链不是新增独立真人或建筑。目标实际点数、簇及票数只允许进入作答后条件诊断，不可混入验证建筑上的采集前分类。
