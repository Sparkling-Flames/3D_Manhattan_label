# HOHONET v2.1 人员分类：七八人大块替换的独立容量与执行审计

## 核心结论

**“原报告选定方向的八人路径只有少数图片”不等于“整套分类只有这些八人替换容量”。** 在当前普通 Manual 主目标的 206 个合法池中，TARGET_DSTRUCT_K3 的严格纯类八人替换有 42 池容量，OPPJOINT_K4 有 71 池容量；旧研究分别只在 19、21 池登记过八人事件。旧设计的八人格均为 n12/m8，恰好半队的 n16/m8 没有进入这些方法的既有设计。

**因此需要补的是明确的设计覆盖缺口，尤其非最高 Q 换入方向与 n16/m8；并非重新证明已有 n14/m7、n12/m8 或大队 AC 是否存在。** 新 RAW3_K3 候选 n16/m8 的容量扩大到 64 池、19 楼，原 TARGET_K3 为 41 池、15 楼。这是容量变化，不能单独证明新分类更好。

**所有池最大只有 35 人，故严格 ABC 的 n20/m8 对任何分类均不可行。** n20/m7 可以有严格 ABC；较大团队的直接 AC 使用另一套人数条件。把它们合为一个“大块已验证”的结论会混淆估计对象。

本文件是补算前的审计快照，只使用已有注册与保存端点；主代理随后执行的统一格补算必须单列，不回写本表。源仓库读取的是 `519c7447278dd16c3d69f505b807fb5b53792b36`。

## 1. 实际读取与复核范围

独立读取当前两份 INPUT_SNAPSHOT，共 294 池；Manual 为 255 池，其中普通主目标 206 池、普通其它准入目标 30 池、门洞 17 池、特殊范围 2 池。Semi 不并入这些容量分母。

从当前 45 配置的楼外标签与真实池成员重算 11,475 个池×方法的类别容量，再与旧交付 `POOL_METHOD_CAPACITY.csv.gz` 逐行核对：人数、已知/未知历史人数和完整类别容量字典全部一致，差异为 0。

逐一核验全局广筛、重点、固定 A、细化对照及直接 AC 等阶段的精确事件。跨阶段同一方法、池、n/m、A/B/C 端点只计一次，得到 89,660 个不同方法事件，其中 87,694 个严格 ABC、1,966 个直接 AC。全部 D/X/Y/Z 人数与互斥性、源类和目标类楼外标签核验通过；19 万量级缓存实际是 189,514 个去重端点，事件所需端点全部找到。没有重新融合，没有把缺 Q 填成 0。

这些事件和端点是覆盖计数，不是独立样本量。同一图片上的多个成员/背景组合先在池内平均，同图不同目标再等权，主结果按图等权；建筑均值另列。已有各阶段样本设计不同，本审计将其合并仅用于覆盖与诊断，不将不匹配的均值当成公平方法排名。

## 2. 容量定义与退出原因

本轮既有严格纯类设计为 A=D∪X、B=D∪Y、C=D∪Z。X/Y 来自同一源类，Z 来自另一目标类，四块真实互斥；每队 n 人，三块分别 m 人。对真实池总人数 N、源类 S、目标类 T，充分必要的纯类容量条件是：

\[
N\ge n+2m,\quad S\ge 2m,\quad T\ge m,\quad 3\le n,\quad m\le n.
\]

因为四块共需 `(n−m)+3m=n+2m` 名不同人员。缺少历史特征的人可以留在 D；不能用已建类人数代替 N。X/Y/Z 则必须具有该目标楼外的已知标签。

直接 AC 不含 B，因此条件另为 N≥n+m、S≥m、T≥m。它不能计算同类幅度，也不能计算 C−B。

漏斗保留全部合法池，并分别记录：总人数不足；总人数足够但已知类别人员不足 3m（AC 为 2m）；已知人数足够但类别分布不足；容量存在但未登记；登记但未运行；已运行但指定指标不可评。另保留未知人数与类别字典，便于看到“3m 总量足够但某类受缺历史影响”的情况。历史不足的计数不是在声称所有缺标签都不影响类别容量。

这些条件限于纯源/纯目标块。若 X/Y 是同一**混合构成向量**，每类要求变为能提供两份对应席位；S≥2m 不再是必要条件。本审计没有把纯类容量不足误称为所有混合换人都不可行。

## 3. 七八人、半队和大队分开看

下表只列普通 Manual 的 206 个主目标池。每格“容量 / 已执行 / C−B 可评”均为池数；这些池在这里也各对应一张主目标图片。容量允许所有合法纯类方向，不限于选定最高 Q 角色。

| 方法 | n14/m7，半队 | n12/m8，超过半队 | n16/m8，半队 | n20/m7，较大队 |
|---|---:|---:|---:|---:|
| DSTRUCT_K3 | 132 / 90 / 89 | 62 / 20 / 18 | 58 / 0 / 0 | 99 / 0 / 0 |
| TARGET_DSTRUCT_K3 | 128 / 96 / 92 | 42 / 19 / 18 | 41 / 0 / 0 | 100 / 72 / 70 |
| OPPSTRUCT_K3 | 97 / 34 / 32 | 38 / 16 / 16 | 37 / 0 / 0 | 75 / 0 / 0 |
| OPPJOINT_K3 | 123 / 36 / 36 | 63 / 18 / 18 | 60 / 0 / 0 | 90 / 0 / 0 |
| OPPJOINT_K4 | 135 / 44 / 43 | 71 / 21 / 21 | 67 / 0 / 0 | 99 / 23 / 23 |
| RFUSE_GEOM_K3 | 170 / 50 / 48 | 145 / 38 / 37 | 133 / 0 / 0 | 118 / 0 / 0 |

对应总人数层的分母分别为：n14/m7 与 n12/m8 需要至少 28 人，206 池中 178 池满足；n16/m8 需要至少 32 人，150 池满足；n20/m7 需要至少 34 人，120 池满足。这些方法在上述总人数足够的池中，已知人员总量也达到 3m；继续退出主要来自具体类别分布，而非池总人数。

普通其它准入目标的 30 池单列，它们当前人数不足以支持上述七八人严格纯类事件，不能把这些池当成“分类无效”的负例。门洞及特殊范围有独立行，未进入普通 Manual 主结论。

固定 m7、允许所有可行 n 时：TARGET_K3 有 128 池容量，旧执行过 m7 的为 96 池；OPPJOINT_K4 有 136 池容量，旧执行为 59 池。固定 m8、允许所有可行 n 时：TARGET_K3 为 42/19 池，OPPJOINT_K4 为 71/21 池。因此“固定 m 的容量”和某一个 n/m 格的容量也需要分开。

“所有可行 n”按源合同允许 n=m、即 D 为空的极端；它是数学容量上界。具体可采用条件仍以逐 n/m 表为准，本轮必要补算的四个主格均有非空 D。

`REPLACEMENT_BAND_COVERAGE.csv` 同时列出所有 m 的半队/过半、m≥5 的半队/过半、固定 m7/m8、n≥20 的大队及大队 m≥7，附实际 n/m 列表。不能把小池 n3/m2 的结果拿来增加大块替换支持。

RFUSE_GEOM_K2 在真实楼外池中没有纯类 m7 或 m8 容量，K3 却有较宽容量。这不说明 K3 的解释一定更好，也不说明 K2 无用；它说明两层能够支持的实际干预规模不同。保留 RFUSE_K2 作小组响应解释，与宣称它能承担大块换人主方法是两件事。

## 4. 哪些具体方向被旧设计覆盖，哪些需要补

TARGET_DSTRUCT_K3 的 n14/m7：

- 结构机会转折秩 2→3 有 85 池、21 楼容量，85 池已经登记，不需要为了证明其存在再补一轮。
- 结构机会转折秩 2→1 有 48 池、13 楼容量，只登记了 12 池，另有 36 个**方向×池**缺口。
- 所有方向合起来，128 个池已有 96 个池登记，池层面缺口是 32。36 与 32 不冲突：部分池在另一个方向已被执行。

n16/m8 则两方向都未进入旧设计：2→1 为 30 图、10 楼；2→3 为 11 图、9 楼，合计 41 图、15 楼。这说明补算不能只追最高 Q/最多转折组。

OPPJOINT_K4 的 n16/m8 也有 67 图、15 楼容量，但结构转折秩 2→4 只有一图；2→1 却有 63 图、14 楼，另有 3→1 的 4 图。这正是“选定高 Q 方向八人支持很小”和“该分类八人容量很小”不能等同的原因。它们各自使用真实楼外角色，不把 ALL 类号复制到不同建筑折。

现有 TARGET_K3 n14/m7 的方向诊断如下。统计合并旧阶段后按图等权，仅作覆盖诊断：

| 结构秩方向 | C−B 可评图 | C−B 平均 | C−B 正向图 | 同类幅度 W | 跨类幅度 C | C−W | 跨类幅度更大图 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 2→1 | 10 | +1.719 | 4/10 | 6.061 | 3.277 | −2.784 | 1/10 |
| 2→3 | 83 | +6.570 | 76/83 | 4.578 | 7.967 | +3.389 | 62/83 |

W=|Q_B−Q_A|，C=(|Q_C−Q_A|+|Q_C−Q_B|)/2，幅度要求 A/B/C 三端点共同可评。该例表明平均数和多数图片方向必须并报；2→1 的少量支持不能被包装成整体升质，也不能仅据此认定参数错误。补齐其未覆盖池后才能判断其适用范围和类内差异。

## 6. 必要补算设计审查

主代理提出的统一格为 n14/m7、n16/m8、n12/m8、n20/m7，方法为 TARGET_DSTRUCT_K3、RAW3_K3、OPPSTRUCT_K3、OPPJOINT_K3/K4，保留所有合法纯类方向。该设计分别回答七人半队、八人半队、八人过半和大队七人，范围与当前缺口匹配。

每格两个不同 XYZ 成员块，目标类背景取可行 low/high 各一个；low=high 时只计一次。按输入容量测算为 1,888 个方向×池×n/m 格、5,838 个事件，端点上界 17,514；RAW3 n12/m4 的普通宽覆盖再加 432 格、1,650 事件、端点上界 4,950。端点去重与缓存复用将减少实际新融合量。这些是登记前上界，不冒称已运行。

设计应保证同一池、方法、方向与 m 的 XYZ 跨 n 固定，low/high 背景由固定成员顺序取前缀，让 n12/m8→n16/m8、n14/m7→n20/m7 能作真实嵌套比较。若复用旧块时按不同 n 各自挑块，会破坏这一条件，需要在注册时避免。两个成员块不是独立图片，两种背景也不是独立受试者。

暂不需要把所有 K2/K4 都全量扩展。原 TARGET 的 K2/K4 已有广筛和真实父子材料；RAW3 的各层先有原答、稳定性与容量结果。若统一格结果显示 RAW3_K3 内某一分裂对决定主分类必不可少，再明确补其父子比较，不能只因为多一个 K 就默认更多研究价值。
