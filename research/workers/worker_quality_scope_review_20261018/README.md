# 人员质量、scope与相对Q的独立核查

2026-10-18。真实数据v1；本包为审查结果，不改变正式评分、人员分类、资格、历史裁决或原留出。没有读取 `label_studio_received_20261017` 模拟标注包。

结论：**相对Q值得采用，而且已经实现；scope应同时保留“拒绝倾向”和“任务裁定对照的误拒／误收”，二者不能互相改名。Semi、scope和确认个人失误可以归入“标注质量与可靠性”大板块，但展示栏目不等于加权总分。** 当前无需等待v2，也不需要先建立一个通用综合分才能推进人员与组合研究。

明确采用判断：**相对Q现在可以作为人员比较和选队的主轴，原尺度Q并列解释实际成果，不双重计权；选队必须用目标建筑外的画像。已有楼外24.98%/23.69%的误差下降足以支持当前研究用途，不需要等待永久人员类型。** 它不保证每张图中高Q队伍都优胜。

## 1. 现在的scope到底算什么

存在三代相关字段，不能只看“scope”这个名字。

| 字段或页面 | 实际定义 | 可以如何解释 |
|---|---|---|
| `S_rejection` | 将回答 `in_scope` 编码为0、`oos`为1，再按图片任务与人员拟合双向固定效应；不使用gold作为响应变量 | 调整任务组成后的拒绝倾向；正值比池内人员更容易拒绝，不代表更差或更正确 |
| `S_clear_rejection` | 上述做法限制在旧快照 `scene=clear`；原代码没有再要求历史人工gold为in_scope | 旧clear子集的相对拒绝效应；不能直接称最新人工OOS对照正确率 |
| 新 `scope_evidence.csv` | 原始选项与历史任务级gold、后来hold、当前场景相容条件逐份连接 | 有裁定且语义相容的误拒／误收证据；不是全261图当前任务正确率 |
| 当前工作台“人员画像→适用性判断” | `workers__scope_worker_opportunities`，按人／条件显示提交和不同裁定覆盖 | 机会表；表中 `current_clear_compatible` 是机会次数，不是正确率或分数 |

旧S轴实现：`tools/thesis_main/analysis/worker_four_axis_update_20261015.py:90`、`:117`、`:136`。当前B8L2/D10包仍从旧包继承这两个S效应，而非根据新增70份重新拟合，见 `worker_b8l2_d10_20261017.py:285`。工作台菜单绑定见 `research/statistics/research_explorer_v1_r2_20261017/workbench.js:13`。

本轮从22个真实原始导出逐份回读3222份作答的scope选项，与接入表全部相符：3217份有选项，2627份in_scope、590份OOS，5份缺失。**590/3217只能叫回答OOS的比例；它没有人工正确性分母。** 缺失不计为正确或拒绝。

新相容条件为：历史任务gold可用、没有later hold、历史gold=in_scope、当前 `scene=clear` 且 `oos_subtype=not_oos`。接入代码已把Pro易误解的 `current_clear_in_scope_adjudicated` 改为 `historical_gold_current_clear_compatible`，另标本轮未独立裁定当前目标。实现见 `tools/thesis_main/analysis/worker_v1_pro_integration_20261017.py:53`、`:115`。

对于人员w，在已知可标且语义相容的任务上：

`误拒率 = 回答OOS次数 / 有有效二元回答的可标机会数`。

在已知不可标、且同一任务表示规则下的任务上：

`误收率 = 回答in_scope次数 / 有有效二元回答的不可标机会数`。

必须分开分母。任务池OOS比例不同会改变混合准确率；不能把二者简单合并后比较人员。门洞并非自动不可标，多空间选择并非自动scope错误，有GT也不是二元可标裁定。

本轮独立重算结果见 [scope_panel_counts.csv](scope_panel_counts.csv)：

| 面板 | 条件 | 机会 | 图／楼／人 | 错误 |
|---|---|---:|---|---:|
| 当前相容可标 | Manual | 286 | 11／7／26 | 38误拒，13.29% |
| 当前相容可标 | Semi | 78 | 3／2／26 | 10误拒，12.82% |
| 旧协议 | Manual | 727 | 28／11／26 | 129误拒 |
| 旧协议 | Semi | 468 | 18／10／26 | 49误拒 |
| 旧协议 | OOS条件 | 234 | 9／6／26 | 95误收 |
| 窄历史geometry／split-level OOS | OOS条件 | 156 | 6／5／26 | 71误收 |

26人包含历史整体排除者的行为证据，不能因此恢复主Q或投票资格。主24人当前相容Manual为32/264误拒、Semi为7/72；W030在该Manual面板9/11误拒，不代表其总体错误率为81.82%。原始gold可连接1481份，后来hold排除52份，余1429份属于历史协议诊断。

新scope楼外模型本身仍是任务调整的0/1错误效应；用“训练楼外总体错误率＋人员效应”截到[0,1]后计算Brier，不能称已经校准的风险概率。Pro已发布主24人264份/7楼的连续效应Brier下降15.79%，5/7楼改善，建筑bootstrap区间−7.49%至27.08%；本轮核对定义与发布表，未重跑其bootstrap。该证据可探索，尚不足以宣称稳定通用scope类型。

## 2. 是否过于保守：有一个可以具体补齐的scope缺口

**702份、27图、12楼已有历史in_scope gold，但当前scene为unflagged，因而没有进入364份相容面板。** 另169份当前clear记录没有匹配的历史gold。这里的未知是裁定/协议兼容性未完成，不等于这些图真的无法判断。

建议按任务级处理，而非重新审核所有作答：先复用现有用户确认的目标空间、可标性与原任务说明，建立“旧任务规则→当前允许表示/目标”的对应；对确实一致且有明确证据的任务生成独立相容回执，再扩展误拒机会。当前明确OOS图也应逐任务核对原始回答时所用规则，满足同义裁定后才进入误收分母。仅将冲突或缺证据的任务交用户补判。

不建议仅因为 `unflagged`、`current_class=简单/困难`、图已出分或存在可用GT就自动宣布in_scope；但也不建议把兼容核对缺口长期当作“资料不足所以不能做”。目前这27图是明确、有限、能复用已有核验推进的任务，逐图清单见 [scope_bridge_candidates_27.csv](scope_bridge_candidates_27.csv)。清单保留已有历史gold、来源、当前场景/表示、条件分母和待桥接状态；它没有把unflagged解释为无OOS，也没有自行改变702份资格或正确性。

## 3. 相对质量已有实现，而且有实际必要

普通Manual主Q共有1048份、24人、87个精确任务、19栋建筑；任务键为 `(image_id, condition, reference_id, reference_version)`。模型为：

`score(c,w) = task_intercept(c) + worker_effect(w) + residual(c,w)`，并约束人员效应和为0。

这不是只按简单／中等／困难减均值，也不是直接取每个人任务内残差的均值。它同时控制任务组成与比较人员组成，人员效应就是当前相对Q。原尺度均值／中位数／低尾说明实际交付质量；调整Q说明在现有共同任务连接下相对别人如何。二者回答不同问题，但来自同一几何评分，不能当两份独立证据重复加权。

实现入口：`tools/thesis_main/analysis/worker_b8l2_d10_20261017.py:91`、`:97`；目标建筑外拟合和至少6个可比任务、3栋建筑支持见 `worker_classification_progress_20261014.py:70`、`:82`；同测试任务/人员集合内居中评价见 `worker_b8l2_20261016.py:99`。

本轮未调用原拟合函数，采用任务内去截距、23维零和人员对比设计及 `numpy.linalg.lstsq` 独立求解全样本与19个留楼折：960个效应和2096个预测全部复现，最大差约1.85×10⁻¹³。每折设计秩均为23，当前24人模型可识别。来源与数值见 [CHECKS.json](CHECKS.json)、[q_effect_recheck.csv](q_effect_recheck.csv)、[q_network_recheck.csv](q_network_recheck.csv)。

| 同一主训练面板示例 | 任务／建筑 | 原均分 | 原均分名次→调整Q名次 | 相对Q |
|---|---|---:|---|---:|
| W013 | 38／11 | 61.01 | 22→17 | −3.18 |
| W031 | 58／14 | 65.27 | 13→16 | −2.49 |
| W017 | 52／14 | 67.28 | 11→12 | −0.21 |

因此不同人所标任务确实影响比较，用户提出相对质量有实质依据。完整同面板对照见 [absolute_relative_recheck.csv](absolute_relative_recheck.csv)。

本轮独立复现的建筑等权楼外相对MSE下降为B8L2 **24.98%**、D10 **23.69%**，表明相对人员信息在当前人群跨建筑时有预测价值，值得继续使用。这个百分比不是分数提高或人员能力提升。Pro同对象原均值基线为25.82%/24.41%，并未证明调整Q预测必胜原均值；保留调整Q的理由是估计问题明确、减少任务组成混淆，而不是编造预测优势。Pro原留出208份/4楼的相对Q结果属于已使用历史留出，不是新盲测；本轮未重新拟合该留出与所有基线。

当前Q仍是清洗后、普通Manual、指定参考下的人员效应；任务交互、门洞专项、任务选择与未观察失误无法由一个加性Q消除。零点二分可用于描述组合，边界人员应显示连续值与支持范围，不要求永久稳定类别。

## 4. 质量大板块应怎样组织

建议使用以下层次，直接利用已有结果，不等待统一总分：

| 栏目 | 现在可用的内容 | 不能混成什么 |
|---|---|---|
| 几何产物质量 | 原尺度B8L2/D10、低尾与离散；同任务调整Q；普通/门洞分层 | 原均分不直接当能力；绝对Q与相对Q不重复投票 |
| Semi处理表现 | 实际初始化质量、最终质量、兼容净改善；已知错误机会与结局 | 未修改不自动是失败；有改动不自动是纠错；final与gain任务内人员效应不重复加权 |
| 适用性判断 | 原始拒绝倾向、明确任务误拒/误收、裁定覆盖 | 不能把目前全量场景标签直接当原任务二元gold |
| 交付可靠性 | 具体个人失误与证据、已审核/未审核、原因未知和机会分母 | 全部清洗排除不等于个人严重失误；未审核不等于正确 |
| 效率（与质量并列） | 同口径active time及调整T | 快慢不等于认真程度；不以lead_time补active_time |

现有Semi 574份已恢复初始化。437份普通兼容、可归因净改善中B8L2平均−2.619分，409份为开发训练、28份原留出；可以现在分析“谁在怎样的初始化下改好或改坏”，无需因部分语义结局缺失把整块工作暂停。强缺陷机会156份中25份未改、131份改后缺陷是否真正消除未知；这131份应沿用未知，而已有净改善和终稿几何仍可分析。Semi专项开发楼外结果优于普通Q迁移，但28份/2楼留出方向为负，应保留场景外推限制。

85份原审核剔除里，25条具体依据、68条宽不可接受只是候选文本编码，前者包含于后者；不能称85次已确认严重个人错误，也不能将25和68相加。GT问题、图级人数不足、OOS诊断、范围解释、非独立借点和整人历史排除继续独立列因。对明确个人失误可直接保留事实证据；争议仅限对应对象，不应阻止其余证据进入展示。同一对象的scope错误、漏纠错、严重失误须去重，但去重并集没有统一机会分母，仍不是风险率。

综合指数不是原则上禁止。若后续用途明确为“在指定场景、质量要求和时间预算下选队伍”，可在目标建筑外固定规则，以真实融合质量、完整率和成本检验多维信息是否比Q/T更有用；这比现在任意给scope误拒、几何一分和一次历史剔除设交换权重更可审查。当前不应把“没有通用总分”解释为“不能推进综合人员质量研究”。

## 5. 机器证据、检查与交接

- `CHECKS.json`：本轮实际独立回读和复算检查；明确没有使用模拟数据、没有改评分/资格。
- `scope_panel_counts.csv`：面板×条件粒度；n为机会数，图/楼/人为覆盖，结果列为对应事件数；不适用结果为空。
- `scope_worker_recheck.csv`：27人逐人原始拒绝次数/有效回答数，以及Manual/Semi相容误拒次数/机会数；零机会的率为空。
- `scope_bridge_candidates_27.csv`：27图待桥接清单，覆盖702份历史in_scope、当前unflagged记录；含历史gold来源、条件分母、当前场景/表示及明确未重新裁定状态，不用于自动更改资格。
- `q_effect_recheck.csv`：全样本及19留楼折×24人×2指标，960行；独立解、发布值与差值。
- `q_network_recheck.csv`：20个拟合面板的秩、人数、任务数、行数。
- `absolute_relative_recheck.csv`：同一1048份普通Manual面板的24人原均分、中位数、样本数、相对Q与两种名次；任务截距均值=原均分−相对Q，仅为模型内分解。

公共catalog、地图、统一入口由统筹接入。本包是研究审查支撑，非新方法合同或新数据release。未做新全景逐张人工审阅、未重新裁定OOS、未重跑Pro全部训练/bootstrap、未自动发布或提交推送。下一步优先任务语义桥接和将当前多维证据接到工作台，不新增大批人工审核。
