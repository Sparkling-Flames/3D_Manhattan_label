|分类|B8L2人数|D10人数|
|---|---:|---:|
|Q较高／较低|10／14|12／12|
|较高且较快|3|5|
|较高且较慢|6|6|
|较低且较快|7|5|
|较低且较慢|5|5|
|Q×T无法分类，全27人分母|6|6|

6人包括普通Q人员中3名T支持不足者，以及W019、W026历史整人排除和W022缺普通训练支持者；后3人没有恢复资格。Q正负依相对池内零点，T负为快、正为慢；没有在Q组内重新按中位数平分。零效应、无训练、不可识别或少于6个可比任务／3建筑均单列。

- [逐人完整画像](person_profiles.csv)及[分组人数与任务覆盖](group_coverage.csv)：同时保留效应、支持数、缺失原因、成员ID；各组图片/建筑有交集，不能相加。
- [原尺度Q统计](absolute_Q_training_profiles.csv)：每人每折的均值、中位数、10%分位数、标准差、最小值及图/建筑数。不同人的任务池不同，原均分不直接等于能力排名。
- [楼外画像](fold_person_profiles.csv)与[训练范围](fold_training_ranges.json)：每张目标图只使用目标建筑外的Q/T信息；原留出在训练源中仍排除。对既有折直接复用，对缺少的目标建筑用同一旧拟合器及原支持门补折，未修改模型或阈值。
- [跨建筑稳定性](cross_building_stability.csv)：两评分各有6名人员的Q符号会随留出建筑变化，T有1名，Q×T有5名；没有支持者分别为3、6、6人。折有重叠，不是独立重复实验。另保留既有50次互斥建筑两半的[Q符号覆盖](disjoint_half_stability.csv)，不可把未能比较的两半算稳定。

Q×T是效率构成候选，不要求四格提高单人质量预测。分类用于比较同图同人数的成本、分歧与过程；不存在某组必须获胜的验收条件。

两种Q视角确实提供不同信息：以当前24人B8L2描述为例，W013原均分61.01，原均分序位22，而调整任务后的相对效应序位17；W031对应序位从13到16。这是同一批分数经过任务调整后的排序差别，不是两次独立测量，更不能据此认定人的内在能力发生变化。

## 2. 给融合线程的实际名单

入口为[TEAM_REQUESTS.json](TEAM_REQUESTS.json)，schema为`worker_v1_team_requests_20261017_v1`。它包含173个合格非OOS Manual图片池：156个普通池和17个门洞池；门洞能否计分继续由参考与几何资格决定。每池至少3名有效独立人员。完整261个Manual来源池的[请求资格表](source_pool_request_status.csv)保留其余69个人数不足、12个OOS诊断池、7个既有图片/池暂停，不删掉分母。

每图有15条顺序：3条固定种子的随机排列，加上B8L2和D10各自的Q高优先、Q低优先及四种Q×T组优先。组内及其它人员顺序使用同一预定随机排列，未按目标图成绩挑人。没有该焦点组时仍保留路径，但`policy_has_focus_support=false`，不能称为实际组别对照。

- `teams`：14845个去重后的真实成员集合；包含W与object_id、目标图/建筑、声明评价参考、成员绑定参考、人数、实际时间已知和与缺失人数，以及可复用缓存位置。
- `paths`：2595条实际完整人员排列，`prefix_request_ids[k-1]`就是第k人的真实子集。所有k=1…N节点都声明，k=1/2不影响来源图片至少3人的准入要求。
- `matched_random_prefix_request_ids`：同图、同来源池、同人数的第一条随机对照；另外两条随机排列供有限敏感性比较。不能把2595条路径或14845个重叠集合当独立图样本。
- 每条策略写明选择用的指标版本、目标楼外折、焦点组可用人数、训练范围键。分组名单及支持量在`fold_person_profiles.csv`按`fold=building_id + metric + worker_id`连接。缺Q或T的人保留为未知并随机排到焦点组之后。
- `source_time_known_sum`与`target_time_known_sum`仅为相应成员**已知部分**的实测和；配合`*_missing_n`使用。只要缺失人数大于0，就不能把这个和称为完整成本；来源时间不冒充目标空间专属时间。时间是结果描述字段，没有参与目标图选人。

楼外名单下，两指标均有172/173池同时出现Q高低；四种Q×T都出现的池，B8L2为83/173、D10为93/173。其余池可研究部分组别，不能伪造全四格比较。所有排列的全员集合相同，确定性融合的全员终点应相同；途中成员集合不同可能产生不同过程。

## 3. Semi：修改、纠错与历史净改善

[Semi逐份证据](semi_evidence.csv)覆盖全部574份，而非只取定向审核样本。实际初始化来自既有import/runtime匹配证据，所有当前对象以稳定object_id连接。不能把confirmed_nontrap理解为正确初始化。

288个错误机会沿既有确认trap及实际初始化匹配的历史定义，保留初始参考依据与暂停字段；本轮没有按当前新目标重新认证初始化错误。它们是可追溯的历史纠错机会证据，不自动成为当前主质量评分资格。

|证据层|分子／分母|可作的解释|
|---|---|---|
|定向“未改动”线索|105条，其中104 Semi、1非Semi|定向审查覆盖，非总体随机抽样|
|坐标确实未改|100/105条线索；36 trap、31 nontrap、33未知来源|仅说明坐标保留；后两类没有初始化正确性确认|
|核实实际使用的错误初始化|288/574份Semi|确认trap且实际初始化预览/导入匹配；不是所有574都有已知错误机会|
|错误初始化原样保留|36/288个已知错误机会|可以确认该错误初始化未被修改|
|改动后仍未改对|3/288个已知错误机会|人工有明确文字，坐标也确实变化|
|上述机会的纠错结果未知|249/288|没有把改动或净增分当作纠错成功|
|明确修复成功标签|0条已确认|表示缺少逐项成功裁决，不能解释为成功率0%|

4条“未改”线索实际有坐标改动，其中3条有上述未改对评论，另1条评论“好像没有改动”与坐标核查矛盾，纠错结果保留未知。证据决定及引用见[EVIDENCE_DECISIONS.json](EVIDENCE_DECISIONS.json)，逐份原审核历史保持，不以评论出现字段数重复计事件。

历史OSPA30净改善540/574份有值：254正、150负、136为零；按trap状态分为264 confirmed_trap、72 confirmed_nontrap、204 unknown。它是既有初始/最终几何及旧参考下的损失改善，保留初值、终值和修改距离；不是B8L2/D10净改善，也不能把正值命名“修复成功”。其余34份缺值保留。本包首交时B8L2/D10实际初始化重评分尚未做，旧空列保持历史身份；现已在上方接续包采用Pro的574份初始化及437份普通兼容净改善。不能把最终分减历史OSPA30或把Manual不适用记0。

## 4. 个人错误剔除及其它限制

全库存85份`excluded_by_review`、133份`historical_not_accepted`均保留在[排除证据表](exclusion_evidence.csv)。本轮从已有最终invalid及明确个人错误评论中保守识别10份可归因错误剔除，逐条列出引用；它是**已知下限**，没有把剩余75份invalid归为正确，也没有仅靠“奇怪”“不知道标什么”等模糊评论认定具体严重错误。

133份历史未接受中113份属于W019/W026整人历史排除，余20份归因仍未知；整人排除不等于113次逐条确认错误。GT/参考限制、OOS、人数不足、非独立来源与暂停等在逐记录字段及互斥primary_reason中另外保留，不能统称人员失误。12条历史来源重复版本单列在[重复版本来源](duplicate_source_versions.json)，不增加3222份规范提交分母。

[27人证据汇总](person_evidence_summary.csv)同时提供：已知错误数/全部规范提交数、已知错误数/本规则可判断机会数、审核覆盖、归因未知和未明确判断数量。本规则可判断机会共1009：10条明确个人错误剔除及999条逐份审查后usable/保留范围变化的记录；后者只表示该次审查未裁为严重失误，不证明所有局部正确。另2213份尚不满足这一明确判断规则，不能当正确。审核总体1540/3222，异常优先被审核，任一子集比例都不直接外推总体风险。

同条件/场景的机会和未知另见[分层证据表](person_evidence_by_condition_scene.csv)。本轮没有建立统一严重度量表或做完整盲审，10条不是正式完整的“严重错误率”。Semi未纠错与个人错误剔除以同一object_id保留交集，本次所确认两类交集为0；没有生成相加扣分，也不由此断言一般不存在重叠。
